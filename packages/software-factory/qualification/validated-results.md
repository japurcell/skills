# Validated result evidence qualification

The agent runner now saves a filtered, bounded `{ "kind": "result", "payload": ... }` envelope in an attempt-owned `validated-result` capture after the authoritative adapter decoder and caller payload validator accept it. The raw `resultCaptureId` remains the adapter's original output stream. Successful settlement atomically verifies that the new capture is complete, belongs to the exact attempt and invocation, and uses the approved channel, then records its ID in `attempt.agent.validatedResultCaptureId`. The successful `AgentResult` and learning extraction report expose the same new ID. Sessions retain their raw references.

The store rejects successful settlement of a newly recorded agent attempt without the validated ID, and rejects incomplete, foreign, wrong-channel, failed, and nonstarted links. An identical terminal retry is idempotent; a different ID cannot replace the committed link, and an omitted ID on retry leaves the committed link intact. Older attempts without the field remain unknown. The normalized capture is limited to 1 MiB before recording and checked again after filtering, since redaction can expand text. Capture or link failures cannot produce successful settlement.

Public tests use the fake adapter through real `invoke` calls and a disposable repository. Ordinary JSON and JSONL output both produce a filtered normalized payload and preserve the distinct raw capture. The complete-capture event precedes the settled event. Invalid payloads, questions, process failures, denials, oversized normalized payloads (including expansion after filtering), and injected capture/link failures produce no validated link. Direct store tests check ownership, channel, completeness, terminal retry behavior, and prelaunch metadata forgery.

The focused store test was observed red before implementation: the prelaunch-forgery test reported “Missing expected rejection.” Later missing-reference and filtered-expansion assertions also failed before their guards were added. After implementation, `node --test test/validated-results.test.mjs` passed seven cases. `npm run typecheck`, `npm run build`, `npm run test:store` (31), `npm run test:adapters` (108, including fake, Codex, and Copilot), and `npm run test:learning -- --operation extract` (13) passed. These runs used pinned Node 24.22.1 in the private worktree. The parent owns the combined integration gate.

This task does not evaluate learning proposals or adopt changes. The downstream evaluator must bounded-read the complete capture, verify the attempt link, compare its normalized payload with the extraction report, and treat missing, pruned, oversized, or mismatched evidence as inconclusive.
