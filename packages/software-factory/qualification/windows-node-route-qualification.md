# Representative pinned Node Windows spawn route experiment

The separate `windows-factory-node-route.yml` job runs twelve cases, comprising seven original cases and five separately labeled root-launch differential cases, on a disposable `windows-2025` runner. It has a narrow push trigger on `codex/research-agentic-workflow-prototypes` for its workflow and qualification dependencies, plus manual dispatch after the workflow is registered. It follows the [pinned Node launch audit](../../../docs/software-factory/research/windows-node-launch-equivalence-2026-10-22.md) and reuses the exact Node 24.22.1 bootstrap and pinned official Git 2.54.0 and TypeScript 7.0.2 archive preparation. It does not change the original Windows startup matrix or product runtime.

The actual pinned `node.exe` calls `child_process.spawn()` directly. Two diagnostic baseline cases use `detached:false`, `windowsHide:false`, `shell:false`, and `stdio:['ignore','pipe','pipe']`: exact Git `rev-parse --show-toplevel` and a fresh successful `tsc.exe -p` emission. Five candidate cases use `detached:true`, `windowsHide:true`, `shell:false`, and the same stdio tuple: the same Git and separate fresh TypeScript outputs, intended nested `cmd.exe`, and the reviewed native fixture's deadline and output controls. Each spec fixes absolute executable, argv, cwd, and a private environment. The fixture is compiled by the existing qualification build script and its source and executable hashes are recorded.

The existing `DEBUG_PROCESS` tracer launches pinned Node as its root with `CREATE_NO_WINDOW`, inherited file handles for stdout/stderr, `NUL` stdin, private environment, and the case directory as cwd. It verifies each CREATE PID and image independently through Windows process handles and retains CREATE, EXIT, DLL, and completion records in each case's `debug.tsv`. The protocol matches Node's reported direct child PID to one independently verified helper CREATE. Candidate helper cases permit the Node root and that direct helper only. The positive control additionally requires the intended nested `cmd.exe` CREATE. Every observed process must exit, both Node-managed pipes must close, and the outer debug loop must finish without a stop or error. Module paths must resolve inside Windows or the pinned package roots, with helper package bytes checked against the archive manifest and the expected Git DLLs observed. The runner independently extracts `node.exe` bytes from the already SHA256-pinned official zip using the platform `tar`, compares the archive member's digest and size with the on-disk executable before any trace, and rechecks the executable digest before each case. The report retains both sides of that comparison, package closure, tracer source hashes, exact outer launch conditions, bounded child output, and raw trace paths.

Run `39845102351` failed six original cases; baseline TypeScript completed diagnostically, while its strict no-extra check still failed. The retained `baseline-git/node-result.json` records direct exit and child close at code 0, exact 65-byte stdout, `stdoutClosed:true`, and `stderrClosed:false`; the launcher saved the result from the child close callback before the stderr pipe close callback. The launcher now saves a successful lifecycle result only after the child close and **both** pipe close callbacks. The original 45-second guard also applies to that combined closure; expiry records a failing result, with no assumed pipe closure. The same run observed an extra `conhost.exe` CREATE in every candidate under the outer `DEBUG_PROCESS | CREATE_NO_WINDOW` launch, and two in the nested command case. These remain strict failures, without attributing which process caused either console host. Failed run log: `/tmp/factory-native-39845102351-failed.log`; raw artifact: `/tmp/factory-windows-node-route-39845102351/factory-windows-node-route-39845102351-1/`.

The driver also runs a separately labeled five-case `DEBUG_PROCESS | DETACHED_PROCESS` root-launch differential using the tracer's existing closed launch mode. It keeps the same pinned Node spawn tuple, exact Git and fresh TypeScript inputs, nested command positive control, native deadline/output controls, private environment, 60-second outer guard, 45-second Node guard, capture limit, independent CREATE/EXIT/image/DLL checks, output checks, and child/pipe closure checks. Its cases live in `rootLaunchDifferential.cases` in `qualification.json`; the original seven remain in `cases`. Any failed differential assertion fails the experiment. A difference between debug-root modes is diagnostic only and requires an independent non-debug OS process-start trace before a production equivalence claim.

Native run `39847861421` at `70719945` completes all twelve cases in the original step bound. Both baseline lifecycles now complete diagnostically with both pipes closed, proving the persistence-order repair on pinned Windows Node. All five original candidate cases still fail strict extra-process checks. Detached-root Git, TypeScript, deadline and output cases pass; detached-root nested cmd still records an additional `conhost.exe` and fails. The intended nested cmd is present, but the additional console host prevents strict acceptance. This mode-dependent result requires the independent non-debug observer gate; no product helper is admitted. That run also exposes an attribution error in the baseline diagnostic summary: dropping the first child array entry incorrectly labels the direct helper as extra when a console host appears first. The protocol now reports additional processes by excluding the independently matched Node-reported direct PID. Public red/green checks and replay of both retained native traces identify only the actual console host. The original artifact remains unchanged; this correction changes reporting, without relaxing process acceptance or asserting a new native run.

Normal Git cases require complete captured stdout bytes equal to the known repository path rendered with forward slashes and one LF byte, with empty stderr. The capture byte count must equal the reported total, so truncation and extra lines fail. The separate fresh TypeScript cases require empty stdout and stderr, exactly one emitted `input.js`, and the independently stated UTF-8 bytes `const result = 42;\nexport { result };\n`; the report records expected and actual digests and sizes.

The deadline fixture must emit its 15-byte `deadline-ready` marker before Node's 500 ms `SIGTERM` request. The output fixture must exceed 256 KiB before Node's output-limit request within 10 seconds; Node retains at most 256 KiB per stream. Both require Node's direct kill return value, direct exit and close events, pipe closure, and an independent debug EXIT. The outer tracer has a 60 second guard and should never request a stop during a valid case. Its own termination code 124 is not used as evidence of Node's kill outcome. The prior direct C# fixture run remains separate evidence, including its 4 MiB output and code 124.

Baseline cases are diagnostic. Their extra process observations and strict no-extra result remain explicit in `qualification.json`; an expected `conhost.exe` does not become a candidate pass. A candidate disagreement under `DEBUG_PROCESS` requires an independent non-debug OS process-start trace before equivalence can be claimed. A representative pass is only a gate to the still-required full alternate exact Git and TypeScript matrix, with all original hostile inputs and controls. It does not authorize product admission, a Job subsystem, a public `noChildren` switch, broader runtime changes, or release.
