# T13a ended-source extraction qualification

Status: bounded local extraction implemented and tested on 2026-10-22. This is T13a only. Comparative evaluation, adoption/revert, UI composition, live provider qualification, and test-group registration remain separate owner tasks. No real prompt, skill, profile, or installed runtime was changed.

## Public workflow and saved record

Copy `templates/workflows/learn.ts` and its `./change.js` dependency (`templates/workflows/change.ts`) to authored `.factory/workflows/learn.ts` and `.factory/workflows/change.ts` in a repository with the pinned factory toolchain and an explicitly configured agent. The dependency supplies the canonical bounded candidate fingerprint; ordinary TypeScript workflow compilation resolves the `.js` import to the copied `.ts` source. Invoke learning through the existing foreground `invoke` path with a new isolated worktree and versioned JSON input. For example:

```json
{"version":1,"focus":"Test discovery","sources":[{"invocationId":"EXACT_ENDED_ID","attemptIds":["EXACT_ATTEMPT_ID"],"eventCursors":["EXACT_DECIMAL_CURSOR"]}]}
```

`focus` and `agentProfile` are optional. An omitted `attemptIds` list selects the available bounded attempt pages of that invocation; an omitted `eventCursors` list selects no events. Input accepts 1-6 unique exact invocation IDs, at most 12 explicit attempt IDs and 12 event cursors per source, a 4 KiB focus and an 80-byte profile name. Only finalized `succeeded`, `failed`, `interrupted`, and `needs_input` sources are eligible. Unknown, active, and wrong-invocation references fail or retain an explicit uncertainty when the relevant page was not reached.

The report capture contains `version`, actual `suppliedSources`, actual `examinedSources` with outcome and exact attempt/event/capture IDs, `captureLimitations`, and `proposals`. Empty proposals require `noProposalReason`. The agent result capture ID is also saved. A proposal has a result-local `key`, summary, `{scope,path}` target, a bounded unified diff or exact complete candidate capture reference, supporting and contrary evidence references, and suggested cases. The workflow constructs examined references and limitations from stored pages. Agent output cannot supply or replace those facts, and cited evidence must match a reference actually examined. A candidate capture reference requires complete captured content; partial content remains citable only with its visible limitation.

The `WorkflowContext.sourceHistory` port returns bounded read-only history, invocation-owned capture, and exact event-cursor pages. It exposes no store, database, write method, or all-history search. Each source reads at most three 20-row history pages, at most 40 selected captures, and at most two 20-chunk capture pages with a 32 KiB page budget. All supplied capture text shares a 48 KiB budget; the final agent context is capped at 128 KiB. Additional pages, partial/pruned/unknown capture states, text that cannot fit a first page, and budget exhaustion appear in `captureLimitations`. A page prefix is never reported as a complete source. If an attempt is beyond the bounded pages, it is marked unexamined instead of being called missing. The underlying store cannot distinguish an arbitrary absent attempt ID from one belonging to another invocation through this bounded port, so that diagnostic states `missing or foreign`.

Source text is untrusted evidence inside the analysis context. The ordinary agent call requests read-only report permissions and validates its versioned result. Explicit invocation overrides retain their existing higher precedence, including a supported `agentOverrides['learn/extract']` workspace-write setting. The workflow fingerprints the whole isolated worktree before and after agent analysis using the canonical bounded helper; a changed candidate fails extraction with a saved diagnostic, preserving the modified worktree and source evidence for inspection. It does not undo edits or promote a proposal. Patch proposals are validated as one bounded unified text-file diff whose old/new paths match the declared target path, with `/dev/null` allowed for creation or deletion. Multiple files, renamed paths, mismatched paths, and traversal paths are rejected. The patch remains data and is never applied by extraction. Existing runner admission, accounting, native stop, capture, report persistence, and needs-input or infrastructure outcomes apply unchanged. A captured candidate reference identifies retained bytes by invocation and capture ID; evaluation must still check availability and exact baseline/candidate inputs later.
