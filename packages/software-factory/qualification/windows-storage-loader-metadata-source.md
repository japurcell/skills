## Fixed controller context and bounds

The only controller CLI is `NODE qualification/windows-storage-loader-metadata.mjs --metadata-only`. No discovered tool or arbitrary executable/path/mode field is accepted.

The selected System32 Windows PowerShell5.1 runs with NoProfile/NonInteractive, a minimal declared environment, and only the selected inbox module profile. The collector's sole fixed internal mode is `-Mode metadata-only`. No discovered program executes. Discovery caps 16 installations, 8 toolset entries per installation, 8 SDK versions, 64 companion DLLs per host/target directory, 256 total file facts, 128MiB per non-metadata file, 64KiB installation metadata, and 512MiB total distinct observed file bytes. Repeated observations must match. More than one installation/toolset/SDK tuple blocks rather than selecting newest.

The controller captures at most 1MiB stdout and 8192 stderr bytes. Output byte counters saturate, and candidate output is suppressed on process failure. Its deadline is294s plus at most1s observation teardown. Default process capture accepts only exit0; only the fixed collector call explicitly accepts `[0,1]`, then requires exit0/observed or exit1/blocked after strict wire validation and controller-source postflight. Any blocked result remains exit1 with selection/build/native authority false. SDK rows are three fixed header and four architecture-specific library prerequisite samples, not the consumed include/library closure. Later build-only authorization and complete consumed provenance remain separate root gates.
