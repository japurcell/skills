# T15b first-install publication qualification

The explicit `install.py install` route authenticates the complete selected release and pinned Node archive in Python before selected JavaScript runs. The preparer creates and binds an incomplete candidate, issues one private ticket, and exits with its owned process groups closed. Python writes the exact post-exit receipt, then invokes the staged Node/controller in the foreground. The staged controller uses the sole SQLite maintenance claim as its mutation gate.

Publication writes an operation-bound intent before either rename. Both candidate subtrees retain their recorded directory identities and full receipt inventory whether still under the candidate or moved to `factory/install` and `factory/toolchain`; a foreign target with matching bytes cannot be adopted. An authoring plan records the original compatible files and directories before publication. Each newly created directory and file gets its own private identity sidecar. A file created without its sidecar after an interruption is ambiguous and refuses automatic adoption. Existing compatible customized authoring files are preserved byte-for-byte.

The installed receipt records release, schema 7, exact operation/repository/claim, selection and manifest hashes, candidate binding, both moved subtree identities, stage digest, publication-intent digest, and only authoring files actually created. The controller validates the actual published release, complete Node/toolchain inventories, selected external provider sources, direct installed Node/npm/TypeScript commands, authoring ownership, marker and sole live claim. The store transaction then records the receipt hash, marks ready and releases exactly that claim. The marker is unlinked only inside `recoverCompletedFirstInstall` after revalidating committed evidence and installed bytes. Python removes only a fully inventoried, unchanged operation stage after the staged process and its groups exit; failure preserves evidence.

Native Darwin arm64 qualification uses the exact `/private/tmp/factory-node-v24.22.1-darwin-arm64-selection.tar.xz`, Python 3.13.14 and a copied read-only offline cache. It hard-fails if prerequisites are missing. It proves public foreground ready, direct installed Node 24.22.1, npm 11.19.1 and TypeScript 7.0.2, complete stage cleanup, unchanged dirty tracked source/index and shared cache, preserved customized authoring files, newly created templates, and second-installer refusal. Run directly with:

```sh
FACTORY_TEST_PYTHON=/Users/adam/.pyenv/versions/3.13.14/bin/python3.13 node --test qualification/install-publication-native.qualification.mjs
```

The archive-free `test/install-publication.test.mjs` covers the operation intent before and after each rename, foreign same-byte and linked targets, published-byte tampering, known-live reclaim refusal, stale ticket token, stage/candidate tampering, provider descriptor rejection, and a ready row that cannot unlink the marker without actual installed validation. Controller, candidate, bootstrap, release and binding regressions remain separate. This node does not qualify Windows ACL/process lifetime, native Linux archive execution, provider runtime calls, installed provider CLI binding, upgrades, uninstall or cleanup. It does not authorize registering the broader unfinished maintenance operations as passing.
