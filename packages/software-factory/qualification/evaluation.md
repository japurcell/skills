# T13b comparative learning evaluation qualification

Status: bounded local evaluation implemented and exercised on 2026-10-22. This source is an ordinary explicit workflow template. Test-group registration, integration with T14 adoption, live provider quality, and release acceptance belong to later owner work. No real prompt, skill, profile, or installation was adopted or edited.

## Public contract

Copy `templates/workflows/evaluate.ts` and its `./change.js` dependency (`templates/workflows/change.ts`) into authored `.factory/workflows/`. Invoke `evaluate.ts` through the existing foreground `invoke` path with a new isolated worktree and a versioned input. A captured-text example is:

```json
{
  "version": 1,
  "extraction": { "invocationId": "ENDED_EXTRACTION_ID", "proposalKey": "RESULT_LOCAL_KEY" },
  "baseline": { "invocationId": "ENDED_SOURCE_ID", "captureId": "BASELINE_CAPTURE_ID", "sha256": "64_LOWERCASE_HEX_DIGITS" },
  "candidate": { "invocationId": "ENDED_CANDIDATE_ID", "captureId": "CANDIDATE_CAPTURE_ID", "sha256": "64_LOWERCASE_HEX_DIGITS" },
  "cases": [{ "key": "selected-check", "criteria": "candidate must pass the check", "sourceSuggestion": "EXACT_PROPOSAL_SUGGESTION", "argv": ["/absolute/executable", "argument"], "timeoutMs": 5000 }]
}
```

An optional `reviewProfile` selects a configured profile. Each case may name an exact `sourceSuggestion` from the proposal's saved `suggestedCases`. Unexamined suggestions remain named limitations and prevent a supported assessment; a foreign suggestion fails even when another reference is pruned or the target is unsupported. The extraction reference must identify one proposal key in a complete successful version-1 extraction report from `.factory/workflows/learn.ts`. Its saved source list, examined source references, and selected candidate/evidence references must be complete. The report's `proposalResultCaptureId` must belong to the successful `learn/extract` agent attempt that used the extraction validator. Its separate `proposalValidatedResultCaptureId` must identify that same attempt's immutable, complete `validated-result` capture. Evaluation bounded-reads the normalized `{ "kind": "result", "payload": ... }` envelope and compares the entire validated proposals array with the workflow report. It also bounded-reads the same successful attempt's `inputsCaptureId`, verifies its `context` channel and attempt ownership, parses the saved extractor context, and compares every reported supplied source ID, examined outcome and selected attempt, event and capture reference with `context.evidence`, and compares the reported limitations with `context.captureLimitations`. A supplied source's optional attempt and event selectors, when present, must equal the actual selected references. Any authentic capture limitations keep the comparison inconclusive. Raw provider output may be JSONL and is never re-decoded through mutable adapter settings. A merely successful invocation with a forged or altered report cannot certify improvement. Missing, pruned, partial, oversized, unreadable, invalid, foreign, or mismatched normalized or input evidence yields an inconclusive report before assessment. The candidate capture reference must equal that proposal's `candidateCapture` invocation and capture IDs. The baseline and candidate must each resolve to a complete retained capture whose entire text hashes to the supplied SHA-256. A mutable path cannot stand in for either variant. Unknown source invocations and foreign proposal keys fail the ordinary invocation with a saved diagnostic; a missing capture within an existing source, partial/pruned capture, or digest mismatch produces an inconclusive report with a named limitation and no evaluation attempts. An unsupported shared target or diff-only proposal likewise produces an inconclusive report. Diff-only proposals need a later exact materialization and binding design; their candidate bytes are not inferred from patch text.

This first comparison supports one repository-scoped text file per captured proposal. For each case, it stages one exact text at a time under the same temporary cwd in the invocation's isolated worktree, at the declared relative target path. It removes and recreates the entire temporary root after every objective repetition and review, including cwd-relative sibling files, before staging the next trial. Each case uses identical argv, cwd, criterion and timeout for both texts. The command runs twice per side through `WorkflowContext.command` with `required: false`, so a stable nonzero exit is a genuine objective result rather than a terminal infrastructure failure. The command must be explicitly supplied with an absolute executable path, at most 16 arguments, and a 100-30,000 ms timeout. Evaluation allows 1-3 unique cases. It then asks a fresh `WorkflowContext.agent` review session for each side and case, with the exact text, declared criterion and recorded objective results. The workflow requests read-only permissions and no reuse, then reads the retained effective input capture for each successful review. A writable override makes the assessment inconclusive even if no bytes changed. Existing runner admission, capture, timeout, native stop, cleanup and accounting remain authoritative; it creates no scheduler, registry, replay service or global trial counter.

The saved report includes actual supplied references, the examined extraction report capture ID and SHA-256, the raw and validated result capture IDs plus extract attempt ID when resolved, resolved text hashes, target, proposal suggestions, case criteria/settings, each objective attempt ID and exit code, separate review attempt IDs/result capture IDs/judgments, effective permissions/profile and input capture IDs, contrary case keys, limitations, and `supported`, `unsupported`, or `inconclusive`. It records requested review permissions and profile separately from effective settings. A supported assessment requires a stable passing candidate in every supplied case, at least one stable failing baseline case, and review judgments agreeing with objective exits. A stable candidate failure is unsupported if review agrees. Nondeterministic exits, uncertain or disagreeing review, identical variants, an unexamined suggested case, a writable or unreadable review input, and no observed improvement are inconclusive. A model judgment never replaces an actual command result. These assessments describe only the supplied bounded cases and criteria, not universal quality.

The workflow checks the staging directory identity before recursive cleanup, removes only its own temporary root, and fingerprints the isolated worktree before staging, after each reset, and after final cleanup. A changed isolated source prevents a successful report. Original source history and active repository configuration are left intact by the workflow. Explicit user-supplied command argv is ordinary workflow code with the existing runner's permissions; the factory does not sandbox arbitrary commands from reaching external paths. Choose trusted bounded checks whose cwd-relative inputs are the staged text. The staged variant contains only the declared target file; cases needing broader dependencies or multiple files require a later evaluation design and must not be treated as supported by this text-only path.

## Deterministic evidence and limits

The public lifecycle fixture copies authored templates into disposable Git repositories, creates retained source captures, runs the real T13a `learn.ts` extraction for valid proposals, then runs the real builder, store, isolated-worktree runner and fake native adapter for evaluation. Same-path authored learn workflows that change the candidate capture or add a fabricated supplied and examined source after a genuine extractor result reproduced false `supported` assessments before their respective repairs; both now yield `inconclusive` with no evaluation attempts. Changed source outcomes, selected attempt/event/capture references, supplied selectors and limitations are separate negative fixtures, as are missing/pruned/partial/oversized/unreadable/invalid/foreign or mismatched extractor input captures and normalized captures. An authentic extraction with a partial source capture retains its limitation and remains inconclusive. The other cases exercise supported improvement, stable contrary regression, diff-only/shared inconclusive, missing/partial/pruned/changed variant captures, foreign candidate/proposal/suggestion, unexamined suggested cases, identical/no-improvement variants, nondeterminism, uncertain review, malformed bounds, needs-input, infrastructure failure, command timeout, reviewer mutation, writable reviewer override, a command that changes staged target bytes, and cwd-relative sibling residue. The fixture uses no paid or live provider. The affected command is `rtk proxy env PATH=<pinned-node-path> node --test test/learning-evaluation.test.mjs test/learning.test.mjs test/workflows.test.mjs` from `packages/software-factory`. Package typecheck and build use the same pinned Node v24.22.1 toolchain. On pinned Node v24.22.1 and macOS arm64, all 63 evaluation/extraction/workflow cases and 142 affected store/capture/adapter/validated-result cases passed after the final correction. Package typecheck and build exited 0. The repaired template is exercised through the public lifecycle builder.

The existing `SourceHistoryGateway` exposes at most 20 capture headers per page and 32 KiB of capture text per read. Its narrow read-only attempt view exposes the saved invocation, operation key, outcome and agent capture IDs, including the immutable validated-result link, without database/write access. Evaluation reads at most four header pages and eight text pages per selected variant capture or normalized result capture, with a 128 KiB text limit; unreadable first chunks or additional pages are inconclusive. It reads at most four header pages and eight text pages for the extraction report, sixteen 32 KiB pages and at most 384 KiB for the same-attempt extraction input capture, plus eight bounded pages for each review input capture. A history read for an unknown invocation is terminal in the existing runner; its saved diagnostic is the negative evidence rather than an inconclusive report. A timeout or failing review can also be terminal under the common runner, preserving actual attempts and cleanup rather than fabricating an evaluation result. The fake fixture establishes the workflow contract and truthful provenance, not the quality of an actual model's judgment. A later integrated test group and provider qualification must be recorded separately.
