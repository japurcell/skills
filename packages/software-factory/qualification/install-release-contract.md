# T15b release contract prerequisite

Schema 2 adds three exact release files: `templates/package.json`, `toolchain/package.json`, and `toolchain/package-lock.json`. Schema 1 remains its original exact inventory and is not silently widened. This contract supplies installation inputs; it does not install the factory, create a repository store, bind a provider, register a desktop notification helper, or publish a release.

The authoring template is an absent-only `.factory/package.json` candidate. It declares a private ESM package with no application dependencies. A later installer must preserve an existing regular customized authoring declaration byte for byte and diagnose incompatible dependencies or foreign path collisions. The separate private toolchain package pins `typescript` 7.0.2 and `@types/node` 24.19.2 as exact direct dependencies. Its npm lockfile v3 contains the full integrity-bound closure, including `undici-types` 7.24.6 and TypeScript's optional platform packages. It contains no Playwright or development package dependency. A later installer must run the verified Node's npm against only this lock in its owned staging toolchain with `npm ci --ignore-scripts`; it must not copy development `node_modules` or alter an application's lock.

The release command requires an explicit platform, semantic version, exact pinned Node v24.22.1 archive URL and SHA256, and an absolute new destination. Windows additionally requires the qualified helper selection. The command verifies the build receipt against source, templates, toolchain declarations, development lock and installed compiler inputs, then emits a complete sorted manifest. The consumer requires an externally selected SHA256 of `release-manifest.json`; it does not trust a digest read from the bundle. It checks every file's length and SHA256, exact compiled runtime and template inventory, the new declaration and lock closure, portable names, case-insensitive collisions, symlinks, unexpected files and directories, and the existing pinned Node/helper facts. Schema 2 also pins SHA256 `bea7cfb5a835aba203893966dde3e964418b12c69f8680e53a65b3603b9467d6` for the complete approved toolchain lock bytes. This binds npm's platform, CPU, executable, engine and archive integrity metadata independently of a newly selected manifest digest. An intentional lock change requires a new release schema. A missing or altered declaration, lock or runtime file fails even when the manifest itself is rewritten with a matching new digest.

The toolchain lock was generated with the pinned Node v24.22.1 npm 11.19.1 in the dedicated `toolchain/` directory using `npm install --package-lock-only --ignore-scripts --offline --cache /tmp/software-factory-npm-cache --audit=false --fund=false`. npm documents that `npm ci` requires an up-to-date lock, leaves the package and lock unchanged, and can suppress lifecycle scripts with `ignore-scripts`: [npm ci](https://docs.npmjs.com/cli/v11/commands/npm-ci/). npm documents the lockfile v3 format: [package-lock.json](https://docs.npmjs.com/cli/v11/configuring-npm/package-lock-json/). The exact Node archive SHA256 facts remain sourced from the [Node v24.22.1 checksums](https://nodejs.org/download/release/v24.22.1/SHASUMS256.txt).

On macOS arm64 with the qualified Node v24.22.1, `npm run typecheck`, `npm run build`, and `npm run test:release` passed on 2026-10-22. The public release selector ran 18 cases: the original fourteen plus complete authoring/toolchain manifest binding, semantic refusal of self-consistent but incompatible declarations or lock closure, refusal of reselected manifests after platform or integrity changes, and an offline disposable `npm ci --ignore-scripts` from the packaged lock. The disposable installation reported TypeScript 7.0.2, `@types/node` 24.19.2, `undici-types` 7.24.6, and absent Playwright. The suite also checks stale build receipt refusal after a toolchain lock change. No native Windows install, production repository install, provider call, auth change or visible desktop delivery is claimed here.
