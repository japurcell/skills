## Artifact and trust boundary

`createCopilotAdapter({packageRoot, manifestFile, manifestSha256, environment})` requires absolute, explicit paths, a 64-digit digest and the native environment. The manifest is a canonical JSON array of every package regular file, with relative path, mode, size and SHA256. Validation checks the manifest digest, path shape, duplicate and traversal rejection, recursive package contents, symlinks and special files, each file's mode/size/content digest, the `index.js` and `package.json` presence, and package name/version. It bounds metadata to 1 MiB, package entries to 262, total listed bytes to 198117357 and hashes package files in fixed 64 KiB chunks. The adapter requires Node 24.22.1 and uses the factory process's `process.execPath`. Trusted artifact validation is separate from native platform qualification, matching the common Codex adapter contract. Fake-process protocol conformance can run on other hosts; only the exact macOS arm64 artifact and native mode have live qualification evidence. T15 release binding must supply only the separately qualified platform artifact; a caller-supplied digest alone does not establish a new native support claim. It does not run a downloader, update step, global installer or ambient `node` from PATH.

## Exact launch and result contract

The launch argv is the factory-owned Node executable, `<packageRoot>/index.js`, then:

    --no-auto-update --no-ask-user --no-remote --no-remote-export --output-format=json --stream=on --model=gpt-6-luna --reasoning-effort=low --available-tools=view,grep,glob --deny-tool=shell,write,url,memory --disable-builtin-mcps -C <worktree>

`COPILOT_AUTO_UPDATE=false` is set in the child environment. There is no `-p` prompt argument: the managed common runner sends a UTF-8 packet and EOF on stdin. That packet begins with the active task, then the required JSON control envelope, explicit saved correction context if present, and literal skill instruction/resource bytes. Resource content is labeled as task data. Prompt, context and resource bytes are absent from argv. Requested skill names are not reported as native loaded skills.

The exact installed help at `/tmp/factory-copilot-1.0.101-help.txt` confirms the flags and piped stdin mode. The [official programmatic reference](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-programmatic-reference) describes JSONL and piped prompts. The [official permission guidance](https://docs.github.com/en/copilot/how-tos/copilot-cli/use-copilot-cli/allowing-tools) distinguishes tool availability from approval and gives deny precedence. Exact installed version behavior controls qualification when documentation changes.

The stdout decoder requires a native turn, a `final_answer` message start, its matching message content or deltas, a matching turn end and one terminal `result` with nonempty `sessionId`, zero native `exitCode` and no error/failure field. It never accepts tool, log, user or reasoning text as a final answer. `tool.execution_complete` with `success:false` and `error.code:"denied"` is terminal failure regardless of native exit code or subsequent assistant output. Native errors, malformed JSONL, missing terminal events, conflicting final content and events after result fail. Parser diagnostics do not echo untrusted native bytes. The common runner retains bounded raw captures before decoding and validates the decoded control envelope and caller payload.

The terminal `result` is the first reliable session identity in the observed stream. The per-launch parser emits one root lifecycle event with that native ID. Earlier running identity remains unknown, and interrupted work may have no native session row. Usage, loaded skills and child-parent attribution remain unknown. `canReuse` is false, direct reuse is refused, and each correction/review uses a fresh launch. Stop delegates only to the common owned process-scope callback; escaped or remote descendants are outside the demonstrated cleanup claim.

## Mode boundary

Only read-only is offered. The installed sandbox help at `/tmp/factory-copilot-1.0.101-sandbox.txt` says native `--sandbox` governs shell commands and optional local MCP/LSP servers, while built-in file edits are not OS-sandboxed. The installed permissions help says a plain `--allow-tool=write` permits all file edits, and default path verification includes the current directory and the system temporary directory. A single absolute `write(path)` rule names one path; this does not establish arbitrary writes confined to the factory worktree. Combining broad write approval with the command sandbox would overstate the factory's `workspace-write` contract. The adapter refuses that mode until an exact native path-enforcement design and harmless proof exist. No write permission is silently relabeled as workspace-write.
