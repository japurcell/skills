## Native protocol

`.github/workflows/windows-factory-startup.yml` runs only by manual dispatch on `windows-2025`. It uses read-only repository permission, checkout without persisted credentials, pinned action SHAs, an exact Node 24.22.1 bootstrap, exact official archive digests, no repository secrets, and an `always()` artifact upload. Archive downloads occur in this explicit disposable CI job, never in product startup. Each run retains `bootstrap.json`, `artifacts.json`, `qualification.json`, per-case `spec.json`, raw debug event TSV, stdout/stderr, and launcher logs for 14 days, including failures.

`windows-startup-trace.cs` launches the absolute selected executable with `CreateProcessW(DEBUG_PROCESS)` in a private cwd/environment. The tracer uses `WaitForDebugEvent` on the same thread, records every `CREATE_PROCESS_DEBUG_EVENT`, the root `EXIT_PROCESS_DEBUG_EVENT`, `LOAD_DLL_DEBUG_EVENT` paths from kernel file handles, and a completed event loop. It records a positive control in which a debugged PowerShell process starts an intentional child. `DEBUG_PROCESS` covers debugged descendants unless a descendant itself starts a separate debug chain, per [Microsoft's debug process documentation](https://learn.microsoft.com/en-us/windows/desktop/Debug/process-functions-for-debugging). A missing positive event, missing DLL path, unmatched root image, unexpected child, timeout, or trace error fails qualification. A separate sleep control requests direct termination and requires observed root exit and a `STOP_OBSERVED` record. See [WaitForDebugEvent handle and event rules](https://learn.microsoft.com/en-us/windows/win32/api/debugapi/nf-debugapi-waitfordebugevent) and [process creation flags](https://learn.microsoft.com/en-us/windows/desktop/ProcThread/process-creation-flags).

The helper matrix exercises all four fixed Git argument lists in normal, linked-with-spaces, unborn, and reftable disposable repositories. It also alters a linked registration to require a nonzero identity probe. A private global config includes active include, pager, fsmonitor, filter, hook, credential, and remote canary values. A PATH-first `git.cmd`/`tsc.cmd` wrapper and config commands write an owned marker if executed; `where.exe` confirms the wrappers resolve through PATH, while no fixed helper may create the marker. The tracer's environment contains only explicit Windows roots, private home/temp/config paths, PATH wrappers, and fixed trace2-off values. The outer process seeds hostile Git redirect, ask-yes-no, strace, compiler debug, Node, and loader variables and asserts none reach a helper. No config, hook or filter is disabled in the product. A separate output flood control must trigger a 256 KiB stop request and observed root exit; retained stdout/stderr files are truncated to that bound with original byte counts recorded.

The compiler matrix directly launches `tsc.exe -p <generated-config>` for a successful single-file build, a type error, and a no-emit case. The generated config fixes files and compiler options; a separate hostile authored config and executable-looking source text must not be executed. Neither LSP/API, `--build`, watch, extends, plugins, arbitrary flags, nor a caller compiler host is admitted. Captured stdout/stderr over 256 KiB fails the case. The probe mutates and restores a copy of `git.exe`, a Git DLL, `tsc.exe`, and a packaged compiler library to prove package identity refusal before launch. Actual loaded DLL paths must be inside the pinned archive or the Windows root; package member hashes are rechecked.

This is a bounded probe of the selected helper versions, arguments and disposable environment. It is not a generic Windows child-containment layer. A passing workflow would be evidence for a subsequent review of a private operation discriminator, exact cwd/config/argv/artifact identity, captured pipes, ignored stdin, claim-linked repository revalidation, and direct completion. It would not qualify arbitrary commands, a PATH wrapper, checkout/worktree add, source-to-binary equivalence, or full same-invocation new-worktree startup.
