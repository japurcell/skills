## Native protocol

`.github/workflows/windows-factory-startup.yml` runs on a path-filtered push to `codex/research-agentic-workflow-prototypes` after review, or by manual dispatch once the workflow is present on the default branch. The push trigger permits this new workflow to run without changing the default branch. It uses `windows-2025`, read-only repository permission, checkout without persisted credentials, pinned action SHAs, an exact Node 24.22.1 bootstrap, exact official archive digests, no repository secrets, and an `always()` artifact upload. Archive downloads occur in this explicit disposable CI job, never in product startup. Each run retains `bootstrap.json`, `artifacts.json`, `qualification.json`, per-case `spec.json`, raw debug event TSV, stdout/stderr, and launcher logs for 14 days, including failures.

`windows-startup-trace.cs` launches the absolute selected executable with `CreateProcessW(DEBUG_PROCESS)` in a private cwd/environment. The tracer uses `WaitForDebugEvent` on the same thread, records every `CREATE_PROCESS_DEBUG_EVENT`, the root `EXIT_PROCESS_DEBUG_EVENT`, `LOAD_DLL_DEBUG_EVENT` paths from kernel file handles, and a completed event loop. Its positive control launches a native `cmd.exe /d /c` parent that invokes a second absolute `cmd.exe /d /c exit 0`; the trace must show a distinct child PID with that exact image and its exit. An incidental console-host child cannot satisfy the control. [Microsoft documents](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/cmd) `/d` as disabling AutoRun and `/c` as executing a command then exiting. `DEBUG_PROCESS` covers debugged descendants unless a descendant itself starts a separate debug chain, per [Microsoft's debug process documentation](https://learn.microsoft.com/en-us/windows/desktop/Debug/process-functions-for-debugging). Each fixed helper case must contain at least one resolved DLL path; each Git case must show all five pinned imported non-system DLLs in its own trace. A missing positive event, missing DLL path, unmatched root image, unexpected child, timeout, or trace error fails qualification. A separate sleep control requests direct termination and requires observed root exit and a `STOP_OBSERVED` record. See [WaitForDebugEvent handle and event rules](https://learn.microsoft.com/en-us/windows/win32/api/debugapi/nf-debugapi-waitfordebugevent) and [process creation flags](https://learn.microsoft.com/en-us/windows/desktop/ProcThread/process-creation-flags).

The helper matrix exercises all four fixed Git argument lists in normal, linked-with-spaces, unborn, and reftable disposable repositories. It also alters a linked registration to require a nonzero identity probe. A private global include is positively queried for `core.fsmonitor`; the fsmonitor command value is not invoked by that query. Pager, filter, hook, credential, and remote values are present as decoys, but the current fixed modes do not prove those values effective or exercise their execution paths. A PATH-first `git.cmd`/`tsc.cmd` wrapper writes an owned marker if executed; `where.exe` confirms the wrappers resolve through PATH, while no fixed helper may create the marker. The tracer's environment contains only explicit Windows roots, private home/temp/config paths, PATH wrappers, and fixed trace2-off values. The outer process seeds hostile Git redirect, ask-yes-no, strace, compiler debug, Node, and loader variables and asserts none reach a helper. No config, hook or filter is disabled in the product. A separate output flood control must trigger a 256 KiB stop request and observed root exit; retained stdout/stderr files are truncated to that bound with original byte counts recorded.

The compiler matrix directly launches `tsc.exe -p <generated-config>` for a successful single-file build, a type error, and a no-emit case. The generated config fixes files and compiler options. Executable-looking source text is compiled without running it. The separate hostile authored config is an unselected decoy: no case passes its path to `-p`, so this run makes no claim about how the compiler would handle that config. Neither LSP/API, `--build`, watch, extends, plugins, arbitrary flags, nor a caller compiler host is admitted. Captured stdout/stderr over 256 KiB fails the case. The probe mutates and restores a copy of `git.exe`, a Git DLL, `tsc.exe`, and a packaged compiler library to prove package identity refusal before launch. Actual loaded DLL paths must be inside the pinned archive or the Windows root; package member hashes are rechecked.

This is a bounded probe of the selected helper versions, arguments and disposable environment. It is not a generic Windows child-containment layer. A passing workflow would be evidence for a subsequent review of a private operation discriminator, exact cwd/config/argv/artifact identity, captured pipes, ignored stdin, claim-linked repository revalidation, and direct completion. It would not qualify arbitrary commands, a PATH wrapper, checkout/worktree add, source-to-binary equivalence, or full same-invocation new-worktree startup.
