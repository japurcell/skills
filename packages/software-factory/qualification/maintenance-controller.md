# T15b maintenance admission boundary

The controller reserves an absent canonical Git common directory's `factory/` child with one nonrecursive `mkdir`. It then writes, flushes, closes and verifies the private, bounded `bootstrap-incomplete` marker before creating SQLite. The marker binds a generated operation and repository ID, canonical Git root/common directory, original owner, selected release and artifact digests, target schema 7, and stage name outside `install/`. An existing empty, foreign, linked, partial or unmarked root is ambiguous and is preserved. A crash between `mkdir` and the complete marker has no recorded operation to reclaim.

The new schema, `incomplete` repository row and one typed maintenance claim commit in one SQLite transaction. The existing `owner_claims` table remains the only post-bootstrap admission authority. Runners and dashboards use the same `ready()` predicate; a typed maintenance claim blocks both. Generic owner clearance rejects every maintenance claim, and generic quiescent release rejects typed claims. Explicit reclamation inspects the recorded owner, refuses a known-live identity, requires a bounded operator clearance, and rotates the claim token and owner while retaining the operation in one transaction. PID age alone is never clearance.

`inspectMaintenance` opens current SQLite read-only and returns a redacted operation summary even while normal store open refuses the marker or incomplete state. Unsupported schema, corrupt data, mismatched marker/claim, partial records, missing first-install marker and unrecorded database sidecars remain blocked. A complete marker with absent database can be resumed only for its recorded operation after owner inspection. This path never recreates a present partial or corrupt database. An installed-ready commit and marker unlink are deliberately reserved for the later install validator.

The controller accepts a bounded staged `payload/` tree outside `install/`, hashes regular files and empty directory names through checked descriptors, and records its directory identity and digest before issuing a private `0600` ticket. The ticket contains the claim token, selected release digests and a random nonce; the public prepare result omits the token and nonce. A foreground launcher must wait for the old process to close, then write the matching private `handoff-exit-<nonce>.json` receipt. The staged entry checks the repository, marker when applicable, exact stage bytes and identity, ticket, receipt, claim token, operation and phase before atomically marking the ticket consumed, phase `modifying`, and repository `incomplete`. Replay and altered stage content refuse. Explicit reclamation of a prepared handoff invalidates the old token/nonce and can issue a new ticket for the same operation and phase.

The receipt is a protocol assertion from the future external launcher, not independent proof of process lifetime. The maintained tests use controlled disposable stage files and simulate the receipt. They do not run a Python launcher, replace a mapped Windows image, validate an installed runtime or publish `ready`. The install task must supply the foreground wait, actual staged Node and full installed-file/schema validation before one final ready/claim-release commit. Native Windows image-lifetime qualification remains separate.

## Reproduction and checks

From `packages/software-factory` with pinned Node v24.22.1 and offline dependencies, run `npm run typecheck`, `npm run build`, then `node --test test/maintenance-controller.test.mjs`. The focused file passed 14 disposable cases with zero skips covering first-installer contention, ambiguous and linked roots, marker/database crash boundaries, corrupt/unsupported storage and logical claim mismatch, runner/dashboard/maintenance admission races, generic clearance/release bypass, known-live owner refusal, exact phase and token compare-and-set, selected-digest and stage tampering, nonce mismatch, ticket replay, and operation-preserving handoff reclamation. It requires local Git process and placement probes. The maintained selector in `scripts/test.mjs` still needs parent registration before `npm run test:maintenance` or `test:all` counts these cases.

This implementation adds no public CLI, installer, schema migration, backup, uninstall, cleanup, provider call, notification send, or publication path. No user home installation or native Windows qualification was performed.
