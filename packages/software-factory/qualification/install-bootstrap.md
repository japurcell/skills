# T15b install bootstrap verification

`skills/software-factory/scripts/install.py` is a Python 3.11+ standard-library first-execution boundary. The public command is:

```text
python3.11 skills/software-factory/scripts/install.py verify --bundle-root ABSOLUTE_BUNDLE --manifest-sha256 EXTERNALLY_SELECTED_SHA256 --node-archive ABSOLUTE_PINNED_ARCHIVE
```

It returns one bounded JSON receipt with the schema, release version/platform, selected manifest and Node digests, archive size/member count, bundle file count, and exact omitted convenience-link names. It writes no repository, `factory/`, store, installed-ready state, provider artifact, authentication data or configuration. It makes no download or desktop call. Every failure has exit 1, no receipt on stdout, and a bounded diagnostic on stderr.

Python checks the exact schema-2 manifest SHA256 selected outside the bundle before parsing it, rejects duplicate JSON keys/unknown fields and enforces the qualified Node asset table. It independently checks the complete fixed runtime, map, declaration, web, template, metadata and toolchain file inventory, exact directory inventory, regular types, portable paths, case-folded collisions, per-file sizes and SHA256, and the fixed approved toolchain lock SHA256. Each source file is copied through a no-follow descriptor into a private temporary snapshot and hashed during copying; the original inventory and identities are rechecked before execution. The selected archive is copied and SHA256-checked against the platform's fixed release pin before inspection. No selected JS is imported from the mutable source path. The verified temporary Node runs only `validateInstallSelection()` from the verified temporary bundle; its complete JS semantic release validation remains required. The fixed Python receipt never exposes temporary paths or a selection token.

`prepare_install_selection()` is the reusable scope for the later installer. Its `PreparedSelection` carries distinct canonical original source paths and private snapshot paths; `revalidate_sources()` checks original identities, inventory, and bytes again before a later candidate may bind those paths. A successful `verify` certifies the selected snapshot at verification time. It is not permission to assume that an original source path remains unchanged later.

The public `extract_node_archive()` API is the hostile archive test seam. It accepts only a fresh `PrivateStage`, validates all member names/types, duplicate and ancestor case collisions, parent types, and bounds before writing regular files/directories. It refuses all unexpected links and special entries; POSIX omits only the exact `bin/corepack`, `bin/npm`, `bin/npx` symlink name/target pairs. Production verification requires all three omissions for macOS/Linux. Limits are 8,192 members, 256 MiB expanded regular payload, 128 MiB per member, and 128 MiB archive source. ZIP entries reject link/reparse metadata and are opened through `zipfile` for central/local header and CRC checks. The stage records its exact created inodes and removes only those regular files/directories, without following links or deleting an unexpected foreign file. The temporary tree is outside `factory/`.
