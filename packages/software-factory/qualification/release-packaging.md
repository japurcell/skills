# T15a release packaging qualification

T15a produces a reviewable directory and manifest. It does not install into a repository, download Node, publish a release, or claim native desktop delivery. The command requires an explicit JSON release selection and an absolute destination outside the source tree that does not yet exist. A matching complete destination may be verified and returned again. A changed or partial destination is preserved and refused for operator inspection.

Build with the pinned Node v24.22.1 and the locked development dependencies, then run `node packages/software-factory/scripts/package-release.mjs --descriptor /absolute/selection.json --destination /absolute/new-bundle` from the repository root. `--source-root /absolute/package-root` is available for disposable qualification fixtures. The selected JSON has `version` (semantic version), `platform` (`darwin-arm64`, `linux-x64`, or `win32-x64`), and `node` with exact `version`, `url`, and `sha256` fields. Those Node values must match the pinned official release values in [`runtime-manifest.json`](runtime-manifest.json), sourced from the [Node v24.22.1 release checksums](https://nodejs.org/download/release/v24.22.1/SHASUMS256.txt). The command never guesses or downloads an asset. The caller must supply the intended release version and selected artifact facts.

For `win32-x64`, the selection additionally requires `windowsHelper` with absolute `path`, exact `sha256`, and `qualificationRun: "39808257041"`. Packaging pins SHA256 `f46ba4a408f8618d5e186ce29cf47bdac3411b67356136d79da4a0ed0c35ec44`, the retained native x64 helper from that run, and verifies the selected binary before copying it. That run proved native compilation and temporary shortcut ownership tests. Visible delivery remains unverified. An ARM64 helper, a different hash, or an absent binary is refused until separately qualified and the pinned release contract is revised. macOS and Linux use the platform's existing system notification commands, so no helper binary is bundled for them. The Windows startup Git/TypeScript helper candidates remain unqualified and are not included.

The payload owns `dist/` compiled runtime plus web, `templates/`, a minimal ESM `package.json`, and the pinned Windows helper only on `win32-x64`. `dist/learning.js` is an ordinary importable runtime module for an explicit operator learning workflow. Templates use `@local/software-factory` only for TypeScript type imports; the release package does not install an authoring dependency environment. T15b/T16 must install and maintain that environment separately. No `node_modules` or development package metadata is copied into the payload.

`src/release.ts` exports the typed `ReleaseSelection`, `ReleaseManifest`, `packageRelease`, `validateReleaseSelection`, and `validateReleaseBundle` contract. The command prints `manifestSha256` in JSON. T15b must obtain that digest from its selected release descriptor and pass it as the required second argument to `validateReleaseBundle(absoluteBundleRoot, expectedManifestSha256)` before consuming any file. Validation checks the exact pinned Node/platform/helper facts, regular files, every file SHA256 and byte length, required files, no unowned files or directories, no symlinks, safe portable paths, duplicates, and case-insensitive collisions. The selected manifest digest is the external trust binding; a manifest inside the directory alone cannot authenticate itself.

The deterministic public command and validator tests use disposable source and destination trees. They cover complete sorted inventory, repeat verification, payload tamper and unowned content refusal, source symlinks, stale built web, manifest hash/traversal/duplicate refusal, exact version/platform/Node asset selection, and missing/unqualified/changed Windows helper refusal. Run:

```text
PATH=/absolute/qualified/node/bin:/Users/adam/homebrew/bin:/usr/bin:/bin node --test packages/software-factory/test/release-packaging.test.mjs
```

On 2026-10-22 the focused eight-case suite passed under Node v24.22.1 after strict typecheck and build. A disposable proof of the actual built tree produced 89 owned files for a selected `1.2.3` darwin-arm64 fixture and 90 for a selected `1.2.3` win32-x64 fixture, including the retained qualified helper. Their manifest digests were `e8358ed21596005bf8fe1accf8d3ceafa433100c6beca2f4a11d458aca2d089c` and `ea8b3c673230e9b11a3da6fd06240eaddf7e0eed7d7ba1ec895be955a122f80d`, respectively, under `/tmp/factory-release-proof-b0vSI1/`. These are local review fixtures, not a published release selection. Full native installation, provider and visible desktop acceptance remain T15b/T17 work.
