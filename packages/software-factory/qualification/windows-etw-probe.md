# Bounded Windows ETW feasibility probe

This qualification-only probe is T17-Windows-ETW-probe. It creates one file-backed sequential `EVENT_TRACE_SYSTEM_LOGGER_MODE | EVENT_TRACE_STOP_ON_HYBRID_SHUTDOWN` session with `PROCESS | IMAGE_LOAD` on a disposable `windows-2025` runner. The stop-on-hybrid policy is requested explicitly, rather than leaving ETW to choose its documented default. The session is started and queried before a normal, non-debug pinned Node v24.22.1 launch. That Node runs one known transient Node child. The ETL has a 64 MiB cap; observation has a 30-second internal bound; the workflow step has a 12-minute outer bound that does not imply trace completeness. The native bridge holds the root process handle through stop and offline parse, checks its full image against the pinned executable, and compares the root/child process keys in memory. Known process start and image-load paths must exactly match the canonical pinned executable; NT path forms or other ambiguity fail the probe. Only after start/end lifetime, parent, key and image checks does the bridge emit fixed `pinned-node` labels. The receipt contains controlled process IDs, labels, selected start/end/image timestamps, TDH field names/types, rundown counts, API return codes, session and final-header loss counters, and the ETL byte count. It does not serialize full process command lines, environments, raw image paths or kernel pointer values.

The Node public validator fails on missing API success, session identity/flags, ABI, positive root/child events, parent/key labels, timestamps, image loads, final `EndTime`, loss counters, file cap or completion marker. It requires one all-true five-bit `QUERY` row for each successful ready and before-stop query. These bits report only whether the returned GUID, log mode, enabled flags, file cap and loss counters match the existing exact checks. It also requires one `MODE` row per query with the exact current expected categories: system bit 1, sequential bit 1, alternate storage 0, hybrid selector `stop`, other bits 0. The exact SESSION mode is now decimal 37748737, the single requested system + sequential + stop profile. The category row distinguishes missing required bits, conflicting storage, hybrid selector bits and other bits without disclosing the numeric returned mode. The producer emits both rows before the unchanged exact full-mode comparison can throw; these categories do not authorize normalization or alternate accepted profiles. A synthetic passing receipt verifies the protocol, not Windows feasibility. Native failures and bridge diagnostics use fixed stage/code fields and numeric Win32 codes without exception text. The C# producer caps `native.tsv` at 65,536 UTF-8 bytes before writing it; overflow writes only a small typed failure. The workflow removes the raw ETL and validates byte bounds and the native TSV row grammar before uploading explicit receipts. It skips upload if cleanup or artifact preparation fails. The native result is review-required even if it passes. This task stops before any Git/TypeScript comparator, unknown-child absence claim, product observer or helper admission.

Official source contracts used: [StartTraceW](https://learn.microsoft.com/en-us/windows/win32/api/evntrace/nf-evntrace-starttracew), [EVENT_TRACE_PROPERTIES](https://learn.microsoft.com/en-us/windows/win32/api/evntrace/ns-evntrace-event_trace_properties), [ControlTraceW](https://learn.microsoft.com/en-us/windows/win32/api/evntrace/nf-evntrace-controltracew), [EVENT_TRACE_LOGFILEW](https://learn.microsoft.com/en-us/windows/win32/api/evntrace/ns-evntrace-event_trace_logfilew), [TRACE_LOGFILE_HEADER](https://learn.microsoft.com/en-us/windows/win32/api/evntrace/ns-evntrace-trace_logfile_header), [EVENT_RECORD](https://learn.microsoft.com/en-us/windows/win32/api/evntcons/ns-evntcons-event_record), [TDH property decoding](https://learn.microsoft.com/en-us/windows/win32/api/tdh/nf-tdh-tdhgetproperty), [Process_V2_TypeGroup1](https://learn.microsoft.com/en-us/windows/win32/etw/process-v2-typegroup1), [Image_Load](https://learn.microsoft.com/en-us/windows/win32/etw/image-load), [Windows file path formats](https://learn.microsoft.com/en-us/dotnet/standard/io/file-path-formats), [Win32 naming rules](https://learn.microsoft.com/en-us/windows/desktop/fileio/naming-a-file), and [Microsoft PerfView's managed ETW declarations](https://github.com/microsoft/perfview/blob/main/src/TraceEvent/TraceEventNativeMethods.cs). The x64 layout is checked at runtime. Hosted administrator documentation is a prerequisite hint, not native rights proof.

Automatic approval review rejected uploading raw ETL to GitHub because its system-wide process metadata might disclose ambient information. Independent follow-up review found that operational `bootstrap.json` also contains runner paths and free-text errors. The workflow keeps it local for exact pin verification, suppresses its untrusted console output, and uploads only explicitly reconstructed `upload/qualification.json` and validated `upload/native.tsv`. Artifact preparation checks each source byte bound before copying and never publishes raw bootstrap data. If the process is interrupted, an always-run cleanup step removes the exact ETL before upload. The uploaded result cannot support independent raw ETL replay. A raw trace artifact would require separate authorization.

The first hosted Windows run at `43b3b9bb` demonstrated administrator access and successful start, ready-query API return, stop, ETL open, process and close calls, but failed before launching the Node fixture. The diagnostic run `39859018946` isolated an exact log-mode mismatch. The third run `39861499716` reported `QUERY readyQuery 1 0 1 1 1` and `MODE readyQuery 1 1 0 stop 0`: the requested system and sequential bits were present, with only the documented stop-on-hybrid bit added. The later decode failure is downstream of that pre-fixture exit and proves neither TDH schema failure nor known-event absence. Microsoft's logging-mode constants document that ETW chooses a hybrid-shutdown default when neither selector is requested. The explicit stop request resolves that policy ambiguity while retaining exact equality; it does not claim an undocumented internal mechanism or establish native feasibility. Another reviewed native run is required.

At most one `DIAG` row appears immediately before `FAIL decode`. Most reasons retain exactly four fixed fields: phase (`callback`, `keys`, `identity`), reason, and target (`root`, `child`, `none`). Only `callback process-image-mismatch root|child` appends three closed categories from the already decoded process-start `ImageFileName`: `form` is `name-only`, `dos-absolute`, `device-absolute`, or `other`; `basename` is `same` or `different` relative to the pinned executable basename; `time` is `before-creation-window`, `before-creation-within-window`, `at-or-after-creation-within-window`, `after-creation-window`, or `unknown` relative to the held root's `GetProcessTimes` creation. The window remains five seconds. Child time is always `unknown` because this probe holds no child handle. Explicit Windows string classification recognizes drive-absolute paths with documented slash or backslash separators and native `\Device\...` paths, while treating extended Win32, UNC, malformed and unrecognized forms as `other`, without guessing a namespace mapping. These categories are diagnostic evidence only. Exact pinned-path equality and every existing acceptance predicate remain unchanged, so a matching basename or time category cannot make the event pass. The row never includes the decoded path, property value, exception text, provider identifier or ambient metadata; the first rejection wins.

A diagnostic never satisfies `EVENT`, `SCHEMA`, `COUNTS`, `HEADER`, or `COMPLETE`. Artifact preparation retains a single well-formed failed-decode diagnostic within the 65,536-byte cap and removes malformed, duplicate, misplaced, unknown, extra-field, path-bearing, oversized, or positive-plus-diagnostic native receipts. The parser rejects child time categories other than `unknown` and any extra fields on other reasons. A forged passing summary with a failed diagnostic is downgraded to `failed/receipt-invalid`. A fresh native Windows run must be reviewed before any acceptance change.

If a callback or identity check fails and `CloseTrace` also returns an error, the receipt records the numeric `API close` result, then the first fixed `DIAG` and one terminal `FAIL decode`. A close-only failure records `API close` and one `FAIL decode native-api` with its numeric code. The strict upload parser still removes the old duplicate-failure form, while retaining the corrected bounded failed receipt. Local PowerShell 7 reflection exercised both compound and close-only outcomes; Windows PowerShell 5.1 and actual native behavior remain unverified.

For the image-form extension, the public `--prepare-artifacts` tests first failed against the four-field allowlist, then passed with the seven-field closed grammar and negative upload cases. Portable PowerShell 7 reflection exercises Windows path categories, basename categories, five-second time boundaries, child `unknown`, first rejection, compound failure order, native wiring and producer byte cap. Existing reflection checks retain the exact mode and ABI assertions. These local tests do not substitute for a fresh Windows receipt showing the actual field form.
