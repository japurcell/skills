# Bounded Windows ETW feasibility probe

This qualification-only probe is T17-Windows-ETW-probe. It creates one file-backed sequential `EVENT_TRACE_SYSTEM_LOGGER_MODE` session with `PROCESS | IMAGE_LOAD` on a disposable `windows-2025` runner. The session is started and queried before a normal, non-debug pinned Node v24.22.1 launch. That Node runs one known transient Node child. The ETL has a 64 MiB cap; observation has a 30-second internal bound; the workflow step has a 12-minute outer bound that does not imply trace completeness. The native bridge holds the root process handle through stop and offline parse, checks its full image against the pinned executable, and compares the root/child process keys in memory. Known process start and image-load paths must exactly match the canonical pinned executable; NT path forms or other ambiguity fail the probe. Only after start/end lifetime, parent, key and image checks does the bridge emit fixed `pinned-node` labels. The receipt contains controlled process IDs, labels, selected start/end/image timestamps, TDH field names/types, rundown counts, API return codes, session and final-header loss counters, and the ETL byte count. It does not serialize full process command lines, environments, raw image paths or kernel pointer values.

The Node public validator fails on missing API success, session identity/flags, ABI, positive root/child events, parent/key labels, timestamps, image loads, final `EndTime`, loss counters, file cap or completion marker. It requires one all-true five-bit `QUERY` row for each successful ready and before-stop query. These bits report only whether the returned GUID, log mode, enabled flags, file cap and loss counters match the existing exact checks. It also requires one `MODE` row per query with the exact current expected categories: system bit 1, sequential bit 1, alternate storage 0, hybrid selector `none`, other bits 0. The category row distinguishes missing required bits, conflicting storage, hybrid selector bits and other bits without disclosing the numeric returned mode. The producer emits both rows before the unchanged exact mode comparison can throw; these categories do not authorize mode normalization. A synthetic passing receipt verifies the protocol, not Windows feasibility. Native failures and bridge diagnostics use fixed stage/code fields and numeric Win32 codes without exception text. The C# producer caps `native.tsv` at 65,536 UTF-8 bytes before writing it; overflow writes only a small typed failure. The workflow removes the raw ETL and validates byte bounds and the native TSV row grammar before uploading explicit receipts. It skips upload if cleanup or artifact preparation fails. The native result is review-required even if it passes. This task stops before any Git/TypeScript comparator, unknown-child absence claim, product observer or helper admission.

Official source contracts used: [StartTraceW](https://learn.microsoft.com/en-us/windows/win32/api/evntrace/nf-evntrace-starttracew), [EVENT_TRACE_PROPERTIES](https://learn.microsoft.com/en-us/windows/win32/api/evntrace/ns-evntrace-event_trace_properties), [ControlTraceW](https://learn.microsoft.com/en-us/windows/win32/api/evntrace/nf-evntrace-controltracew), [EVENT_TRACE_LOGFILEW](https://learn.microsoft.com/en-us/windows/win32/api/evntrace/ns-evntrace-event_trace_logfilew), [TRACE_LOGFILE_HEADER](https://learn.microsoft.com/en-us/windows/win32/api/evntrace/ns-evntrace-trace_logfile_header), [EVENT_RECORD](https://learn.microsoft.com/en-us/windows/win32/api/evntcons/ns-evntcons-event_record), [TDH property decoding](https://learn.microsoft.com/en-us/windows/win32/api/tdh/nf-tdh-tdhgetproperty), [Process_V2_TypeGroup1](https://learn.microsoft.com/en-us/windows/win32/etw/process-v2-typegroup1), [Image_Load](https://learn.microsoft.com/en-us/windows/win32/etw/image-load), and [Microsoft PerfView's managed ETW declarations](https://github.com/microsoft/perfview/blob/main/src/TraceEvent/TraceEventNativeMethods.cs). The x64 layout is checked at runtime. Hosted administrator documentation is a prerequisite hint, not native rights proof.

Automatic approval review rejected uploading raw ETL to GitHub because its system-wide process metadata might disclose ambient information. Independent follow-up review found that operational `bootstrap.json` also contains runner paths and free-text errors. The workflow keeps it local for exact pin verification, suppresses its untrusted console output, and uploads only explicitly reconstructed `upload/qualification.json` and validated `upload/native.tsv`. Artifact preparation checks each source byte bound before copying and never publishes raw bootstrap data. If the process is interrupted, an always-run cleanup step removes the exact ETL before upload. The uploaded result cannot support independent raw ETL replay. A raw trace artifact would require separate authorization.

The first hosted Windows run at `43b3b9bb` demonstrated administrator access and successful start, ready-query API return, stop, ETL open, process and close calls, but failed before launching the Node fixture. The later diagnostic run `39859018946` reported `QUERY readyQuery 1 0 1 1 1`: only exact mode equality failed. The actual returned mode was not serialized, so its bit pattern and cause remain unknown. The later decode failure is downstream of that pre-fixture exit and proves neither TDH schema failure nor known-event absence. Microsoft's logging-mode contract does not by itself prove a normalization on this runner. This change adds only closed mode categories and x64 property-offset checks; another reviewed native run is required to interpret them.

Local checks on 2026-10-22: exact local Node v24.22.1 ran twelve public protocol and CLI cases, including missing, duplicate, false, unknown and path-bearing mode rows, a forged qualification missing mode rows, safe retention of fixed failed diagnostics and removal of unsafe native rows. PowerShell 7 on macOS arm64 compiled the changed C# source, checked the 120-byte properties structure and LogFileMode/EnableFlags offsets 64/72, and a 70 KB synthetic producer input wrote only the 24-byte `FAIL receipt overflow` row. Static source-order verification placed both `QUERY` and `MODE` before either predicate throws. `node --check` and actionlint passed. Windows PowerShell 5.1 compilation of this change, actual queried mode categories, TDH path form and schema, final header values and known event visibility remain unverified. Microsoft documents `Process_V2_TypeGroup1.ImageFileName` as a path and `Image_V1_Load.FileName` as a file name; if the native fields do not carry the exact pinned path, this strict gate must fail closed until a defensible native identity method is proved. A failed native receipt is a feasibility blocker, never a reason to weaken existing tests or admit the route.
