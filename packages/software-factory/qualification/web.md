# Saved observation browser qualification

Status: T11 browser, CLI and host proof on macOS arm64, 2026-10-22, with independent reader repair checks. This is a read-only local observer. It has no workflow launch, answer, approval, clearance, PID termination, native result mutation, installation or notification delivery control.

## Owner handoff and serving boundary

An actual owner handle can mint a cryptographically random, one-use, 60-second handoff ticket with `createUiHandoff()`. The ticket is in a URL fragment, so it is not sent on the initial GET. An inline script removes it synchronously with `history.replaceState` before loading an external script or making a request. Same-origin `POST /api/ui-session`, with an exact Origin and Host and a bounded JSON body, redeems it once. The response provides the host's existing bearer only to the page's memory. The ticket never becomes the bearer, is not persisted in the store, and cannot be minted through a public HTTP route. There are at most eight pending tickets and 32 failed redemption attempts per host. Cross-process reuse has no read credential and cannot create a handoff. Its CLI attempt refuses without closing the existing owner.

Only `/` and the two built assets `/assets/app.js` and `/assets/style.css` are served. Static paths are an exact allowlist, with no arbitrary file read. The UI has no third-party assets, scripts or referrers. Responses use no-store, no-referrer, nosniff, DENY framing and a restrictive CSP. Saved-data routes, including new run, event-head and selected-invocation pages, require the same bearer as T10 and retain exact local authority and browser-origin checks. The scoped selected-capture response includes its saved `attemptId`; a foreign capture gets a bounded 404. Browser SSE uses a `fetch` stream with an Authorization header, following the [Fetch API](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API/Using_Fetch) instead of native [EventSource](https://developer.mozilla.org/en-US/docs/Web/API/EventSource/EventSource), whose constructor has no custom-header option. The bearer is not sent in a URL, query, metadata, endpoint claim or console output.

The `dashboard --repository PATH` CLI opens an existing compatible store, starts an owned loopback host, prints only the one-use handoff URL, and closes the handle it owns on SIGINT or SIGTERM. It does not seize another process's claim. The owner must keep the process running for browser reads.

## Saved data and bounded state

The browser uses grouped run pages of 30 cards, chronological per-run invocation pages, at most 50 timeline lanes, 200 selected-invocation event rows and one bounded capture chunk page. Attempt, session and capture pagination replaces the current 50-row page and retains page cursors for backward navigation. The active attempt, session, capture and event pages are saved in bounded browser history state so Back/Forward restores the selected reader window. It retains parent identities of visited session pages so a collapsed branch stays hidden across page boundaries. Latest invocation status, outcome, cleanup uncertainty and operator clearance are shown independently; a clearance never rewrites an earlier result. Native child sessions use their saved reported parent IDs and can be collapsed. Capture content is rendered as inert text with explicit continuation, completeness and pruned state. Local search and filters apply to the currently loaded page. An unknown or unavailable deep link is disclosed without falling back to a different run.

The store uses indexed run and invocation selectors, a constant-time saved event head, and an indexed `invocationId` expression selector for selected event pages. The browser reads the committed head before its first snapshot. Every initial, route, page, Follow and gap snapshot owns one stream barrier: it invalidates and aborts the prior stream, waits for any in-flight projection, commits only if its route and snapshot ownership still match, then resumes SSE from the last applied cursor. A gap reads a replacement head before its snapshot and adopts that head only after the snapshot commits. The browser deduplicates rows already present in a snapshot. Freeze holds the applied cursor and current page while counting pending observations; Follow refreshes the current page before resuming from that cursor. Deferred observations retain at most 200 event objects even if more arrive, and SSE replay rebuilds from the applied cursor after Follow. Connection loss marks the display as the last known update. No unbounded history scan or event transfer is used to obtain a page.

Populated-state repair also preserves the run scroll position, inspector focus, open disclosures, capture page, and selected event window across Back/Forward and saved resnapshots. Scrolling away from output or selecting text pauses that output window while saved outcome, cleanup, attention and the header continue to update. An open capture follows new committed text within its current page; the page remains below 1,047,552 UTF-8 bytes and offers explicit continuation when full. Live event and capture rows keep their DOM identity during updates, preserving keyboard focus. Loaded index cards update their saved summary in place without reordering. A selected event cursor is checked by primary key and invocation ownership; a phase or attempt beyond the first page opens through a targeted page. Capture events with no attempt field resolve ownership from the saved capture's indexed identity, including captures beyond the first history page; fresh capture events also carry the saved attempt identity. The phase and saved-question selectors use the fresh schema-4 `attempt_operation_target` and `capture_question_target` indexes. Existing schema-4 stores opened before these indexes were added remain readable; their phase-only and saved-question selectors may use a table scan, while links with an attempt identity still use the attempt primary key. Schema-3 stores remain refused without mutation.

New repositories use schema 4 for the run and invocation event indexes. An existing schema 3 store is explicitly refused without modifying its data. T16 must provide an explicit, maintenance-locked 3-to-4 migration that creates these indexes and advances the version only after success. T11 does not auto-migrate on ordinary open.

## Reflection

The durable boundary is owner-only ticket minting, exact redemption and in-memory bearer use, alongside indexed and bounded saved reads. The independent repair showed that reading a committed head before a snapshot still requires deduplication against the snapshot window, and that preserving live reader focus requires stable event/capture nodes. The root repair additionally showed that every snapshot needs the same stream barrier and exact owner check; a visible cursor must follow committed projections. Browser and HTTP regressions encode these lessons. The old-schema migration prerequisite is recorded above for T16.
