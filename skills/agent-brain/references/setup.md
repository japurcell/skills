# Install and set up

Software installation and repository activation are separate operations. The repository installer retains its existing skill/global hook behavior and additionally installs immutable agent-brain software. The standalone `scripts/install-agent-brain.py` installer requires explicit `--software-dir`, `--bin-dir`, and discovered `--python` destinations. It validates the complete shipping source and exact available core/adapter/schema identities without importing supplied code. Use `--check --json` for read-only preflight. It downloads nothing, edits no shell profile, and reports the PATH action. POSIX defaults are `~/.local/share/agent-brain` and `~/.local/bin/agent-brain`; Windows defaults are `%LOCALAPPDATA%/agent-brain` and its `bin/agent-brain.cmd` plus `agent-brain.ps1` launchers. The repository installers accept `AGENT_BRAIN_SOFTWARE_DIR` and `AGENT_BRAIN_BIN_DIR` overrides. Installation grants no automatic lifecycle authority.

Run `agent-brain setup --json` at the actual Git worktree root. Raw plans include provider before/after setting snapshots and may contain private values: save them to an owner-only file in a private directory outside the worktree, never commit them or copy them into public notes. On POSIX, use an existing private directory and `(umask 077; agent-brain setup --json > /private/outside-worktree/plan.json)`; on PowerShell, select an existing outside-worktree directory with a private user ACL before saving JSON. Plain setup reads mappings, protected guidance, configuration, trust/permissions, certification inputs, ignored state and exact registrations without writes or model calls. Review the complete [plan](../schemas/setup-plan-v1.schema.json), then run `agent-brain setup --apply --plan /private/outside-worktree/plan.json --json`. Apply revalidates the Git base, configuration, knowledge inventory, software and certification under the selected runtime publication lock before effects. Changed inputs require a new plan. Reapplying an intact completed plan is idempotent; missing expected runtime fails instead of initializing a replacement.

A minimal repository gets one compact routing map with no invented learned facts, explicit universal path applicability, and future writable `.agents/instructions` and `.agents/memory` directories. These directories are valid empty owned roots until checked publication creates actual knowledge. Existing root `AGENTS.md`, then memory INDEX, ARCHITECTURE and CONVENTIONS are mapped as exact read-only files in required order. A read-only file root protects that exact document even alongside a writable directory root; publication requires exactly one writable directory owner and no matching read-only owner. Existing mappings remain authoritative.

Setup enables only configured exact observed native support records. Offline fixtures remain confined to disposable Git repositories and prove process translation only. Unverified builds, modes, events, permissions or runnable bytes remain unsupported. Copilot uses `.github/hooks/agent-brain.json`, Codex uses managed entries in `.codex/hooks.json`, and Gemini uses managed entries in `.gemini/settings.json`. Each provider/build/mode has a distinct selector in `.agents/context/registrations/`; the index records simultaneous integrations. Unrelated handlers and user/policy settings remain intact. Consumers need no existing hooks, canonical generator or `hooks/families` tree. Optional canonical source gates select their known provider from ordinary payloads; ambiguous simultaneous modes fail closed.

Immutable external software is bound by an exact absolute bundle path, manifest revision and complete byte inventory. Linked/reparse components, extra bytecode, changed code and unavailable version pins are rejected before code execution. The installed launcher chooses the repository's reviewed pin within its selected installation; help works without active context. To review an inventory update, invoke the explicitly selected compatible interpreter on the new bundle's `scripts/agent-brain.py setup --json`, then apply that saved plan through the same new bundle. Only explicit schema-1 to schema-1 updates with the same core/adapter identity are supported. Setup takes a bounded SQLite backup, preserves sessions, ownership/generations, existing opaque handles, obligations, candidates and history, and keeps the prior configuration binding only when semantic configuration and existing enabled provider definitions are unchanged. Unsupported version changes or downgrades fail before effects. Existing source pins must remain coherent with their selected bundle.

The durable setup journal records bounded forward/inverse file bytes before effects. Selectors publish last, and incomplete activation never grants authority. `setup --rollback JOURNAL --json` reverses only exact owned effects, preserves unexpected edits as explicit conflicts, revokes live authority and retains portable knowledge/history and recoverable runtime. `setup --deactivate --json` produces a new reviewable plan that removes owned handlers while preserving unrelated handlers added since activation. Apply that plan to revoke authority and keep knowledge/history. Missing runtime does not prevent owned deactivation or erase the external expected identity.

Private operational data includes setup journal setting snapshots, SQLite backups, runtime/source snapshots, local identities, selectors, locks and temporary files. Scoped local ignore markers precede their first write and remain after interruption or rollback of root `.gitignore` effects. Existing unrelated ignore bytes and negation order remain intact. Portable config, maps, candidates and semantic history remain visible; overlapping ownership is rejected. Already tracked private records cause a conflict and require explicit user index cleanup without deleting recovery data. [Git ignore rules](https://git-scm.com/docs/gitignore) do not untrack existing files. Retained privacy markers carry no lifecycle authority and are separate from reversible managed configuration effects.

`.agents/context/expected-runtime.json` survives complete deletion of the ignored runtime directory. Read-only `status`/`doctor` report unavailable/incomplete state rather than silently treating it as uninitialized. Preserve the exact backup and identity for recovery. Setup and rollback share the selected runtime's publication lock with learning/recovery; a separate bounded setup lock serializes first initialization. Unexpected concurrent edits remain conflicts. Journals use the existing 8 MiB complete-set bound; exact inverse bytes are never truncated.

Use `setup --shell posix` for POSIX shell commands or `--shell powershell` for PowerShell. The adapter emits the exact installed foreground continuation command with matching quoting, including PowerShell `&` and doubled apostrophes. Issued continuations and start/prepare/publish/complete commands retain the exact selected `--config` path. The launcher reads that configuration's pin before importing core code, even when its software installation default has advanced. Run the issued command unchanged and append only its supported control/classification flags. Registered learn/dream stage commands accept the absolute installed launcher or the exact bundled Python form. Shell composition or unknown command flags do not pass registered-command admission. Native provider consumption, native Windows behavior, provider watchdogs, semantic quality, performance/usage benefit and power-loss durability remain unverified.
