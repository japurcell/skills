# Native adapter candidates

M7 ships deterministic native envelopes and offline subprocess fixtures. It certifies no installed provider build, model boundary, consumption, Windows behavior or provider watchdog. Both VS Code harnesses remain deferred. Registration templates in `assets/registrations/` are inactive files: replacing `__BUNDLE__` or installing a skill does not activate support. M8 owns reversible activation; M10 owns observed native certification.

Copy the complete runnable skill bundle, including `scripts/` and `assets/adapters/`. No generator or peer provider import is needed. Launch the matching copied adapter with `--event EVENT` and `--registration .agents/context/native-registration.json`. The [selector schema](../schemas/native-registration-v1.schema.json) binds the configured integration, provider build, entry mode, repository-local bundle and selected configuration. Its configured provider must be enabled, use `kind: native`, and reference an exact [support record](../schemas/native-support-v1.schema.json). Codex desktop and CLI have separate entry modes and certification identities. Never relabel an offline fixture as observed certification.

Support pins include actual Git repository/worktree roots, repository UUID, core/adapter/schema versions, canonical certification UUID, platform/filesystem device, current permissions and native lifecycle configuration bytes, runnable adapter and complete Python bundle bytes, event set, initial scope, and build/mode. Configuration changes invalidate issued authority. `offline_fixture` is accepted only in disposable temporary Git repositories and carries `offline_translation_only` evidence. A `certified` record additionally requires matching observed context, decisions, event and watchdog evidence. This structure is a certification prerequisite, not proof that self-authored JSON or a successful process exit establishes consumption.

The adapter reads one UTF-8 JSON object without waiting for EOF. It rejects duplicate keys, non-finite numbers, malformed types, invalid UTF-8, incomplete/trailing data, special/linked pinned files and size excess. One cumulative four-second watchdog includes registration, input, subprocess, output and cleanup, reduced to 80% of a lower native deadline. On POSIX it also bounds blocking work with an alarm and bounded nonblocking stdout. Windows uses `PeekNamedPipe`; actual Windows process/output cancellation remains unverified. An internal incomplete decision says nothing about whether the provider honors it or times out open. Copilot timeouts remain documented fail-open. Diagnostic stderr never copies subprocess output or user content; high-rate successful tool decisions contain no context chatter.

Codex uses SessionStart (startup/resume/clear/compact), UserPromptSubmit, PreToolUse, PreCompact, supported SubagentStart/SubagentStop and Stop. Immediate compact restoration requires its own explicit capability binding. Copilot uses sessionStart, userPromptTransformed, preToolUse, advisory preCompact, supported wrapper child events and agentStop; ignored userPromptSubmitted output is unavailable. Original transformed prompts survive both successful and unsupported rewrites. Built-in general-purpose child hooks remain unsupported. Gemini uses SessionStart, BeforeAgent, BeforeTool, validated BeforeModel request messages, AfterAgent and advisory PreCompress; no child or post-compression hook is assumed. BeforeModel overrides preserve the original stable request and append guidance only for a bound request shape/order.

Callbacks issue opaque [foreground continuations](../schemas/foreground-recovery-v1.schema.json) for pending source or publication checks, new undelivered tool scope, and completion checkpoints. Run the exact returned `native-integration.py foreground --invocation-file FILE` command in the bound worktree. Classify an issued checkpoint with `--classification active|awaiting_user|ready_to_complete`; explicit `--control pause|cancel` keeps the objective stopped. These options modify an issued bound event only. Generic flags/environment cannot create one. Pre-tool callbacks admit only an exact valid issued continuation or a current registered learn/dream CLI command. Recovery uses existing journals and exact prior identity/output settlement before a new task's context. Duplicate callbacks consume no semantic attempt; foreground checks retain existing finite ownership and attempt caps.

Registered stage admission accepts literal POSIX arguments, including single/double quoted paths, unique `--invocation-file`/`--input`/`--config` values and standalone `--json`/`--no-color`. An explicit config must select the bound config; an omitted config must match the CLI default. Duplicate, unknown or malformed options, stale or mismatched invocation/stage/config, shell composition, expansion and command substitution are denied. Quoting an evaluated shell expression does not make it a registered stage.

Existing canonical source gates use ordinary native payloads through the pinned bridge's `--native-gate` path and the same configured native registration. They neither require fixture-only `agent_brain_event` nor create another obligation. A nested legacy gate cannot observe its outer provider envelope flush, so it never settles fresh context. It issues foreground restoration, invalidates startup/resume/lost-context receipts, and permits only previously verified current completed stop/task results read-only. Inactive legacy configuration remains unchanged. Source scanner reconciliation and its ten-second lock wait run only in foreground. Changed/new/renamed/removed sources and direct unjournaled semantic writes retain M6's incomplete/provenance boundaries.

A foreground parent checkpoint classified active/awaiting_user, or explicitly paused/cancelled, releases that stopping turn after its output flush and settlement. This release binds the exact registration, configuration, current task/input/context generations and recorded receipt. New work boundaries or changed inputs consume it; caller `stop_hook_active` is never authority. Canonical source stop gates join the same verified turn release, retaining pending source/publication work and dependent action gates without claiming objective completion. Parent release never completes a child or bypasses its assigned scoped review.

A native user task arriving on a paused/cancelled objective issues an intent continuation rather than returning empty context or resuming that work. Run the bound file with `--objective new` for independent work, `--objective resume` to explicitly resume the same paused task, or `--objective retain_stopped` to retain its stopped state. Resume restores current context on the same identity without spending or resetting semantic attempts; pending source/action gates remain. Cancelled tasks cannot resume. These choices require that issued task event; generic flags cannot manufacture a new task. New work receives current context while the old stopped identity, semantic attempts and pending source/publication obligations survive. Ordinary clarifications on an active objective keep its identity and budgets.

Foreground delivery records the canonical source snapshot with exact hashes and directory inventories in ignored typed state. Callbacks compare those recorded inputs directly and defer any missing/changed inventory, added/removed source, configuration change or changed source byte. They never invoke even a read-only scanner subprocess. Semantic completion still requires the existing current checked source revision and actual delivered guidance. Successful foreground tickets close after output settlement; resolved unreferenced tickets join the existing 30-day operational cleanup, while unresolved tickets/output and semantic work remain visible. Expired duplicate tickets are reissued without spending/resetting learn attempts or changing ownership.

An issued file and translated denial do not prove automatic execution. In particular, prompt denial can prevent Codex UserPromptSubmit or Gemini BeforeAgent from reaching the agent that should run recovery. These first-task paths remain unverified/unsupported for deployed activation until M10 observes an actual foreground continuation route in that exact build/mode. Certified records must carry that route's observed evidence; fake subprocess payloads cannot provide it.

Native output settlement uses a short-lived opaque issued receipt bound to the exact result and registration. Flush is necessary before availability; failed or interrupted output retains the existing pending marker. A core JSON exit, nested gate, or caller-crafted result cannot settle native delivery. Native consumption remains a separate observed contract.

The official [Codex hooks](https://learn.chatgpt.com/docs/hooks), [Copilot hooks](https://docs.github.com/en/copilot/reference/hooks-reference), and [Gemini hooks](https://geminicli.com/docs/hooks/reference/) contracts were rechecked on 2026-10-06. The Gemini stable request has role/content message pairs and supports `hookSpecificOutput.llm_request`. Unknown/advisory paths remain explicit support gaps. Run `python3 scripts/test-agent-brain-adapters.py` for public copied/provider envelope, lifecycle, source join and recovery proofs; fake translation does not certify native consumption.
