# Learn

The registered foreground agent runs learn for one joined obligation when the integration classifies the objective ready to complete. Clarification turns remain the same task; awaiting_user does not finish the work session. Automatic callbacks deliver this procedure and an ignored invocation file. Unconfigured providers are disabled. Current registration fixtures are confined to disposable test repositories and certify no native provider path.

1. Run `agent-brain learn start --invocation-file PATH --json` with the integration-issued file. In a source checkout, use `python3 skills/agent-brain/scripts/agent-brain.py` in place of `agent-brain`. Read the complete work package, its assigned scope, current input/guidance revisions, and the delivered guidance in order. Start supplies work and never completes semantic learning.
2. Review the assigned scope against current controlling sources. For a scoped no-change, submit UTF-8 JSON matching [review-v1](../schemas/review-v1.schema.json): `schema_version: 1`, `outcome: no_change`, and `review` with `scope`, ordered `guidance` entries containing `id`, `content_revision`, and `input_revision`, attributable `sources` containing local `path`, actual SHA-256 `revision`, and a short verification `note`, plus an overall review `note`. The [review example](../examples/review-v1.json) has illustrative hashes that must be replaced with actual current revisions. Use proportional evidence; the note explains what was reviewed and why no correction is needed.
3. Run `agent-brain learn prepare --invocation-file PATH --input REVIEW.json --json`. `--input -` uses stdin with the same validator. The runtime validates reviewed scope/source identities and current delivered revisions, runs configured checks in foreground, and records actual receipts. Prepare remains incomplete. A passed flag or invented receipt ID is invalid input. Change publication remains unavailable in this milestone.
4. Run `agent-brain learn complete --invocation-file PATH --input REVIEW.json --json` with the same prepared review. Completion repeats configured checks, rechecks actual input revisions and ownership, and requires all assigned child work settled. Only then can the result be `operation_status: ok`, `stage_outcome: no_change`, and `work_session_status: completed`. A child's scoped result settles its own assignment while the parent retains aggregate learning.

Invalid/expired/revoked/stale authority fails before semantic input is read. Handles expire after 30 minutes by default, use the actual local clock, and renew only at eligible integration events or checked operations. Relevant input or context-generation changes require restored guidance and a fresh review. Duplicate callbacks join the same obligation and preserve attempt limits; stage-generated callbacks do not recurse. Checks and retries are bounded, including at most one semantic repair. Interruption retains pending work. Pause/cancel revokes authority and automatic resume does not restart that objective. Use [the lifecycle protocol](lifecycle.md) for recovery and diagnostic distinctions.

Human-readable start also prints the full work package. Broken output invalidates delivery and mutation authority; a successfully flushed common-protocol response still does not prove native provider consumption or semantic quality. No model, daemon, or maintenance child is launched by the CLI.
