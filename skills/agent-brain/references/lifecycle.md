# Lifecycle protocol

For optional source ingestion, use the [configuration example](../examples/source-ingestion-v1.json) and [schema](../schemas/source-ingestion-v1.schema.json). Replace illustrative engine/bridge hashes with reviewed installed bytes. The standalone canonical/generated engine owns reconciliation and read-only snapshots; agent-brain bundles no scanner copy. Configured consumers first retain a valid existing version-1 manifest. Missing/damaged expected manifests are unavailable, never empty queues. Every linked raw/summary/manifest/skill component is rejected before effects.

Fixture bridge events may run the canonical engine in foreground. The [native adapter candidates](native-adapters.md) issue bound foreground continuations before source scanner work, trusted checks or semantic attempt claims. Their four-second cumulative callback watchdog keeps the canonical ten-second manifest-lock wait and scans/checks in foreground. Generated legacy gates join ordinary native payloads through the pinned `--native-gate` bridge and configured selector; protocol fixtures retain their explicit normalized `agent_brain_event`. A nested legacy gate never grants fresh delivery authority because its outer output flush is unavailable. Without activated configuration gates preserve the focused legacy workflow and global installation behavior.

Unresolved managed source work survives task identity changes. A dependent new objective cannot accept preserved unjournaled owned artifacts or silently discard a prior active source obligation. Restore that registered foreground obligation first; independent known scope may proceed without affected guidance. Pause/cancel keeps the old objective stopped, while a later objective may learn current sources from intact bases without restarting it. Successful checked current source evidence can satisfy shared source prerequisites across those objectives. Read-only external policy-source changes restore current context and remain separate from automatic source semantic writes; owned policy bases remain protected.

The internal `scripts/integration-bridge.py` reads one versioned normalized [event](../schemas/integration-event-v1.schema.json) as UTF-8/strict JSON on stdin, independent of the ambient encoding. It rejects invalid UTF-8, duplicate keys, non-finite numbers, and malformed types. It is the configured adapter boundary, separate from the six human commands. [The example](../examples/integration-event-v1.json) illustrates shape only: its paths, configuration hash, and identity must match a disposable fixture before it can run. Native events require the validated copied adapter or an issued foreground record, never a directly submitted normalized event. Installed provider builds, consumption, foreground route admission, Windows behavior and native timeout behavior remain unverified. Environment variables and caller identity flags do not issue authority.

An enabled registration pins the core, adapter, schema, lowercase canonical certification UUID, supported event set, and effective configuration SHA-256. Noncanonical certification identities are rejected before creating state; support/event identities must match exactly. A protocol fixture's support record must bind the actual temporary Git worktree; it is never native certification. Runtime verifies Git's real worktree root and common repository root. Canonical worktree, work-session, task, agent, attempt, and obligation UUIDs come from local registration, while provider IDs map to those identities. A provider task ID identifies one objective across clarification turns, rather than each turn creating a new task.

Startup/task events deliver complete startup/reference closure and scoped recall. Scope expansion merges assigned child scope and aggregate parent scope, invalidating older dependent results. Resume and context_lost events restore current content. A prior receipt does not restore lost context. Bridge receipt availability remains pending until output flush succeeds; known failed/partial output revokes authority and retains incomplete obligations. This common-protocol boundary does not certify that a native host consumes output.

At checkpoint/child_stop, classify active, awaiting_user, or ready_to_complete. Missing classification requests a compact checkpoint. One ready parent objective joins one learn obligation; stage callbacks with a registered attempt identity do not recursively create maintenance. Child scope_review assignments have their own registrations and scoped checks, and the parent waits for their settlement before aggregate learn. Children are optional; agent-brain creates none. Independent agents can retrieve within one worktree, but only one can own mutation. Separate worktrees have independent state and writable knowledge.

Ignored worktree-local state lives at `.agents/context/state/brain.sqlite3` by default, alongside an expected-binding sentinel and opaque finite invocation files. Missing/corrupt expected state is unavailable/incomplete, with pending work unknown, and is preserved rather than initialized as an empty queue. Status/doctor read state without creating it. Their output includes safe identities, generations, pending outcomes, and runtime receipts; it contains no invocation handles or handle-file paths.

SQLite mutation connections request DELETE journal, synchronous EXTRA, foreign keys before transactions, and fullfsync on macOS. Responses report observed connection settings and identify read-only access; filesystem/VFS/power-loss durability remains unverified. Transactions cover deterministic coordination only. Foreground semantic review and configured checks run outside them. Contention uses a cumulative two-second maximum with monotonic remaining budget and 250 ms/750 ms delays. Stage attempts have a shared three-total-attempt cap, at most one semantic repair, and any tighter provider cap. Duplicate callbacks never reset them.

A different live owner retains its lease. Expired ownership can be reclaimed only by eligible startup/task/resume/recover/context-restoration events; a checkpoint timestamp cannot authorize renewal. Old generations cannot complete or publish. Default expiry is 30 minutes. No idle heartbeat renews it. Checked operations renew valid authority; explicit pause/cancel revokes it without restarting the objective. Interruption of a CLI attempt is distinct from cancelling the task.

Check configuration includes the built-in guidance and review_sources checks plus explicitly trusted checker IDs and argument lists. No shell interpolation occurs. Long checks are bounded and run in foreground CLI operations or eligible deterministic publication recovery. Runtime receipts bind actual exit/timeout results to current inputs, effective configuration, owner generation, and attempt. Empty diffs, delivery, assertions, and process exits alone establish no completed stage. Optional source ingestion uses the configured canonical engine; [setup](setup.md) separates software installation from reviewed certified activation.

Learn supports prepare/publish/complete for a foreground-authored exact change/evidence proposal, plus checked no-change. Portable inverse records default to `.agents/context/history` and can use another validated `history_dir`; ignored state retains pending publication/output indications. Publication and eligible recovery share one OS-owned exclusive file lock with the operation's bounded contention allowance. Short SQLite claims revalidate generations around effects; no SQLite transaction spans semantic review or external checks. Managed recall exposes affected pending gaps while unrelated coherent guidance remains available. Recovery compares actual raw UTF-8 bytes with exact recorded before/after versions, retains unexpected edits, and respects pause/cancel. Completion, including recovered completion, retains a durable unfinished-output indication until flushed delivery settles. If reconciliation is unavailable, status remains unavailable/incomplete and the next eligible event restores context. No unmanaged all-files-at-once visibility or power-loss durability is established.

Offline protocol fixtures may execute trusted checks at an eligible recovery event. Native callbacks defer with `RECOVERY_FOREGROUND_REQUIRED` before effects or attempt claims and issue `native-integration.py foreground --invocation-file FILE`. The private typed file binds one normalized event, exact registration, configuration and expiry. Duplicate expired tickets are reissued without changing semantic attempts or ownership. Foreground recovery settles the exact recovered prior identity before new context. Source callbacks compare recorded canonical snapshot hashes and inventories without launching a scanner; drift automatically issues foreground restoration. Offline public subprocess tests establish these local paths, not native callback latency, provider consumption or an automatically executable first-task route.

Routine [dream](dream.md) defaults to enabled and first-cycle-due. A completion checkpoint assigns one finite batch, then learn completion waits for that assigned obligation. Dream shares learn's finite ownership, generation, attempts, checks, exact publication, and output recovery engine. Cycle coverage and UTC cadence are visible separately from session completion. Portable unresolved Markdown candidates default to `.agents/context/candidates`; `candidate_dir` and `history_dir` are configurable and separate from ignored state. Only resolved, evidenced dispositions remove candidates from the active queue.

Disposable protocol and validated native `offline_fixture` registrations can place an explicitly offset ISO timestamp under the selected `state_dir/fixture-clock.json` as `{"utc":"2026-10-01T00:00:00Z"}`. This clock affects calendar cadence/retention only; actual wall and monotonic clocks still govern authority, expiry, attempts and contention. Exact registered support and configuration binding are required; certified native records cannot use the fixture clock. It cannot authorize a native path or change the host clock. Validation can pin operational references through `state_dir/validation-pins.json`, with schema version 1 and arrays `work_session_ids` and `cycle_ids`; malformed or unavailable reference records preserve cleanup inputs.
