# Lifecycle protocol

The internal `scripts/integration-bridge.py` reads one versioned normalized [event](../schemas/integration-event-v1.schema.json) as UTF-8/strict JSON on stdin, independent of the ambient encoding. It rejects invalid UTF-8, duplicate keys, non-finite numbers, and malformed types. It is the configured adapter boundary, separate from the six human commands. [The example](../examples/integration-event-v1.json) illustrates shape only: its paths, configuration hash, and identity must match a disposable fixture before it can run. Native providers remain unsupported in this milestone. Environment variables and caller identity flags do not issue authority.

An enabled registration pins the core, adapter, schema, lowercase canonical certification UUID, supported event set, and effective configuration SHA-256. Noncanonical certification identities are rejected before creating state; support/event identities must match exactly. A protocol fixture's support record must bind the actual temporary Git worktree; it is never native certification. Runtime verifies Git's real worktree root and common repository root. Canonical worktree, work-session, task, agent, attempt, and obligation UUIDs come from local registration, while provider IDs map to those identities. A provider task ID identifies one objective across clarification turns, rather than each turn creating a new task.

Startup/task events deliver complete startup/reference closure and scoped recall. Scope expansion merges assigned child scope and aggregate parent scope, invalidating older dependent results. Resume and context_lost events restore current content. A prior receipt does not restore lost context. Bridge receipt availability remains pending until output flush succeeds; known failed/partial output revokes authority and retains incomplete obligations. This common-protocol boundary does not certify that a native host consumes output.

At checkpoint/child_stop, classify active, awaiting_user, or ready_to_complete. Missing classification requests a compact checkpoint. One ready parent objective joins one learn obligation; stage callbacks with a registered attempt identity do not recursively create maintenance. Child scope_review assignments have their own registrations and scoped checks, and the parent waits for their settlement before aggregate learn. Children are optional; agent-brain creates none. Independent agents can retrieve within one worktree, but only one can own mutation. Separate worktrees have independent state and writable knowledge.

Ignored worktree-local state lives at `.agents/context/state/brain.sqlite3` by default, alongside an expected-binding sentinel and opaque finite invocation files. Missing/corrupt expected state is unavailable/incomplete, with pending work unknown, and is preserved rather than initialized as an empty queue. Status/doctor read state without creating it. Their output includes safe identities, generations, pending outcomes, and runtime receipts; it contains no invocation handles or handle-file paths.

SQLite mutation connections request DELETE journal, synchronous EXTRA, foreign keys before transactions, and fullfsync on macOS. Responses report observed connection settings and identify read-only access; filesystem/VFS/power-loss durability remains unverified. Transactions cover deterministic coordination only. Foreground semantic review and configured checks run outside them. Contention uses a cumulative two-second maximum with monotonic remaining budget and 250 ms/750 ms delays. Stage attempts have a shared three-total-attempt cap, at most one semantic repair, and any tighter provider cap. Duplicate callbacks never reset them.

A different live owner retains its lease. Expired ownership can be reclaimed only by eligible startup/task/resume/recover/context-restoration events; a checkpoint timestamp cannot authorize renewal. Old generations cannot complete or publish. Default expiry is 30 minutes. No idle heartbeat renews it. Checked operations renew valid authority; explicit pause/cancel revokes it without restarting the objective. Interruption of a CLI attempt is distinct from cancelling the task.

Check configuration includes the built-in guidance and review_sources checks plus explicitly trusted checker IDs and argument lists. No shell interpolation occurs. Long checks are bounded and run in foreground CLI operations, never bridge callbacks. Runtime receipts bind actual exit/timeout results to current inputs, effective configuration, owner generation, and attempt. Empty diffs, delivery, assertions, and process exits alone establish no completed stage. Source ingestion, publication, dream cycles, installation, and native adapters remain later milestones.
