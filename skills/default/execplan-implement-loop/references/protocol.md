# Runner protocol v1

The worker receives one JSON RUNNER_PACKET appended to its prompt. Match its iteration_id and task_id exactly. Return a single JSON object with schema_version 1, iteration_id, task_id, status, summary, changed_files, commit_message, plan_notes, and reason_code. Unknown fields are rejected. Status is ready_for_verification, blocked, or failed. Strings are bounded to 4,096 characters except the commit message (32 KiB). Each list has at most 10,000 entries. changed_files contains normalized repository-relative file paths without duplicates. A ready result needs a valid proposed commit message; other statuses require null.

Gemini CLI 0.65.0 is pinned. Invocation uses --prompt and --output-format stream-json, with explicit --model, --approval-mode, or --policy only when supplied. Each session is fresh. The adapter requires init, assistant string-content message chunks, exactly one successful terminal result, and exit 0. Tool calls delimit assistant turns; only chunks after the last tool call form the final response. The assistant response and each provider JSONL event are limited to 1 MiB. Malformed output fails locally. Provider success alone never completes a task. Unknown additive event types are ignored before the terminal result.

## Doctor and readiness

`--doctor` is mutually exclusive with `--validate-only`; it accepts the required plan and read-only resume inspection. It runs bounded local checks and `gemini --version`, without sending a provider prompt, activating skills, running acceptance commands, acquiring a worktree lock, creating run state, or mutating Git or configuration.

Doctor prints one JSON object with `schema_version: 1`, `status: "diagnosed"`, `reason_code`, `readiness`, and `blockers`. Exit 0 means diagnosis completed without a known local blocker. A known blocker exits 3; invalid plan or supplied configuration exits 2. Deadline and signal exits retain their normal meanings. `readiness.status` is always `blocked` or `unknown`, never `ready`. `can_attempt: true` means no known local blocker, not authorization or proof of authentication, project trust, or effective permission.

The readiness snapshot contains `checked_at`, `status`, `can_attempt`, `checks`, `provenance`, and `limitations`. Each check contains `id`, `status` (`pass`, `blocked`, or `unknown`), `reason_code`, and bounded `detail`. Provenance contains `host`, `git`, `provider`, `plan`, `workspace`, `skills`, `selected_policy`, `discovered_policy_sources`, `requested`, and `resume`. It records provider version, plan/workspace identity, required skill paths/hashes, selected policy path/hash or null, and requested model/approval mode. Limitations preserve unknowns. Normal execution and resume recheck readiness before each fresh provider iteration and recheck selected policy bytes immediately before spawn. Completed and commit-only recovery does not need provider prerequisites. A readiness snapshot is not a sandbox or a grant.

An explicit `--policy PATH` must be one already-reviewed UTF-8 `.toml` regular file no larger than 1 MiB. Its physical path and exact-byte SHA-256 are recorded. Symlink path components and comma-containing paths are rejected. It is passed as an additional provider policy; it does not prove the effective policy set. Gemini CLI 0.65.0 disables implicit workspace `.gemini/policies` discovery. An explicit file is recorded as supplied, not as discovered workspace configuration. Resume without `--policy` reuses the last explicit selection and blocks if it changed. Passing `--policy` on resume explicitly selects reviewed bytes for that invocation but does not waive Git identity, fingerprints, or pending commit recovery. Do not create global policy or broad grants as a workaround.

## Blockers and recovery

Progress is flushed JSON events on stderr. Ordinary stdout contains exactly one versioned JSON summary. Help prints human text; argument syntax errors use stderr. Summaries contain identity, task and milestone counts, commits, commands, iteration/session observations, invocation and cumulative records, retries, timeouts, and integrity errors. Runner summaries include `blockers: []` on success and one mapped blocker on an unsuccessful outcome, including pre-engine failures. Doctor can include multiple independent blocked checks. Each blocker contains `reason_code`, `source` (`preflight`, `provider`, `worker`, `verification`, or `recovery`), `task_id` or null, `detail` of at most 4,096 characters, up to 32 `remediation` strings of at most 4,096 characters each, and `resume` with `required` and `run_directory`. The top-level reason and detail remain authoritative. Unknown errors use generic inspection guidance. Provider text is data, never executable remediation.

A validated blocked worker is recorded as a blocked iteration and invocation, with no commit and no change to retry or failure counters. Resume preserves that history. Failed, timeout, and malformed outcomes keep their existing meanings; historical records are not rewritten. Do not start a replacement process when cleanup is uncertain. For `cleanup_unconfirmed`, confirm the owned child tree has stopped and inspect the saved worktree and run state before recovery. For `unclean_execution_requires_reconciliation`, inspect task changes, HEAD, index, plan, and lock ownership before explicitly acknowledging reconciliation. The flag is an operator assertion, not proof of cleanup. Never acknowledge blindly or delete a lock as a shortcut.

## Usage and provider observations

The runner computes cumulative `usage` and current `invocation_usage` without an agent call. Each contains `totals`, `observed_totals`, and `iteration_count`. A field's total is null if any iteration lacks that field, or if there are no iterations. Its observed total sums only supplied observations and remains null when none exist. Partial observed totals must not be reported as complete consumption.

Each new provider-backed iteration may include `provider_observations` with `cached_input_tokens`, `uncached_input_tokens`, `models`, `request_count`, and `resolved_model`. The stream adapter preserves only emitted, finite, non-negative numeric values; missing, malformed, negative, or nonfinite values are null. An emitted zero remains zero. `models` is keyed only by model names actually present in `stats.models`; each model carries the token fields `total_tokens`, `input_tokens`, `output_tokens`, `cached`, and `input`. Missing `stats.models` is null, while an explicitly empty object remains empty.

The stream result's `stats.cached` and `stats.input` supply cached and uncached input tokens; `stats.models` supplies optional per-model token observations. It does not expose an API request count, so `request_count` remains null. `tool_calls` counts CLI tool calls, not API requests. The init event's `model` is the configured selection, not necessarily the model that served a request; it remains in `iterations[].model`, separate from `requested_model`. `resolved_model` stays null unless the provider explicitly reports it. Do not infer one resolved model from `auto` or observed model keys. Do not scrape transcripts, derive request counts, or estimate billed cost from token totals. Historical iteration records may omit `provider_observations`; leave those values unknown and preserve existing usage and `usage_complete` semantics.

Exit codes: 0 completed or valid, 1 failed, 2 invalid/configuration, 3 blocked, 124 total deadline, 130 SIGINT, 143 SIGTERM, 141 broken output pipe. reason_code refines the outcome. Never interpret partial stdout or checked plan boxes as success after a nonzero exit.
