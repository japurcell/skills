**Overdue, still running:** Treat the limit as a warning threshold. Send a non-interrupting warning; request status, completed work, blockers, and updated ETA. Keep the worker running. Lateness alone does not justify interruption, cancellation, or replacement.

**Terminated by runtime timeout:** Before replacement, retain the error, submitted settings, runtime limit, partial work, findings, unresolved items, and artifacts. Diagnose instructions, context, dependencies, permissions, tools, and environment. Revise the assignment or limit as needed.

Allow at most **one replacement** unless the user authorizes more retries. Reroute if requirements or demonstrated capability needs changed. Before replacement, satisfy dependencies, validate the route, and ensure runtime monitoring.

**Neither event alone requires a stronger model.** Escalation needs evidence of greater capability requirements, not elapsed time. Verify partial results against acceptance criteria before dependent work relies on them.
