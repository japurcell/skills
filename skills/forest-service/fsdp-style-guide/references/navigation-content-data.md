# Navigation, Content, and Data Display

Use for navigation, search, tabs, accordions, cards, collections, tables, charts, tags, and badges.

## Navigation

- Keep navigation consistent across the product.
- Use clear, short link labels.
- Show current location with an active state.
- Side navigation works best for 1–3 hierarchy levels within a section.
- Avoid stacking horizontal nav, side nav, tabs, and menus unless each is clearly needed.
- Menus must open from explicit triggers, support keyboard navigation, and keep separators non-interactive.

## Search

- Make search easy to find and simple by default.
- Keep the user’s search terms visible in results.
- Use a full search box on home or landing pages where search is a primary path.
- Do not default to advanced search when simple search handles most needs.
- Give search fields enough width for common queries.

## Tabs and accordions

- Tabs need short labels, clear active/inactive states, and one topic per tab.
- Avoid tabs when content is too short, too long, too complex, or heavy with components.
- Use accordions only for a few collapsed sections.
- Do not hide content in accordions when most users need to read it.
- Accordion headers should be full-width click targets and not too close to inner controls.

## Cards and collections

- Use cards for grouped summary content, not decoration or fake table rows.
- Cards should provide clear title, concise summary, and useful metadata.
- Avoid repeating the same image or redundant content across a card set.
- Collections should stay compact, usually 6 items or fewer, with a path to a fuller archive.
- Avoid generic links like “Read more”; headings should carry navigation.
- Collection headings should be clear, concise, and unique.
- Use thumbnail images consistently within a collection.

## Tags and badges

- Tags should mark something new, important, filterable, or status-like.
- Do not mix interactive and non-interactive tags in one visual pattern.
- Non-interactive tags should not show hover, focus, or active states.
- Badges should be small, adjacent to what they annotate, and limited to short numbers or status text.
- Standard tag colors may use USFS green `#005838`, brown `#6a5147`, gold `#ffd51d`, or light green `#9bb672`.

## Tables

- Use tables for structured comparison or data lookup.
- For FSDP web tables, place tables inside cards where that is the established product pattern.
- Use accessible table markup with clear header-to-cell relationships.
- Use sortable and keyboard-reachable headers when sorting is available.
- Put pagination at bottom right when pagination is used.
- Alternating row colors may improve scanning; maintain contrast.
- Scrollable responsive tables must remain keyboard accessible.

## Charts

- Prefer familiar chart types such as bar and line charts.
- Keep each chart focused on one main idea or a few related concepts.
- Do not rely on color alone; add labels, texture, dash patterns, point shapes, or other cues.
- If many colors are required, the chart may be overloaded.
- Provide a plain-language chart summary.
- Provide table or text equivalents when practical.
- Link to source data where appropriate.
