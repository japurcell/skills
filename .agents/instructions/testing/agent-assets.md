# Selected Installer Tests

Keep tests at the accepted public subprocess/file-effects seam. Use disposable committed Git sources, targets, homes and state. Run `rtk proxy python3 scripts/test-agent-assets.py` for the complete applicable installer suite, or select the affected group below. Preserve the existing assertions when adapting fixtures.

- `python3 scripts/test-agent-assets.py --group clone` audits committed clones with autocrlf true/false before repairs, checks literal LF/CRLF/binary bytes and hashes, executes all three relocated startup shell registrations, and proves committed damage fails without writes. `--export-clone-bundle PATH` creates the POSIX-installed Git bundle; consumers set `AGENT_ASSETS_CLONE_BUNDLE` to audit the same immutable payload across operating systems. `--group windows-boundary` requires actual Windows and checks refusal/recovery-evidence preservation only. The platform workflow keeps Windows full mutation acceptance explicitly unmet, separate from read-only clone success. Native client loading is a separate gate. Detached hook maintenance remains enabled; clone fixture cleanup retries briefly for those processes to finish closing SQLite files.

- Selected team installation: `python3 scripts/test-agent-assets.py --group team-install` exercises the public command against disposable committed source/target Git repositories, including spaces, provenance, exact bytes/modes, independent copies, unchanged indexes, no-write repetition, URL/ref safety, linked/occupied targets, record ambiguity, and checkout policy conflicts. `--group selection` covers literal transitive/shared closure, unchanged target fingerprints on refusal, schema/cycles/case-fold collisions, missing chains, maintained bundles, reference/license preservation, six documented client paths, skills-only/pending-renderer restrictions, and explicit repo-local source roots including unlisted filter preflight. `--group lifecycle` covers remote branch preview/update, pins, exact restore/source/rendered integrity, retained origin baselines, edited/pruned files and attributes, offline drift/schema/path checks, linked-worktree mutex exclusion, and real process interruption/recovery. Forged in-root ownership and origin mismatches must leave complete fingerprints unchanged. The interruption case waits for an actual changed payload and journal before killing the process; it asserts interruption occurred and tests external edit/tampered journal refusal before recovery. POSIX cases suspend actual 32 MiB staged writes and substitute linked/regular parents or the final file. They prove unrelated bytes/modes survive, success is refused, pending state remains, and recovery rejects a different directory even with matching baseline bytes. Native Windows mutation tests remain an unmet acceptance gate while writes fail closed. The no-group command runs all implemented groups and is registered in the aggregate runner. `--group providers` covers native agent conversion, installed hook execution after clone/relocation/nested launch, external optional capture state, semantic config preservation/edit/prune/restore, hard-link isolation, invalid native configuration, authenticated ownership, acquired-generator nonexecution, freshness, and updates with old immutable generation lineage. `--group scopes` covers exact private excludes, linked worktrees, whole-operation tracked refusals, authenticated borrowing/promotion/shared pruning, personal exact adoption and lifecycle, external Codex authority, wrappers and tampered-record refusal, and optional RTK checks at public subprocess seams. Native client/OS proof remains separate.

- Scope privacy cases exercise later exact-rule negation, higher-precedence `.gitignore`, force-added private files, unchanged-target refusal and offline drift without index refresh. Codex agent sharing cases cover team-to-local borrowing and explicit local-to-team promotion while preserving payload bytes, inode, and modification time.

For installed security hooks, pair a harmless allowed command with a denied control. A missing policy helper also denies execution, so denial alone does not prove successful packaging. Keep repository and personal installation coverage. See [security tests](hooks-security.md) for the provider-envelope suites.
