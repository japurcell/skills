# Shell Scripts Conventions

- Follow existing shebang style for shell helper scripts: `#!/usr/bin/env bash` or `#!/usr/bin/env python3`.
- Keep scripts directly executable and simple.
- `scripts/test-all.py` owns the explicit registry of maintained test-suite commands. Update it when adding, moving, or removing a suite; exclude `scripts/test-common.sh`, archived tests, generated workspaces, and fixture trees. Keep the runner's CLI regression suite in `scripts/test_test_all.py` registered without recursively invoking the real aggregate run.
- Keep the focused Codex Tool Guardian suite in `scripts/test-codex-hooks-tool-guard.sh` registered beside the Copilot and Gemini suites; `scripts/test-security-banners.py` supplies their shared public-envelope cases.
- `scripts/generate-hooks.py` owns only the explicit targets in `hooks/manifest.py`. Use `--write` to refresh generated provider-local outputs and `--check` as its no-write freshness gate; both installers run `--check` before destination mutation, but never make installers generate repository sources or edit owned outputs by hand. Freshness always compares content and generated ownership; it checks executable mode only on non-Windows hosts, where POSIX modes are meaningful.
- Both installers run `scripts/configure-rtk.py --check` before installed-file writes, then apply its stable RTK 0.50.0 or newer configuration after generated-hook freshness passes. It changes only `hooks.suppress_hook_warning`, backs up an existing changed TOML, and leaves ambiguous or modified legacy files for manual review. Use `--home` with a disposable directory for verification; never use a real home for tests.
- Shell-focused helper scripts should stay in the repo-root `scripts/` tree and use `scripts/common.sh` for shared repo-root helpers that require `REPO_ROOT`.
- `scripts/benchmark-high-rate-hooks.py` is the direct macOS hook-performance runner. Keep its Git fixtures, home, logs, and RTK config in disposable paths; invoke provider JSON entrypoints without installing hooks or launching a provider CLI. Its whole-subprocess timings are not provider delivery timings.
- Use stdout for primary or machine-readable output and stderr for status, warnings, progress, and errors so piping and redirection stay predictable.
- Prefer standard-library solutions unless an existing script already implies dependency use.
- `scripts/agent-assets.py` is the selected team installer; its internal package is `scripts/agent_assets/` and its committed source manifest is `distribution/catalog.json`. Keep tests at the subprocess/file-effects seam. Add catalog entries only with explicit regular-file paths and text/line-ending or binary policy; preserve supporting notices and references. Source acquisition must never execute catalog code, hooks, clients, or Git clean filters, and must leave both source and target indexes untouched.
- Team skills use documented native roots with `.agent-assets/selection.json` and `.agent-assets/lock.json`. Shared clients materialize `.agents/skills` once; Claude uses `.claude/skills`. Refuse unowned destinations and incompatible checkout rules before writes. Check unsupported transforms on previously owned paths and in the proposed effective policy; ownership permits updating declared text/eol rules, not bypassing filter/encoding/ident/crlf checks. Own only exact new path rules in the marked `.gitattributes` block; preserve unrelated text and borrow compatible policy without claiming it. Repeat installation of the same source/selection must make no file writes. Local/user scopes remain unimplemented. Explicit install selection changes and saved-selection update/restore share whole-operation planning; preserve unchanged-upstream local edits with their baseline digest and origin commit. Edited updates/removals or owned attribute changes must stop before target writes. Unknown local ownership records fail closed until their scope schema is supported.
- Lifecycle writes use `transaction.py` with a per-worktree Git-resolved mutex and one pending journal. Before any replacement/pruning, authenticate the exact recorded payload set and baseline metadata against the immutable source commit, including earlier retained origins; native-root membership alone is not ownership. Recheck observed bytes/modes under the mutex and before each replacement/removal. POSIX mutations pin no-follow parent descriptors, verify the original entry and inode immediately before replacement, and confirm desired bytes/mode and visible parent identity afterward. Persist directory identities in the journal before payload writes; recovery refuses substituted parents even when their bytes match the baseline. Native Windows mutations fail closed until verified parent-handle support exists; preview/status remain available. Validate records, source identity, digests, and journal preimages before recovery. Recovery removes only exact recorded staging files and empty created directories, refuses external edits, and deletes the completed journal. Keep no rollback history.
- `status --check` is an offline read-only audit: no source acquisition, Git status/filter execution, repairs, journal recovery, or installation writes. Selection disagreement (including source kind/location/policy) and managed payload/checkout-policy drift exit `1` with `ASSET_DRIFT`; invalid/unsupported records and pending operations exit `2`. Informational status can report drift with exit `0`. Restore verifies both the recorded source digest and rendered baselines at its exact commit, without following a branch.
- The selected catalog resolves explicit required dependencies and curated bundles before rendering. Preserve mandatory conditional workflow calls, references, and notices; optional detail links and descriptive mentions do not create required edges. Missing dependencies must remain unavailable with full chains rather than silently disappearing. Report source availability separately from pending native agent/hook renderer capability. Claude Code, Cursor, and OpenCode initially support skills only.
- Skill `source_root` defaults to `skills/<asset-name>` and permits only that path or `.agents/skills/<asset-name>` when explicitly declared for a maintained prerequisite. This does not authorize wholesale distribution or modification of internal context. Inspect all tracked paths under the actual declared root for transforms before running Git status, not only listed source files. Catalog payloads exclude archives, workspaces, eval output, caches, and undeclared runtime files.
- `scripts/lint-okf.py` must load PyYAML 6.0.3 from `scripts/vendor/yaml/`, verify both the version and resolved import path, and fail with `OKF900` instead of falling back to a site package. Keep the linter read-only and offline at runtime.
- Register cleanup functions by name (for example, `trap cleanup EXIT`) instead of interpolating temporary paths into trap command strings. Quote the exact `mktemp`-created path and pass `--` to recursive cleanup commands.
- Treat user-facing helper scripts as CLIs: reserve `-h`/`--help` for help, prefer descriptive long flags over multiple positional argument types, and keep interactive prompts optional rather than mandatory.
- `scripts/install-codex-agents.py --source-dir PATH --destination-dir PATH` is the strict public converter for top-level canonical agent Markdown. It must run before provider copy operations in both installers and may remove only manifest-owned Codex TOML outputs.
- Both installers must preflight `scripts/install-provider-hooks.py --check` for Copilot and Gemini before any destination mutation. Keep their hook configuration files out of bulk copy and mode-copy operations; merge maintained entries with existing user settings and unowned handlers, including retired registrations left for manual cleanup. Malformed or ambiguous JSON and linked configuration parent directories must stop the install before copying assets. Never chmod an existing config through a hard link; atomically replace it with owner-only bytes when its link count or mode requires repair.
- Gate decorative terminal behavior on TTY detection; if a script introduces color or spinners, it should also respect `TERM=dumb`, `NO_COLOR`, and a direct opt-out flag.
- **Agent-restricted scripts:** Never run human-only orchestration scripts (such as `import-skill-repos.sh` or `pull-skill-repos.sh`). Agents must strictly run only targeted verification and test scripts (such as `test-*.sh`).
- PowerShell-specific guidance lives in `.agents/instructions/powershell.md`; shell-focused validation lives in `.agents/memory/testing/scripts.md`.
- If the change also affects repo-local hook behavior, read `.agents/instructions/hooks.md` and the matching hook validation docs instead of treating hooks as generic shell scripts.
