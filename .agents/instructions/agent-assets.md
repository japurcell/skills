# Selected Asset Installer

Apply [shared script conventions](scripts.md). Use [installer tests](testing/agent-assets.md) for validation; public examples and the support matrix live in [usage](../../docs/agent-asset-installer/usage.md).

## Scope and authority

- Before changing asset distribution or installer scope, consult the [distribution map](../../docs/agent-asset-distribution/map.md), [approved contract](../../docs/agent-asset-distribution/tickets/choose-distribution-contract.md), [existing-distributor comparison](../../docs/agent-asset-distribution/existing-repos-review.md), [implementation ExecPlan](../../docs/agent-asset-installer/ExecPlan.md), and [feature handoff](../../docs/agent-asset-distribution/handoff.md). Follow the current resume gate and approved requirements. Research recommendations become amendments only through the live decision ticket; verify installed client behavior before advertising compatibility.
- Use the [installer task manifest](../../docs/agent-asset-installer/tasks.json) to select remaining closeout work, then verify its prerequisites against the live ExecPlan and handoff. Consult the [task verification log](../../docs/agent-asset-installer/progress.txt) for attributable completion reviews and their inspected-packet digests; a task flag or an author's approval assertion is not review evidence. Task readiness does not renew an expired implementation budget or authorize experiments, recovery or native client sessions.

## Installer invariants

- New owned checkout blocks also require an effective LF policy for `.gitattributes` itself. Record the narrow self-rule when needed, borrow compatible preexisting policy, and refuse conflicting transforms without changing unrelated text. Record the metadata requirement separately from rule ownership so strict checks validate borrowed rules too. Authentic older records remain valid and acquire the requirement during explicit update/restore. Never normalize arbitrary bytes during strict verification. Platform CI lives in `.github/workflows/agent-assets.yml`; distinguish clone/refusal checks from its explicitly unmet Windows mutation job and from live client acceptance in `docs/agent-asset-installer/client-validation.md`.
- Before native Codex acceptance, read [the isolated native probe](../../docs/agent-asset-installer/codex-native-probe.md). Establish actual filesystem/network confinement and normal trust persistence without personal-state access; a disposable profile alone is insufficient. Project trust and hook-definition review are separate gates. Do not fabricate either approval or substitute direct hook invocation for client delivery.
- Before Windows writer work, read [the current distribution contract](../../docs/agent-asset-distribution/tickets/choose-distribution-contract.md), then [the established-project comparison and metadata evidence](../../docs/agent-asset-installer/windows-established-practice.md). The current contract governs safety and release gates; historical adversarial experiments must not silently become new requirements or justify dropping Windows hooks. Preserve DACLs and known mandatory integrity labels with ordinary rights, or refuse known loss; do not require elevation or universal arbitrary audit-SACL preservation. Keep documented API guarantees separate from observations. Existing retained-preimage checks provide stronger historical authority than a descriptor and recomputable digest in the same journal; preserve useful working checks unless an explicitly scoped change is validated, but do not equate a rename wrapper with adversarial race/recovery proof.
- `scripts/agent-assets.py` is the selected team, private, and personal installer; its internal package is `scripts/agent_assets/` and its committed source manifest is `distribution/catalog.json`. Route user-facing scope and lifecycle questions to `docs/agent-asset-installer/usage.md`. Keep tests at the subprocess/file-effects seam. Add catalog entries only with explicit regular-file paths and text/line-ending or binary policy; preserve supporting notices and references. Source acquisition must never execute catalog code, hooks, clients, or Git clean filters, and must leave both source and target indexes untouched.
- Team skills use documented native roots with `.agent-assets/selection.json` and `.agent-assets/lock.json`. Shared clients materialize `.agents/skills` once; Claude uses `.claude/skills`. Refuse unowned destinations and incompatible checkout rules before writes. Check unsupported transforms on previously owned paths and in the proposed effective policy; ownership permits updating declared text/eol rules, not bypassing filter/encoding/ident/crlf checks. Own only exact new path rules in the marked `.gitattributes` block; preserve unrelated text and borrow compatible policy without claiming it. Repeat installation of the same source/selection must make no file writes. Explicit install selection changes and saved-selection update/restore share whole-operation planning; preserve unchanged-upstream local edits with their baseline digest and origin commit. Edited updates/removals or owned attribute changes must stop before target writes. Authenticate the other repository scope before sharing or pruning paths; borrowed metadata never substitutes for immutable source authentication.
- `scopes.py` owns private/personal layout policy and exact Git-resolved excludes; `personal.py` renders personal native paths and immutable registration-template inputs; `prerequisites.py` checks only supported declared runtimes. Local mode never writes `.gitattributes` and fails with `ASSET_LOCAL_TRACKED_CONFLICT` before payload writes when tracked native paths would change. Copilot CLI local settings do not imply VS Code support; use the common native path with this conflict rule, and never invent Gemini project `settings.local.json` or a system override.
- Team/local shared items require identical authenticated bytes, modes, and config entries. Local records mark borrowing. Codex agent collision preflight accepts companion paths only after immutable ownership authentication. Explicit team selection updates local records and exact excludes in one transaction; refuse promotion when another worktree has private records sharing common excludes. A team prune preserves remaining local requirements, adding an exact exclude only for untracked released items. Never exclude tracked team files. Preserve arbitrary existing exclude text and leave obsolete exact lines in place because another worktree may need them. Check effective Git ignore precedence before writes and again under the mutex; strict status flags exposed or tracked nonborrowed private paths without fetching sources or refreshing the index.
- Personal `--adopt` accepts only exact selected immutable file bytes/modes and native registration groups, refusing links, hard links, edits, duplicate/malformed config, unknown revisions, or basename-only authority. Legacy name manifests and backups remain untouched. Personal configuration is owner-only; unrelated settings/handlers are preserved. Templates are byte inputs included in the source digest, never acquired executable code.
- `--codex-home` explicitly authorizes a personal agent destination outside `--home`; persist it and require the same authority for every lifecycle call. Honor inherited `CODEX_HOME` only when operating on the actual process home, so an explicit disposable `--home` cannot accidentally write into real personal state. Journal external agent destinations with pinned parent identity and source-backed ownership; reject record-only override changes.
- Bash/PowerShell explicit arguments forward to the Python CLI. No-argument legacy copying remains until either personal record exists, after which saved-selection update must handle the request, including invalid records. Never let fallback copying bypass ownership checks. Selected skill-only installs need Git/Python, not RTK or client authentication. Declared RTK requirements check stable 0.50.0 and selected Copilot/Gemini processor help without changing account-wide settings; the current catalog contains no selectable RTK hook. Legacy personal RTK setup retains its existing checks and configuration workflow.
- Native hook configuration uses `configuration.py` for exact-entry ownership, preserving unrelated JSON settings and handlers. Compare canonical JSON so boolean and floating values cannot masquerade as owned integer metadata. Authenticate configuration baselines against immutable source before update/prune and compare unowned before/after journal projections. Missing configs can be restored; unchanged-upstream managed edits are retained and reported as drift, while incompatible changes and pruning refuse edited entries or modes. Atomically replace hard-linked native configs without chmod through external links. Refuse malformed/duplicate JSON, linked paths, invalid Codex TOML, and competing inline Codex hooks before writes.
- `hook_rendering.py` verifies desired generated hooks using only trusted command-checkout renderer semantics. Read acquired canonical Python as bytes; never execute acquired generators, even for freshness checks. Unsupported generation inputs require a compatible command checkout. Old ownership/origin authentication hashes immutable lineage and output bytes without demanding old canonical source equal newer trusted source. Desired installation/update/restore still requires compatibility and freshness.
- Lifecycle writes use `transaction.py` with a per-worktree Git-resolved mutex and one pending journal. Before any replacement/pruning, authenticate the exact recorded payload set and baseline metadata against the immutable source commit, including earlier retained origins; native-root membership alone is not ownership. Recheck observed bytes/modes under the mutex and before each replacement/removal. POSIX mutations pin no-follow parent descriptors, verify the original entry and inode immediately before replacement, and confirm desired bytes/mode and visible parent identity afterward. Persist directory identities in the journal before payload writes; recovery refuses substituted parents even when their bytes match the baseline. Native Windows mutations fail closed until verified parent-handle support exists; preview/status remain available. Validate records, source identity, digests, and journal preimages before recovery. Recovery removes only exact recorded staging files and empty created directories, refuses external edits, and deletes the completed journal. Keep no rollback history.
- `status --check` is an offline read-only audit: no source acquisition, Git status/filter execution, repairs, journal recovery, or installation writes. Selection disagreement (including source kind/location/policy) and managed payload/checkout-policy drift exit `1` with `ASSET_DRIFT`; invalid/unsupported records and pending operations exit `2`. Informational status can report drift with exit `0`. Restore verifies both the recorded source digest and rendered baselines at its exact commit, without following a branch.
- The selected catalog resolves explicit required dependencies and curated bundles before rendering. Preserve mandatory conditional workflow calls, references, and notices; optional detail links and descriptive mentions do not create required edges. Missing dependencies must remain unavailable with full chains rather than silently disappearing. Report source availability separately from supported native rendering. Codex, Copilot CLI/VS Code, and Gemini have repository agent/hook adapters; native trust and live delivery remain separate acceptance gates. Claude Code, Cursor, and OpenCode initially support skills only.
- Skill `source_root` defaults to `skills/<asset-name>` and permits only that path or `.agents/skills/<asset-name>` when explicitly declared for a maintained prerequisite. This does not authorize wholesale distribution or modification of internal context. Inspect all tracked paths under the actual declared root for transforms before running Git status, not only listed source files. Catalog payloads exclude archives, workspaces, eval output, caches, and undeclared runtime files.
- `scripts/canonical_agents.py` supplies side-effect-free strict parsing and TOML serialization shared by selected installation and the legacy converter. Never call a mutating personal installer to render repository agents. Preflight unmanaged Codex TOML and case-folded native name/path collisions, and repeat that check under the write mutex. Explicit installer test fixtures must include the shared converter module.

- Journal only present or changing companion-scope records; authenticate both scopes when companion records participate. Do not invent absent companions as recovery placeholders.
- Offline verification trusts the committed authority records. Do not present it as cryptographic authentication against a coordinated rewrite of those records and payloads.
