# Writing subagent dispatch instructions

- Activate the `subagent-model-router` skill once per session. Run `route.py` for each assignment, including worker reuse. Leave task classification, model eligibility and effort policy there. State any stricter requirement in the caller. For example, the router treats a requested tier as a minimum, while `fan-out` requires an exact Fast-tier route. [Router](../../skills/default/subagent-model-router/SKILL.md) · [Fan-out](../../skills/default/fan-out/SKILL.md)
- Keep short phrases whose removal changes a dispatch decision. In `fan-out`, “even unlisted” prompted an attempt with an eligible model omitted from the host’s advisory list. “Explain local fallback” kept the parent responsible for finishing the work when dispatch was unavailable. Choose the fallback that fits the caller. [Wording trials](../../skills/default/fan-out/evals/README.md)
- Verify dispatch in the session trace. Compare the router result with the spawn arguments and the actual child model. For parallel work, check that ready workers launch into available slots before the first wait. A correct answer can also come from the parent doing the work locally. [Evaluation procedure](../../skills/default/fan-out/evals/README.md)
