# Portable brain hooks

The two generated scripts require Python 3.12 or newer and only its standard library. Copy either script alone from a provider tree; neither imports repository helpers. The scripts need no Git, Bash, jq, RTK, packages, or network access at runtime.

The `brain-install` bundle's two hook helpers are also generator-owned outputs declared in `hooks/manifest.py`. Edit `hooks/families/brain.py`, then regenerate provider and bundled copies together. `generate-hooks.py --check` covers both; do not maintain bundle-local helper forks. The generator CLI suite verifies bundled drift detection, read-only checks, repair, and byte parity with provider outputs.

`auto-index-brain.py --provider copilot|codex|gemini` maintains `brain/index.md`. `inject-brain.py` takes the same selector and reconciles the index before returning startup context. Both read the provider's JSON object on stdin. Use the provider matching the registration; do not infer it from payload field names.

## Inventory and context

Automation owns the root index. Put human prose in topic notes and curated subindexes. The root inventory lists Markdown notes in directories without a curated index, sorted by directory and path. When a subdirectory contains a regular `index.md`, it links that index and stops expanding that subtree. Curated indexes own navigation beneath that boundary, including archived plans. Exception: every Markdown file under `brain/codebase/` stays listed in the root inventory, even below nested curated indexes. It excludes the root index, symlinks, and Windows reparse points. It reads filenames, not note bodies. Every entry uses a standard Markdown link with the `.md` extension and a URL-encoded destination relative to the root index.

The validated absolute `cwd` selects the nearest ancestor vault, stopping at the nearest Git marker. A missing vault is a quiet no-op. The script location never selects the vault. Project launchers first select the nearest ancestor Git marker and use only that root's exact script. A competing nested script cannot override it. Only when no ancestor Git marker exists do they search ancestors for the script. They support worktree marker files and do not execute Git. All repository launch variants use `-I -S -B` before `-c`, so project modules cannot shadow standard-library imports.

A persistent `.brain-index.lock` uses a kernel lock released when the process exits. Ignore it in version control. Unchanged inventories keep the index timestamp. Writes use a flushed same-directory temporary file and atomic replacement. Errors preserve the previous index and return nonblocking JSON with a bounded stderr diagnostic. POSIX traversal, lock/index access, temporary creation, and replacement use pinned directory descriptors and no-follow opens. Windows pins the vault and its ancestors with directory handles allowing read/write sharing for entry updates, but denying delete sharing to prevent directory replacement. Sharing flags do not prevent attribute-only reparse edits. Enumeration therefore reads names, types, and full file identities directly from the validated directory handle; queued children must match volume and file identity. File opens and creation use the vault handle, including its first lock when empty. A reparse check after creation rejects an earlier in-place conversion before path-based operations; the held lock then keeps the vault nonempty. Replaced queued directories fail identity checks.

Limits are 2 MiB input, 64 JSON levels, 0.5-second input idle and 2-second total input deadlines, 20,000 scanned entries, a 2-second inventory deadline, 512 KiB index bytes, and a 300 ms writer-lock wait. Startup context is capped at 24,000 UTF-8 bytes. A larger inventory stays complete on disk; context points to `brain/index.md` instead. The 5-second hook timeouts cover these bounded stages.

## Provider registrations

Brain hooks are repository-scoped. Copilot scripts and registrations live in `.github/hooks`; `.copilot/hooks` contains user-level hooks and does not contain brain hooks. Codex uses `.codex/hooks.json` and Gemini uses `.gemini/settings.json`. Copy the complete repository brain handlers and their standalone scripts into another repository. Global templates do not register brain hooks or tool guards. Existing user installations change only after an explicit reinstall.

- Copilot: `sessionStart` injects on startup, resume, and new sessions. `postToolUse` reconciles when `toolResult.resultType` is `success`. Failures use a separate event. Context is top-level `additionalContext`; startup progress uses the documented progress line followed by one final JSON object.
- Codex: `SessionStart` matches startup, resume, clear, compact, and fork. Every completed `PostToolUse` reconciles, including failed commands that may have changed files. Context uses `hookSpecificOutput` with `hookEventName: SessionStart`. The injector's own byte cap permits `additionalContextLimit: 0` without unlimited output.
- Gemini: `SessionStart` injects on startup, resume, and clear. `AfterTool` reconciles when the result object has no truthy `error`. Context uses `hookSpecificOutput.additionalContext`. `PreCompress` has no documented context-injection contract and is not used.

Only startup/reset injection returns context. Tool passes stay quiet. The injector performs reconciliation itself, so correctness does not depend on handler order. Codex and Gemini startup messages use `systemMessage`. Normal status contains no filenames, commands, note bodies, or secrets. Hook configuration changes still require each provider's normal trust review.

When copying a script to another repository, use its repository path or an absolute path within that repository. Example POSIX command: `/absolute/python3 -I -S -B /absolute/inject-brain.py --provider codex`. Quote paths containing spaces. In Windows Codex `commandWindows`, use `"C:\Python312\python.exe" -I -S -B "C:\Repo\.codex\hooks\inject-brain.py" --provider codex`. In Copilot PowerShell, use `& 'C:\Python312\python.exe' -I -S -B 'C:\Repo\.github\hooks\scripts\inject-brain.py' --provider copilot`. Gemini uses the host-native `command` field and timeouts in milliseconds; Codex and Copilot use seconds.

## Verification and recovery

Run `python3 scripts/test-brain-hooks.py` for process, copied-script, and repository registration checks. Installer preservation checks run in their dedicated suites. Run `python3 scripts/generate-hooks.py --check` for freshness. The `brain-hooks` workflow prepares native Windows, Linux, and macOS checks on Python 3.12 and 3.14. Local contract checks do not prove actual provider context delivery or native Windows behavior; retain those results separately in the migration plan.

Live checks on 2026-10-21 verified Copilot CLI 1.0.101 startup, clear/new and interactive resume, and Codex CLI 0.163.0 startup, clear, compact and interactive resume. Codex noninteractive `exec resume` did not refresh hook context in that probe; use interactive resume when fresh context is required. Gemini CLI delivery was explicitly waived and is not claimed. Native process checks cover all three providers.

For a busy writer, retry after the other process exits. For a malformed or oversized existing index, inspect it before restoring a valid inventory or removing that index deliberately. Do not remove a lock file while another writer may hold it. A later valid startup or tool invocation repairs inventory drift. To roll back registration changes, restore only the affected reviewed configuration and scripts, preserving unrelated hooks and runtime logs.
