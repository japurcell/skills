# Durable knowledge admission

- Preserve current project-specific facts that change future decisions and are costly to rediscover.
- Keep one canonical owner per rule. Merge duplicates and resolve contradictions before adding notes.
- Record source/evidence, check date, what it proves and does not prove, and a recheck trigger for version-sensitive claims.
- A code fact or session event is not automatically durable knowledge. Do not copy session logs, speculative claims, or secrets.
- Split topics by distinct loading triggers; keep indexes link-only and update inbound links after moves.
- End-of-session reflection may conclude that no write is needed. Follow-up work belongs in permanent-ID todos.
- Prefer an existing skill or structural check when it prevents recurrence more directly than a note.

Evidence: migration admission review on 2026-10-20, current brain/reflect workflow and retired documentation admission rules. Recheck when the knowledge workflow changes.
