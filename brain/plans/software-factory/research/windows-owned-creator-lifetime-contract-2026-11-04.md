## Decision and scope

Select one **qualification-only minimal creator boundary**: move the existing target-operation branch, its existing catches, and the original `child.Stop()` plus its immediate `ChildStopped` capture onto one fully owned CRT creator thread. Preserve the separately owned survival control and the remaining terminal checks on the observer. Join that creator after normal return, close its owned thread handle, then continue the original marker/exit/output/control/Release/final-count sequence. The original baseline remains before the new thread or any new synchronization resource. The original final query remains after all releases and the new thread handle close; its zero-increase assertion remains exact.

This is eligibility for one bounded qualification experiment, not a repair, support claim or native-ready helper. A passing changed profile would establish only that this exact profile met its original predicates with a completed creator lifetime. It would not establish the old cause, handle identity/number/type, universal hash noninvolvement, Node equivalence, namespace/DLL identity, external process closure or product/helper admission.

Root clarified that no stronger standalone closure guarantee is required for a stuck API/thread. An unproven join may pin state, emit no final query/COMPLETE/admission, and rely only on the **unchanged 12000ms transport cutoff** and **existing 8000ms fixture fallback**. This is a failure limitation, not successful cleanup. `processClosure` remains unverified. No early process exit, forced thread termination, unwinding live objects or new process handles is authorized.

## Why this boundary

| Candidate | Assessment |
| --- | --- |
| Full original operation on the owned creator, including survival control and both Release calls | Can serialize globals if gated, but moves the non-debug survival control, its readiness/termination, and all release scopes onto the new thread. It broadens the profile change and requires more result projection. It supplies no stronger stuck-worker closure guarantee. Defer. |
| Target branch + original catches + child.Stop + ChildStopped capture | Select. Preserves control readiness before target work, original target cleanup before exit/marker/output/control cleanup, and original Release ordering. The observer is idle while the creator mutates child/globals. The target is already subject to its original Stop/exit/EOF checks before creator return; observer completes all remaining checks after join. The only new lifetime boundary is placed between ChildStopped capture and the original marker/exit inspection. |
| Probe-only worker, followed by observer-side child.Stop | Reject. Attached refusal paths would run Wait/Continue on a different thread from debug creation. Merely joining/closing the worker first also changes owner-death behavior before original attached cleanup. |
