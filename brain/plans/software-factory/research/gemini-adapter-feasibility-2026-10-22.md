## Permission decision

**No Gemini 0.65.0 factory mode is qualified yet.** A bounded **workspace-write candidate** exists for an already trusted workspace under its existing account, hook and policy configuration, but only if its effective native permission and sandbox settings are demonstrably compatible with the requested profile. A strict **read-only candidate is not established** by `--approval-mode plan` or `--sandbox` alone. If the profile requires a write boundary that cannot be proved, dispatch must reject Gemini explicitly. These are exact-version findings, not permanent claims about Gemini CLI.

For workspace-write, do not supply `--skip-trust`, `--yolo`, `--approval-mode=auto_edit`, `--allowed-tools`, `--admin-policy`, `--policy`, or environment/config changes that disable security or hooks. In particular, do not force `--approval-mode=default` over an existing `plan` setting: that would broaden the user's mode. The candidate requires normal native trust and authentication already established outside the adapter, effective default approval mode, compatible user and admin policies, hooks left enabled, and an effective native sandbox whose real filesystem/network allowance is accepted by the profile. If any prerequisite is unknown, unsupported, or requires a trust/permission bypass, reject before launch. Headless unknown-tool default is `DENY`, but configured allows, trusted MCP servers, and admin/user rules still govern. A required live human approval is unavailable through plain `-p` JSONL; [native ACP](https://geminicli.com/docs/cli/acp-mode/) needs a separate design and qualification.

The specific policy trap is visible in `gemini-GLQ4MVLB.js:8435-8470`: `policyPaths` is `(argv.policy ?? settings.policyPaths)` and `adminPolicyPaths` is `(argv.adminPolicy ?? settings.adminPolicyPaths)`. These flags **replace** configured supplemental lists. `chunk-DKZARV6U.js:368257-368296` shows that nonempty `policyPaths` also replaces the default user policy directory rather than adding to it; `:368348-368383` loads standard system, supplemental admin, user and default paths, with standard admin policies suppressing supplemental admin paths. An adapter-generated `--policy` or `--admin-policy` cannot be assumed to add a restrictive rule safely. A future additive policy proposal must reconstruct the exact effective lists including the user directory where applicable, prove precedence and error handling, and preserve existing admin/user files. This task does not establish that mechanism. Similarly, `--allowed-mcp-server-names` replaces a configured allowlist (`gemini-GLQ4MVLB.js:8454-8458`), and `--allowed-tools` replaces configured allows (`:8440`), so neither is a safe generic narrowing mechanism.

Plan Mode is useful for human planning, but not a factory read-only guarantee here. Built-in `policies/plan.toml:24-35,76-86,108-190` allows noninteractive exit from Plan Mode and permits writes to designated plan Markdown paths. The [policy reference](https://geminicli.com/docs/reference/policy-engine/#approval-modes) and [Plan Mode guide](https://geminicli.com/docs/cli/plan-mode/#custom-policies) say user/admin policy and persistent Plan Mode approvals can override lower-tier built-ins. `--sandbox` on macOS defaults to a whole-process Seatbelt `permissive-open` profile (`gemini-GLQ4MVLB.js:10108-10121`); `sandbox-macos-permissive-open.sb:4-10,75-91,132-138` allows broad reads, project/temp/cache writes and outbound network. It is a useful workspace-write boundary, not read-only. `policies/sandbox-default.toml` configures the newer tool sandbox manager (`chunk-DKZARV6U.js:257735-257790,381230-381269`); it does not by itself prove every hook, extension, MCP server, child and CLI operation is read-only. `--sandbox` may also override `settings.tools.sandbox` (`gemini-GLQ4MVLB.js:7866-7882`), so blindly adding it can weaken a stronger configured sandbox. A truly read-only native mode needs a separately demonstrated full-process filesystem boundary compatible with normal auth/hooks and policy rules, or must remain unsupported.

Trust is a prerequisite, not an adapter flag. The [trusted-folder reference](https://geminicli.com/docs/cli/trusted-folders/#headless-and-automated-environments) says headless invocation fails with `FatalUntrustedWorkspaceError` when folder trust is enabled and the folder is untrusted. The adapter must surface that prerequisite and never set `--skip-trust` or `GEMINI_CLI_TRUST_THIS_FOLDER`. Hooks can run commands as the user; [hook configuration and trust](https://geminicli.com/docs/hooks/) remain in force. The factory cannot infer a no-write guarantee from tool policy while those native paths remain able to write.

## Stream and input contract to qualify

Use fresh `-p` with `--output-format stream-json`, no `--resume` or `--session-file`. Optionally supply a newly generated UUID via `--session-id`; `gemini-GLQ4MVLB.js:17340-17422` rejects an existing ID. Require exactly one `init` for that launch, record its `session_id` and model, then correlate all events with the owning child/attempt. The ID is native conversation identity, not proof of process identity or a resumable factory attempt. New attempts, including corrections, should use fresh native sessions unless a later explicit resume qualification proves otherwise. Do not use private reasoning as control input.

The [headless reference](https://geminicli.com/docs/cli/headless/#output-formats) names `init`, `message`, `tool_use`, `tool_result`, `error` and `result`, and [exit codes](https://geminicli.com/docs/cli/headless/#exit-codes) 0, 1, 42 and 53. In the actual bundle, `gemini-GLQ4MVLB.js:11649-11998` (agent-session branch) and `:12156-12456` (older branch) emit assistant `message` chunks with `delta: true`, tool requests/results, and terminal `result`. `:12041-12049` switches branches through `getAgentSessionNoninteractiveEnabled()`, so fixtures must cover both or pin and verify the effective setting. `result` has status/stats but **no final response payload or phase marker**. Build the proposed final text from assistant deltas after the last completed tool phase, not from user messages, tool output, or arbitrary earlier assistant narration. Reset the candidate assistant buffer at each `tool_use`, require matching tool results before final acceptance, require a nonempty final assistant segment when the workflow expects one, and then validate the workflow's result schema. This selection rule is a conservative proposal pending native transcript proof, especially for multiple tool calls and assistant text around them.

Require bounded, well-formed JSONL, a single terminal `result`, native exit 0, `result.status=success`, no error-severity event, no `tool_result.status=error`, no pending tool call, and no native stop/block marker. In `:11852-11985`, `STOP_EXECUTION` can emit a tool error while `agent_end` still emits `result: success`; `AGENT_EXECUTION_BLOCKED` becomes an `error` event with severity `warning`. The older path `:12282-12295,12308-12327,12404-12431` can emit `result: success` on `AgentExecutionStopped` or `STOP_EXECUTION` as well. The adapter should classify these as inconclusive/failed according to its public contract rather than report a successful answer from prior chunks. Preserve warning/usage provenance without inventing cost or hidden reasoning. A fatal error may leave no terminal result; that is failure, never a partial success.

`-p` is **appended to stdin** by the CLI (`gemini-GLQ4MVLB.js:17760-17766`), and macOS sandbox relaunch injects piped stdin ahead of `-p` (`:17608-17629`). The headless path tests leading `/` for a slash command and preprocesses `@` references before the model receives the prompt (`:11656-11690`, `:12162-12196`). `chunk-34OW3ELT.js:66997-67060,67410-67475` shows `@` can select files, MCP resources or agents and can perform reads before an ordinary model tool call. Do not pipe or concatenate untrusted task/resource bytes as an unexamined prompt. A candidate is a fixed adapter-owned, non-slash launcher prompt with one controlled `@` reference to a bounded in-workspace prompt file; file content must be confirmed to enter as data without recursive slash/`@` handling. Test this with harmless literal slash/`@` fixtures before using it. Keep stdin closed or empty when using `-p`, and do not put secret material in argv, logs or the research artifact.

`gemini.js:31-105` normally relaunches a Node child for memory configuration unless `GEMINI_CLI_NO_RELAUNCH` or `SANDBOX` is set; `gemini-GLQ4MVLB.js:17604-17632` can relaunch again under a sandbox. Do not claim a single-child lifecycle. The common runner's owned POSIX process group and stop/grace handling must encompass wrapper, model child, sandbox child and any descendants; this source review does not prove quiescence. Windows child-tree behavior is unknown and must be qualified natively rather than inferred from POSIX signals.

## Bounded follow-up gate

1. Deterministic fixtures against the exact source contract: both noninteractive branches, multi-chunk final after tools, missing/mismatched tool result, malformed/truncated/duplicate terminal JSONL, error and warning events, hook block, `STOP_EXECUTION`, empty final, native nonzero exit, and session-ID mismatch. Verify no false final answer from earlier assistant/tool text. Check prompt-file delivery with literal leading slash, `@file`, `@agent`, and MCP-like tokens as data, plus size/encoding bounds.
2. Read-only preflight of the **effective** trusted settings, policy paths, default mode, hooks, extensions/MCP, sandbox and artifact hash. Prove a candidate profile never broadens configured permissions. If policy composition or sandbox scope cannot be established, return an explicit unsupported-mode result. No install, trust acceptance, auth mutation, `--policy` replacement, or security-disable workaround belongs in qualification.
3. After the user configures normal CLI auth, run one bounded native headless batch in a disposable trusted worktree: a harmless final-response case, a denied-write case, a permitted workspace-write case if requested, hook-block case, and stop/cancel with descendant quiescence. Record raw JSONL privately with bounded redaction and hashes, effective config facts without credentials, exit codes, file effects and process-group outcome. Repeat platform proof separately on Windows; do not extrapolate from macOS. Only then may the parent select a supported exact mode and implement/register an adapter.

Until those gates pass, T8-Gemini remains a research outcome with no live support claim.
