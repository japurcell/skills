## Decision

Implement one closed set of persisted formats in `src/cleanup-references.ts` and one advisory selection module `src/cleanup.ts`. An exact, bounded shape plus its explicit reference semantics is a **format claim**, not authentication of authored workflow code. No compiled workflow closure digest exists in current persisted records: `src/build.ts:50-53` imports an emitted `run`, while `src/lifecycle.ts:98,123` saves workflow/commit metadata and generic report JSON. Neither path, selected commit, report channel, validator name alone nor digest alone authenticates a producer.

Support current extraction/evaluation v1 through the concrete ownership joins below, and current exact library adoption/revert shapes through the explicit strict compatibility rule below. Keep all historical unversioned change/audit reports and unknown/custom variants opaque. Never infer an old report's version from its filename or add historical markers.

For **future shipped change/audit reports**, a producer-declared `{version:1,kind:'change-report'|'audit-report'}` in the report is sufficient. No new runtime-issued producer marker is required: it would add no authored-source authentication, and this feature only interprets a declared persisted contract. Require exact nested schemas and complete owned attempt/operation/input joins as well. Small forward source addition, owned by C3 after release: add these two fields at `templates/workflows/change.ts:210` and `audit.ts:53`; project `candidate` and investigation `result` to `{summary:string}` when returning them. Current validators allow extra model fields (`change.ts:35-42`), so direct reuse of arbitrary model objects would otherwise make new reports opaque. Raw/validated agent evidence remains intact. Add no runtime metadata, registry, DDL or generic registration framework. Unknown versions/kinds/fields still refuse, including a custom workflow which claims this marker but fails its exact contract.

Without that forward addition, a real default scenario still works in a history containing only recognized learning/action reports: select unreferenced ended startup command stdout/stderr from an actual learn/evaluate invocation. Its report references extraction/reviewer/objective attempts, not its compiler/setup commands. Another minimal scenario is a public invocation with exact empty root inputs, no returned report and an ended ordinary command; there is no unknown report to interpret. A preexisting opaque ordinary report anywhere in the retained history intentionally blocks capture-payload eligibility. Backup-tuple inspection may still return C2 facts independently; this does not permit payload cleanup. With the two-field forward addition, new change/audit histories get the same useful startup-output selection while all named checks and prior attempt evidence remain protected.

All paths beginning `src/`, `templates/` or `test/` below are under `packages/software-factory/`.

## Core graph and ownership invariants

Roots: **every report payload, every request payload, every root invocation input payload**, all question/selected-context references, and each agent attempt's explicit input/raw/output/normalized references. All operational rows, attempt admission/settlement/accounting/lineage, events, notifications, claims, sessions and capture headers remain immutable facts; do not add ownership edges from *every invocation to every command attempt*, which would accidentally protect every command output forever. All attempt rows survive but only an evidence-referenced command attempt roots its owned payloads.
2. Invocation metadata input belongs to the invocation, channel context, attempt null. Root input wrapper exactly `{inputs,question,contexts}` agrees with metadata. Question points to complete request; selected contexts belong to the same run (resolve actual owner invocation from the globally paged header map, then compare run IDs), not necessarily same invocation (`lifecycle.ts:70-71,96-98`; `store.ts:910`). Retain **all** saved requests, not only `readSavedQuestion`'s latest (`store.ts:2141`). Empty inputs `{}` have a sufficient literal-only input compatibility rule. For nonempty inputs use the selected recognized producer's exact input schema above or action-reference shape; unknown structural input semantics block. Never scan prose for IDs.
3. Attempt facts join owner invocation/run, actual operation row/kind/key, explicit `priorAttemptId` and `reusedAttemptId`. Same-run older-invocation lineage is valid; foreign run is not. A referenced attempt protects **every** owned capture discovered by the full header scan, any prior/reused attempt recursively and their captures, independent of attempt success. A dangling/malformed/opaque prior reference blocks. Agent metadata roots its declared capture IDs; verify channels and owner. If current metadata is missing because admission failed, retain known captures and block only when required evidence is unresolved or activity uncertain, not by synthesizing IDs.
4. Generic owned agent input context is exactly `{inputs,purpose,context,sourceCaptureId}` (`agents.ts:142-145`). `sourceCaptureId` is an extra required edge to the invocation-owned attempt-null source context; that original context exactly `{step,inputs,purpose,context,validator}` (`agents.ts:66-68`). EffectiveInputs exact shapes come from `profiles.ts:19-30` with no history edges in their text/path fields. 5. ## Deterministic bounded algorithm and snapshots

- Open C1's existing-only `openCleanupReadStore` (`store.ts:195-233`) once. It holds a validated read-only WAL snapshot until close; do not compose separate ordinary `RepositoryStore` reads which each take a new transaction. C1 `readCleanupSnapshot` at512 reports high-water cursors and **unassessed** recovery, not permission. No historical/live SQLite was opened for this packet.
- Page all invocation facts, attempt facts and capture headers through that snapshot's fixed high-water values, ascending canonical decimal cursor; no report-filtered SQL that hides arbitrary skipped rows. Use C1 methods at582,585,588 with100rows/256KiB. Require matching `through`, strictly advancing cursors when `hasMore`, and each row within bounds. Every C1 opaque fact is an explicit blocker, including null stable ID: preserve kind+cursor, do not drop or renumber it. Header maps index capture->owner and attempt->capture IDs, not payload strings. No eager `readHistory` or previews.
- Read every report in full only after its byte measurement/header permits <=131072; C1 capture pages use20chunks/256KiB and each raw chunk<=65536, verify contiguous sequence/header/state/owner on every page. Hash exact UTF-8 payload bytes and length-delimited sequence records separately; never hash parsed/re-serialized JSON in place of raw report bytes. Decode one bounded object, emit ID edges/digest facts, then release its strings. Capture source evidence may stream full bytes for hash/prefix comparison without retaining text. Agent input decode cap393216. Keep byte and object depth prechecks before parsing recursively; no unlimited concatenation.
- Build all recognized report edges before computing completeness/impact. Discover and resolve in fixed node-key order; de-duplicate edges by complete tuple. Detect cycles with an iterative three-color traversal and an explicit bounded stack. A cycle blocks (`cycle`/`invalid-lineage`) and retains all discovered nodes, never cuts an edge or treats the cycle as proof of independence. Reverse adjacency gives every report reachable backwards from each selected capture, then all their reverse-dependent reports. Sorted roots/neighbors produce repeatable graph/impact pages independent of insertion order. An opaque report is a **global blocker for all payload selections** because its dependency scope is unproved. Partial local results may be displayed as diagnostic-only and never `eligible`.
- Limits, all refusal rather than truncation: selection100unique capture pairs or20unique backup tuples;100000source rows;1000reports;16384nodes;65536edges;4096total read/output pages;32MiB explicitly charged retained graph/maps/DTO state;64MiB total decoded/streamed payload bytes;30s elapsed checked before/after every page/record; metadata64KiB/record, events/operation data8KiB, report128KiB, typed agent input384KiB; JSON depth12; action embedded object count64; IDs256bytes. Report-dependency traversal depth128 (cycles refuse earlier). Producer cardinalities above remain tighter where applicable. Nested action reports cannot recursively contain other revert outcomes: fixed types only. Public output pages <=100records and<=256KiB, ID-only bounded blocker/impact records; a single oversized record blocks. Default bounds can be tightened only, never widened past these fixed maxima. Deadline is cooperative, not a promise to interrupt SQLite/native work.
- Content snapshot digest is a versioned domain-separated canonical hash of repository/schema/release/DB identity/recovery evidence and high-waters; ordered raw invocation/attempt/operation identity+bytes+hash facts; ordered complete header facts; every recognized/opaque report identity+raw bytes hash when available; exact required input/reference payload hashes and chunk-sequence digests; selected payload hashes/byte counts; event facts used; accepted C2 exact tuple/parent/file/evidence digests. Unknown/missing digest prevents a complete impact. Hash metadata raw C1 SHA, not just normalized projection, so an update to existing JSON or report bytes changes the snapshot even when high-water is unchanged. C1 opaque oversized raw data has no digest: block, never fabricate one.
- Advisory analysis is coherent within its read snapshot, but is not a current mutation authorization after that snapshot closes. A future claim task must recompute and compare the complete content snapshot under its own accepted exclusion protocol; do not add that protocol here. C2 filesystem facts may change outside SQLite; impact binds their accepted observation digest and remains advisory.
