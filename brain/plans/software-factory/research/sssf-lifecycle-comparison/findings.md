### Example: an agent asks for a decision

Suppose an agent replies, “Should I delete `old.sql` or preserve it?” as plain prose. The adapter captures it as the assistant’s final text, but no question event or UI control receives it. The envelope parser cannot find a JSON object, sends a correction request, retries twice in the same Pi session, and then raises an error if the result is still prose. If the agent instead returns valid JSON with that sentence in `summary`, the run simply treats it as summary text and continues according to the envelope status, gates, and workflow code. Neither path waits for a human answer.

### Limits and source caveats

- These are code-path findings, not measured latency, reconnect, signal-delivery, or install outcomes. No upstream tests or end-to-end run were performed. In particular, OS process-group signal delivery and a live child surviving its parent were not exercised.
- The README calls the visualizer read-only, while the server exposes archive/restore as its one database write. The README also says a killed run finalizes, but source implements that finalization only for SIGTERM/SIGINT. SIGKILL and parent-only signaling have no child-cleanup path in the inspected code.
- The pinned `SKILL.md` says the visualizer ships in a later pass, although the same pinned tree and README contain the visualizer implementation. For behavior, the UI source and server routes are stronger evidence than that stale scope note.
- The report concerns SSSF’s selected `pi -p --mode json` adapter and supplied subagent extension. It makes no claim about Pi’s separate interactive TUI features or what a custom extension could add.
