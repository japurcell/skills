## Decision after the next native result

| Native category | Decision |
| --- | --- |
| Full DOS/device/other path with matching basename | Compare only through an OS/file-handle-verified namespace or `FILE_ID_INFO` on opened file handles. `QueryFullProcessImageNameW` documents Win32 versus native path modes; `GetFinalPathNameByHandleW` documents DOS versus NT paths. A string prefix replacement is insufficient. Recheck that the start belongs to the held process lifetime. |
| Name-only with matching basename | The process ETW property cannot independently establish the full pinned path in this run. Use a held process handle and pinned file identity for each process, then associate the ETW key and lifetime. Keep name-only as a consistency check only. |
| Different basename, time before the held root's creation | A prior same-PID process is plausible; current first-rejection callback can mask a later valid start. A future bounded decoder must classify all relevant starts without admitting the earlier event, then enforce one exact candidate in the held lifetime. |
| Different basename near the held root's creation | Do not infer that the process was pinned or even that the event belongs to that process. Investigate TDH decoding and process/event association with closed evidence. |

For a later independent-identity route, keep a verified handle to the pinned executable file, hash **that held file** against the bootstrap pin, and compare volume serial plus 128-bit file ID for any independently opened candidate file. Keep the file handle through fixture execution with sharing that prevents write/delete replacement, subject to a real Windows feasibility check. `QueryFullProcessImageNameW` on each held process handle supplies its full image path; `GetProcessTimes` supplies creation and exit times; `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION | SYNCHRONIZE)` can hold the child object. The child must stay alive until C# has opened and verified that handle. The current `spawnSync` fixture prints its PID after exit, so the minimum fixture change is a bounded parent/child handshake: root starts the child asynchronously, reports the PID in the current private control pipe while child waits, C# opens and verifies the child handle/path/file identity, then signals release and waits for both clean exits. Hold both process handles until offline parse completes. No global tracker, production Job Object, startup download, or change to the single sequential ETW session is needed.

On that route, match each live start and end to the held process's PID and creation/exit interval, require equal nonzero `UniqueProcessKey` within a process, distinct root/child keys, exact child parent, and reject duplicate or prior same-PID candidate events. A held handle prevents reuse during the held object's life; event timestamps and key continuity must still establish that a selected start/end are that object's events. Require the image-load event's **file** identity to resolve to the held pinned file, using a verified OS-backed path/file handle mapping if the event supplies a resolvable full path. A basename-only image-load field cannot prove this on its own. This design remains conditional until native field forms and the lifetime relationship are observed.

## Primary contracts

- [Process_V2_TypeGroup1](https://learn.microsoft.com/en-us/windows/win32/etw/process-v2-typegroup1): start/end opcodes, `ImageFileName`, `UniqueProcessKey` and explicit warning that PIDs are reused.
- [Image_Load](https://learn.microsoft.com/en-us/windows/win32/etw/image-load): load opcode 10, `ProcessId`, `FileName`, and rundown opcodes.
- [QueryFullProcessImageNameW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-queryfullprocessimagenamew) and [GetProcessImageFileNameW](https://learn.microsoft.com/en-us/windows/win32/api/psapi/nf-psapi-getprocessimagefilenamew): handle-based Win32/native and device path contracts.
- [GetProcessTimes](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getprocesstimes), [PROCESS_INFORMATION](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/ns-processthreadsapi-process_information), and [OpenProcess](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-openprocess): held process timing and PID/handle lifetime.
- [EVENT_TRACE_LOGFILEW](https://learn.microsoft.com/en-us/windows/win32/api/evntrace/ns-evntrace-event_trace_logfilew) and [EVENT_HEADER](https://learn.microsoft.com/en-us/windows/win32/api/evntcons/ns-evntcons-event_header): converted event time by default and event callback semantics.
- [GetFinalPathNameByHandleW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getfinalpathnamebyhandlew), [GetFileInformationByHandleEx](https://learn.microsoft.com/en-us/windows/desktop/api/winbase/nf-winbase-getfileinformationbyhandleex), [FILE_ID_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_id_info), and [CreateFileW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew): handle-backed path namespace, file ID, and sharing controls.
