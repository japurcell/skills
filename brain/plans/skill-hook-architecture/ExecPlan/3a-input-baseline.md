## Result and evidence

On 2026-11-19, Darwin 27.2.0 arm64, Python 3.14.6, candidate `1eaf63dc`, `rtk proxy python3 scripts/tests/hooks/test-input-baseline.py` exited 0 with `Public hook input parity passed`. The fixture extracts `069b3f22` in a disposable directory and verifies each of the three executable files against `git show` raw blobs. It runs the archived and candidate public executables separately with disposable homes, byte-identical inputs and a capturing mock RTK. It compares complete stdout, stderr, RTK input and completion while the writer remains open. The script defines the exact byte streams and prints each observed result; an optional candidate-root argument allows T3b to reuse it. The fixture is POSIX-only: its executable mock and this observation do not prove Windows behavior.

Common means `.codex/hooks/inject-brain.py` (`_read_json_input_text`); RTK means `.copilot/hooks/scripts/rtk-hook-copilot.py` (`read_hook_input`); Codex means `.codex/hooks/load-required-skills.py` (`read_json_input`). For the valid startup event, common returned `{}` with empty stderr (no vault was supplied), RTK returned `{"mock":true}` and forwarded exact bytes, and Codex returned its pass response and the fixture skill context. All three finished with the writer open for ASCII whitespace, a multibyte character split across writes, and the final brace delayed 100 ms. RTK and Codex also accepted nonbreaking spaces on both sides; common returned `{}` and `brain: invalid input or inaccessible vault; previous index preserved` on stderr.

Buffered trailing `x`, incomplete JSON, non-object JSON and invalid UTF-8 were rejected. Common emitted `{}` and the same generic stderr; RTK emitted `{}` with empty stderr and did not invoke the mock; Codex emitted `continue:false` with respectively `Invalid hook input: trailing data`, `Invalid hook input: malformed or incomplete JSON`, `Invalid hook input: expected a JSON object`, and `Invalid hook input: expected UTF-8 JSON`. All completed while the writer remained open. At 65 nested arrays common rejected with its generic diagnostic, while RTK and Codex accepted. Codex accepted exactly 1,000,000 bytes and rejected 1,000,001 with `Hook input exceeds the maximum size`; common accepted 2,097,152 and rejected 2,097,153 bytes with its generic diagnostic. RTK forwarded both limits and a 2,162,748-byte fragmented input exactly. These large cases close the writer after sending; when a bounded consumer rejects early the writer may encounter a broken pipe.

T3a POSIX evidence is captured. T3b remains blocked on the integrated M2 prerequisite; Windows pipe observations remain pending a native runner. Reflection: no additional durable note was needed; the reusable behavioral checks are encoded in the fixture and the existing hook-testing guidance already calls for these boundaries.
