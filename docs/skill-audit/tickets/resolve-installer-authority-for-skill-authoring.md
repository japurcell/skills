# Resolve Installer Authority for Skill Authoring

**Type:** grilling
**Status:** open
**Blocked By:** review-skill-authoring-and-repository-guidance.md
**Research Dir:** not applicable

## Question

Who may perform the account-level refresh required by Create Skill, under what authorization, and what must the agent report when installation is unavailable or prohibited?

[SAG-002](../findings.md#sag-002-installer-ownership-conflict) owns the evidence: Create Skill and repository workflow require refresh, while scripts instructions restrict agents to targeted verification/test scripts. The installer changes several user-level provider destinations and configuration. This is a textual authority conflict; no installation or runtime failure was observed in the audit.

Decide the agent/human responsibility, exact approval and stopping boundary, and scoped source targets. Preserve required authoring dependencies and honest refresh status. Do not turn a human-run import restriction into permission to run importers, or treat this audit as install authorization. The original batch records this as a separate pending decision rather than selecting autonomy for the human.
