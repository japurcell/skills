# Provider skill compatibility findings

Retrieved 2026-10-01. This is a documentation comparison, not a runtime conformance test. Provider documentation can change, and some cited OpenAI pages describe product rollouts rather than guaranteed availability for every account or client.

## Findings

All three CLI ecosystems recognize `SKILL.md` directories under `.agents/skills`, but that shared path does not imply a shared runtime contract. The repository installer copies maintained source skills from `skills/` into `~/.agents/skills` and omits eval files and selected repository-only directories ([`scripts/install.sh`](../../../../scripts/install.sh)). OpenAI, GitHub, and Gemini document `~/.agents/skills` as a user-level location; Codex and Gemini also discover workspace `.agents/skills`, and GitHub CLI and VS Code do as well. Discovery precedence, trusted-workspace behavior, activation, frontmatter, and resource loading remain client-specific.

### Compatibility constraints

- Keep core `SKILL.md` metadata portable: a short, trigger-oriented `description`, simple lowercase hyphenated `name`, and instructions that work without provider-specific frontmatter. The VS Code name rule is the tightest documented constraint among these surfaces.
- Treat invocation controls as adapters. Codex's `agents/openai.yaml`, Copilot CLI's invocation/tool fields, and Gemini's consent-gated activation are not interchangeable. A shared file cannot express identical invocation and permission behavior across these clients.
- Keep resources discoverable through explicit relative links from `SKILL.md`; do not assume a shared preload policy. Codex provides progressive disclosure, Copilot CLI makes skill-directory files available on invocation, VS Code reads linked resources on demand, and Gemini documents progressive disclosure.
- Treat scripts as instructions/resources, not as a portable permission grant. Copilot CLI's pre-approval can materially widen shell capability; Gemini consent to activate a skill is distinct from permission for later tool calls. Validate scripts and tool policy in each client.
- OpenAI's documented behavioral evaluation process proves behavior only for the Codex execution surface and model/client configuration actually tested. It does not establish Copilot CLI, Copilot VS Code, Gemini CLI, or Gemini Code Assist behavior. Gemini's own CLI behavioral tests likewise do not validate this repository's skills across providers. The repository inventory reports eval files for some skills but explicitly does not treat their presence as evidence of quality or passing behavior ([local inventory](../../local-inventory.md)).
