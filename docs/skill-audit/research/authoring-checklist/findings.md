# Claude Skill authoring checklist

Retrieved 2026-10-01. The primary source is Anthropic's [Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices). It describes Claude Skills, so structural limits, discovery behavior, runtime details, and named Claude model families are Claude-specific. The general-authoring labels below identify transferable writing or engineering heuristics; they do not establish cross-provider support or requirements.

The source page does not expose a version or last-updated date. It mixes explicit format requirements with advisory guidance. Treat only the `SKILL.md`/frontmatter constraints below as format requirements; line-count targets, evaluation counts, style rules, and workflow patterns are recommendations, not universal schema validation rules.

## Checklist

### Core principles

- **General advisory - concise instructions.** Remove explanations, background, and repeated text that do not change the agent's action; inspect whether each paragraph adds task-specific information. The source's context-cost rationale concerns when Claude loads each file. [Concise is key](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#concise-is-key)
- **General advisory - match specificity to risk and variability.** Use flexible guidance where context admits several good solutions, parameters where a preferred pattern allows variation, and exact steps or commands for fragile or consistency-critical operations. Inspect the task's failure cost and variation against the instruction detail. [Set appropriate degrees of freedom](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#set-appropriate-degrees-of-freedom)
- **Claude-specific advisory - test intended models.** If the Skill targets more than one Claude model, inspect real runs for each named target and compare guidance sufficiency, clarity, and over-explanation. Haiku, Sonnet, and Opus are examples in the source, not an exhaustive or permanent model list. [Test with all models you plan to use](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#test-with-all-models-you-plan-to-use)

### Structure, naming, and discovery

- **Claude-specific format requirement - required file and metadata.** Verify a `SKILL.md` with YAML `name` and `description` fields; `name` is at most 64 characters, lowercase letters/numbers/hyphens only, without XML tags or reserved words `anthropic`/`claude`; `description` is non-empty, at most 1,024 characters, and contains no XML tags. Inspect parsed YAML and field lengths/contents. [YAML frontmatter requirements](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#yaml-frontmatter-requirements), [Skill structure](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview#skill-structure)
- **General advisory - meaningful, consistent skill names.** Check that a name signals the activity or capability, avoids vague or overly broad labels, and fits the collection's naming pattern. Gerunds are suggested, while noun phrases and action-oriented names are explicitly acceptable. [Naming conventions](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#naming-conventions)
- **General writing advisory / Claude-specific discovery purpose - useful descriptions.** Check for third-person wording, concrete capability or output terms, and explicit use cases or triggers; ensure it distinguishes this Skill from nearby Skills. Keep implementation details in the body rather than overloading the one description field. Third person and specificity are authoring guidance, while non-empty and maximum length are frontmatter constraints. Evidence is the description plus expected activation examples or logs. [Writing effective descriptions](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#writing-effective-descriptions), [Metadata loading](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview#how-skills-work)
- **Claude-specific advisory - keep the entry file focused.** The page recommends keeping the `SKILL.md` body below 500 lines for performance and splitting material as it approaches that size. Inspect the body length and whether supplementary detail is separated and linked. This is an optimization heuristic, not a declared hard format limit. [Progressive disclosure patterns](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#progressive-disclosure-patterns), [Token budgets](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#token-budgets)
- **Claude-specific advisory - disclose detail progressively.** Keep an overview and essential procedure in `SKILL.md`, and link to specialized instructions, reference material, examples, or scripts when those are needed. For multi-domain Skills, inspect whether files are grouped by domain/feature so a task can load only relevant material. The source also encourages bundling comprehensive references, examples, and datasets because Claude pays no context cost for them until accessed. [Progressive disclosure patterns](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#progressive-disclosure-patterns), [How Skills work](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview#how-skills-work)
- **Conditional advisory - separate advanced details.** If only some requests need an advanced feature, keep the basic procedure in the main file and directly point to its detail file. Evidence is whether the main file tells the agent which file applies to that case. [Progressive disclosure patterns](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#progressive-disclosure-patterns)
- **Claude-specific advisory - keep references one level deep.** Link needed references directly from `SKILL.md`; avoid chains where one reference points to another. The source's rationale is that Claude may only preview part of a nested file. Inspect all local links and their depth. [Avoid deeply nested references](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#avoid-deeply-nested-references)
- **Claude-specific advisory - add navigation to long references.** For bundled reference files longer than 100 lines, check for a table of contents near the top that exposes the file's sections. The threshold is the source's heuristic. [Structure longer reference files with table of contents](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#structure-longer-reference-files-with-table-of-contents)
- **Claude-specific advisory - use descriptive paths and organization.** Check that paths use forward slashes, filenames convey their contents, and directories reflect domain or feature rather than opaque numbering. Test that the documented paths resolve in the actual Skill tree. [Runtime environment](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#runtime-environment), [Avoid Windows-style paths](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#avoid-windows-style-paths)

### Workflows and content patterns

- **General advisory - make complex procedures sequential.** For multi-step tasks, inspect for clear ordering and prerequisites; use a copyable progress checklist for especially complex workflows when it helps track completion. [Use workflows for complex tasks](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#use-workflows-for-complex-tasks)
- **General advisory - close the quality loop.** Where quality or correctness matters, check for a validation step, a specific response to failures, and a repeat-until-passing path. Evidence may be a script, checklist, or comparison against a reference. [Implement feedback loops](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#implement-feedback-loops)
- **General advisory - manage time-sensitive facts.** Avoid instructions likely to become stale; if historical behavior must remain documented, separate and label it as old or deprecated while making the current method clear. Inspect dates, version claims, and whether current versus legacy guidance is distinguishable. [Avoid time-sensitive information](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#avoid-time-sensitive-information)
- **General advisory - use terminology consistently.** Check whether the same concepts use the same terms throughout the Skill and its references. [Use consistent terminology](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#use-consistent-terminology)
- **General advisory - calibrate templates to output constraints.** When a format is strict, inspect whether the Skill provides an exact template; when adaptation is appropriate, the template should be a default that permits judgment. [Template pattern](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#template-pattern)
- **Conditional general advisory - provide concrete examples.** When output quality depends on style or shape, inspect for representative input/output pairs and whether they show the level of detail expected. [Examples pattern](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#examples-pattern)
- **Conditional general advisory - make branches explicit.** If the method differs by task type, check for decision points and a distinct procedure for each case. When the branches become long or complicated, move detail to directly linked files and tell the agent which one to read. [Conditional workflow pattern](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#conditional-workflow-pattern)
- **General advisory - choose a default instead of listing options.** Unless alternatives are needed for meaningful cases, inspect whether one recommended path is clear and exceptions are scoped to their trigger. [Avoid offering too many options](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#avoid-offering-too-many-options)

### Evaluation and iteration

- **General evaluation practice, prescribed here for Claude Skills - measure before expanding docs.** First run representative tasks without the Skill and record concrete gaps; the page recommends three scenarios, a baseline, minimal instructions aimed at those gaps, then reevaluation and comparison. Inspect the scenario set, baseline outputs, expected behavior, and comparison records. The count of three is a recommendation, not a platform-enforced minimum. [Build evaluations first](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#build-evaluations-first)
- **Claude-specific advisory - make evaluations inspectable.** Example evaluation data includes the active Skill, request, files, and expected behaviors. Check that a local rubric captures observable success rather than a vague overall judgment. The page says it has no built-in evaluation runner and leaves evaluation systems to users. [Build evaluations first](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#build-evaluations-first)
- **Claude-specific authoring workflow - mine real work for reusable knowledge.** For a new Skill, inspect whether its rules reflect context, preferences, and procedures that recurred during an actual task. Review for unnecessary explanations and whether reference material belongs in a separate file. [Develop Skills iteratively with Claude](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#develop-skills-iteratively-with-claude)
- **Claude-specific advisory - test with a fresh using instance and real tasks.** The described workflow uses one Claude instance to author and another to exercise the Skill. Inspect real task runs for retrieval, rule application, and outcome; record concrete misses, revise, and retest. The page recommends repeated observation/refinement, not a particular number of iterations. [Develop Skills iteratively with Claude](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#develop-skills-iteratively-with-claude)
- **Conditional general advisory - incorporate team feedback.** If teammates use the Skill, inspect feedback about whether it activates when expected, whether its instructions are clear, and what is missing; look for evidence that feedback was incorporated. [Develop Skills iteratively with Claude](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#develop-skills-iteratively-with-claude)
- **Claude-specific advisory - observe file navigation and metadata behavior.** Inspect usage evidence for unexpected exploration order, missed references, repeated reads, and never-read files. Use those observations to consider clearer links, moving repeatedly needed content into the main file, or removing/signaling unused references. Verify name/description behavior against expected activation cases. [Observe how Claude navigates Skills](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#observe-how-claude-navigates-skills)

### Executable resources and environment

- **General software-quality advisory; only applies when scripts are bundled.** Check that scripts handle foreseeable errors with explicit, useful outcomes instead of simply failing and expecting the model to infer recovery. Review fallback behavior for safety and correctness; the page's sample fallback values are illustrative, not a blanket prescription to silently create or substitute data. [Solve, don't defer](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#solve-dont-defer)
- **General software-quality advisory; only applies when scripts have configurable values.** Check that non-obvious constants and parameters have a reason documented near them. [Solve, don't defer](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#solve-dont-defer)
- **Conditional advisory - use utility scripts for deterministic repeated work.** Where a task benefits from reusable, predictable operations, inspect whether a bundled utility avoids repeated generated code and supports consistent use. [Provide utility scripts](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#provide-utility-scripts)
- **Claude-specific runtime advisory; only applies when scripts are referenced.** State whether Claude should execute a script or read it as reference. If execution is intended, inspect for an explicit command, inputs, and expected output; the source generally prefers executing utilities, which it says avoids loading their source into context. [Provide utility scripts](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#provide-utility-scripts), [Runtime environment](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#runtime-environment)
- **Conditional Claude capability advisory - use visual analysis where useful and available.** If source inputs can be rendered as images and the target Claude environment can inspect them, check whether the workflow renders and examines the visual representation where layout or spatial structure matters. [Use visual analysis](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#use-visual-analysis)
- **Conditional general reliability advisory - validate plans before risky execution.** For batch, destructive, high-stakes, or complex-rule work, inspect whether the workflow creates a structured intermediate plan, validates it before applying changes, then verifies the result. [Create verifiable intermediate outputs](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#create-verifiable-intermediate-outputs)
- **Claude-specific and surface-dependent - declare package assumptions.** When a Skill needs external packages, name them and verify availability in the intended Claude surface. The authoring page distinguishes claude.ai package/network access from the Claude API; the linked API code-execution documentation says its container has no internet or runtime package installation and lists pre-installed Python libraries. Audit the actual dependency list against the target environment, not just the example instructions. [Package dependencies](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#package-dependencies), [API code-execution runtime and libraries](https://platform.claude.com/docs/en/agents-and-tools/tool-use/code-execution-tool#containers)
- **Claude-specific runtime model - test actual file access.** The source says metadata is loaded at startup, `SKILL.md` when triggered, and references only when used; scripts run without their source consuming context, while their output does. Inspect links, paths, and example tasks in the actual directory to confirm the expected files can be found and that unnecessary resources stay unreferenced. [Runtime environment](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#runtime-environment), [How Skills work](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview#how-skills-work)
- **Claude-specific mechanism; only applies when MCP tools are named.** Use fully qualified `ServerName:tool_name` references and inspect that each server/tool name matches the connected environment. [MCP tool references](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#mcp-tool-references)
- **Claude-specific and environment-dependent - declare tool/package prerequisites.** Do not imply a package or tool is already installed without evidence. Check that the Skill names prerequisites and gives the supported setup or a documented alternative for its target surface. [Avoid assuming tools are installed](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#avoid-assuming-tools-are-installed), [Package dependencies](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#package-dependencies)

The page's final **Checklist for effective Skills** repeats many checks above in condensed form. It adds no distinct practice beyond the rows here: frontmatter discovery, body size, progressive disclosure, stable terminology, examples, clear workflows, script errors/constants/dependencies/documentation/paths, verification loops, evaluations, model coverage, real usage, and conditional team feedback. Use it as a coverage cross-check, not as a substitute for the preceding sections. [Checklist for effective Skills](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#checklist-for-effective-skills)

## Related first-party clarification

The linked Skills overview adds security guidance that is relevant to a static audit of a Skill bundle, although it is outside the Best Practices page's checklist: inspect every bundled instruction, script, image, and other resource for operations that do not fit the Skill's stated purpose; pay attention to unexpected network/file access, tool use, sensitive-data exposure, and instructions fetched from external URLs. It says to treat Skills like installed software and exercise particular care with untrusted sources and sensitive or production contexts. This is Claude product guidance; later cross-provider audits should translate the risk checks to the actual host's capabilities. [Security considerations](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview#security-considerations)

## Source gaps and qualifications

- The page provides no version or update timestamp in the retrieved content; this file records the retrieval date only.
- The 500-line target, three evaluation scenarios, model testing examples, and style/workflow directions are advice. The page does not specify a machine validator, score threshold, statistical repeat count, or pass/fail bar for effectiveness.
- The authoring page says evaluations do not have a built-in runner. It gives a compact example schema but no standard test harness or rubric format.
- Frontmatter constraints are Claude Skill format constraints. The source does not establish that other providers accept or enforce them.
- Package behavior varies by Claude surface. The linked code-execution page clarifies the API sandbox only; it does not independently establish current claude.ai installation behavior. Validate dependencies against the intended surface when using this checklist there.
- Named models and runtime details can change. Recheck the live docs before turning any provider-specific point into a durable audit rule.
