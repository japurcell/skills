# T4 historical status source-process evidence

T4 adds the informational `status` command and bounded last-scan storage to the standalone source CLI. Work began at `261267c27c42f0267f445f986b429dd1515f040d` and rebased cleanly with restored autostashed edits onto the integrated T3b-R repair, `9c15d10e7e6deb39cd330a08c7119906ddabc6ab`, then onto the integrated T3b-A repair, `5e637a080aeaaf717e344bfe12af8f3a7d66394e`. The isolated branch is `codex/design-b-t4`; evidence was collected on 2026-10-15 using macOS 26.7.1 build 25G241, Python 3.14.6 and Git 2.54.0 (Apple Git-157).

This node does not install anything into a real home, enable hooks, change trust, activate provider lifecycle events or implement publication gates. T3c owns installed neutral packaging. The primary owns plan/registry changes and the single coordinated KB pass. Native Windows ACL/locking/junction execution, installed-bundle proof and authenticated provider delivery remain unverified.

## Public contract

Use the executable `scripts/scan-secrets.py` or initially invoke `python3 -I -S -B scripts/scan-secrets.py`. The protected initial invocation avoids ambient Python startup code and bytecode writes. Convenience re-execution through an already unisolated Python cannot undo startup code that already ran.

`status --repo PATH [--json]` defaults to the current directory. It accepts the common `--json`, `--no-input`, `--quiet` and `--no-color` options before or after `status`. No arguments and `help`, `--help`, `help status` and `status --help` remain read-only help routes. Unsupported options, abbreviations and arguments return 3 without echoing supplied values. `--version` identifies both check and status schemas, the scanner version and policy version.

Exit 0 from status means valid information only. Outside a repository, the response is `not_scanned` with `not_repository`; an identified worktree without a report returns `not_scanned` with `report_missing`. Existing corrupt, oversized, unreadable, unsafe or incompatible reports return 2. A historical finding or incomplete scan is still a valid informational response. Closed output pipes fail without a traceback. Human errors remain on stderr; JSON requests produce one `scan_secrets_status_v1` object on stdout, including under `--quiet`.

Every status result explicitly describes historical information and sets `historical: true` and `authorizes_publication: false`. A saved result contains its completion time and selected scope; human output names both. A missing/unavailable result says no saved time or scope is available. Status never claims freshness, checks whether the current content matches the earlier capture or grants publish permission. Editing content after a scan leaves the report unchanged until another explicit scan completes.

Status loads only the parser, independent `scan_status.py` helper and dependency-neutral `scan_native_file.py` filesystem primitive. It neither imports detector/Git acquisition modules nor launches Git, enumerates the index/content, opens repository configuration/content, accesses a network API, reads stdin, writes reports/config/audit, starts retries, waits for a running scan or leaves background work. A public process still returns the existing historical result after all engine helpers are removed from its copied bundle. An actual Python audit sentinel rejects subprocess/network calls, repository/data enumeration, source/index/config reads and write syscalls; the status result still passes with the sentinel active and an open stdin pipe.

## Identity, report schema and storage

Metadata discovery reads only bounded `.git`/`HEAD`/`commondir` metadata, with at most 4096 bytes per file, at most 128 parent steps and a two-second operation deadline. It ignores inherited `GIT_*` repository redirects. The identity is SHA-256 over canonical common-Git-directory and worktree-Git-directory path bytes separated by NUL. Separate Git directories and linked worktrees remain distinct. Meaningful trailing spaces in Git metadata paths are preserved; only trailing CR/LF record terminators accepted by Git are removed. On macOS, a bounded 1024-byte `F_GETPATH` directory-descriptor operation supplies actual path spelling, preserving identity across case aliases without assuming a case-insensitive volume.

Explicit checks retain the canonical paths already acquired by their protected repository context. Persistence does not rediscover those paths after inspection, so changing a `.git` pointer during the later audit phase cannot attribute the scan to another worktree. Those internal filesystem paths never enter public status JSON. Early failures without an acquired context can still use bounded metadata discovery to save incomplete history when possible.

Each report is `scan-secrets/status/<worktree-digest>.json` under the standard data root: explicit absolute `XDG_DATA_HOME` on Unix/macOS, otherwise macOS `~/Library/Application Support`, other Unix `~/.local/share`, or Windows `LOCALAPPDATA`/`~/AppData/Local`. Reports are outside the scanned worktree and executable bundle. Physical ancestor identities prevent case aliases from bypassing that containment. POSIX status traversal opens every path component with no-follow directory descriptors; it does not resolve the user-selected hierarchy again after validation. The root-owned macOS `/var` and `/tmp` system aliases remain supported.

The stored schema is `scan_secrets_last_scan_v1`, limited to 65536 bytes. It has exactly these allowlisted fields: schema, worktree identity, UTC completion time, completion wall/monotonic nanoseconds, scanner/policy/build versions, selected scope, captured scope digest, outcome, content security outcome, coverage, eight safe count fields, safe reason code, audit outcome and status outcome. Duplicate/unknown/missing fields, unsupported schema/policy, malformed digest/time/version, inconsistent outcome/counts and unsafe scalar types are errors. Findings, matched values, filenames, contents, patches, raw exceptions/child stderr and credential URLs are excluded. Even an existing record containing fake credential values or raw URLs produces only a safe unavailable reason.

POSIX app/status directories are owner-only 0700; reports and stable per-report lock files are 0600. Regular-file reads/writes verify ownership, file type, no symlink/reparse point and link count exactly one before mutation. Existing permissive/unreadable storage is rejected without read-side chmod or repair. Hardlink controls use otherwise-private 0600 tracked-source inodes so rejection cannot pass only because of a separate permission failure. Atomic replacement uses a fresh private exclusive temporary file and a stable bounded nonblocking writer lock. Readers never acquire the lock. Explicit scans may replace malformed display bytes, but readers never repair them.

The Windows path uses native token/security-descriptor APIs for owner validation and a protected single-owner DACL on status-owned directories/files. The existing audit-created application parent is validated as a container owned by the current user; it is not assumed to have the status child's private DACL. Security API failures stop storage instead of applying a null DACL. DACL creation is restricted to actual exclusive file creation; a read-only absent-record race cannot cause ACL repair. Absent stable lock creation uses exclusive open and bounded retry through existing-file checks. This is source implementation only: actual Windows ownership, ACL inheritance, locking, reparse and atomic-replacement behavior remain unverified. The macOS reparse test injects the OS reparse attribute at the stat boundary and is not native Windows proof. The Windows adapter uses T3b-A's dependency-neutral `scan_native_file.py`: child opens and name mutations are relative to held native directory handles. Owner/DACL operations use `GetSecurityInfo`/`SetSecurityInfo` on verified handles, not paths, and extra owner/DACL mutation rights are requested only for exclusive new status objects. Existing/readonly objects request validation rights only. No-delete sharing alone was rejected because it does not exclude in-place reparse changes. The standalone loader captures the native source with the required check modules before audit execution and includes it in the build digest. Status loads that filesystem dependency directly without detector imports. Early failed checks load it once at their persistence boundary when no successful capture exists. No Windows execution is claimed.

## Independent outcomes and completion ordering

Only explicit `check` executions persist status in this node. Clean, finding and incomplete scans write history when possible, including an unavailable detector helper or a later unsafe candidate. Required-audit failure retains the content coverage/security outcome but makes the command incomplete with exit 2. Display persistence failure reports its own `status_outcome`/`status_reason`, emits a safe stderr diagnostic and retains the correct content/audit result and check exit. A missing status helper therefore cannot erase a finding or turn it into a new security outcome.

A check captures the optional status source bytes once and includes those exact bytes in its build digest before compiling that captured source at persistence. Replacing the on-disk helper after the initial read cannot execute a different helper under the earlier build identity. A missing optional status helper contributes an explicit missing marker to the build identity while content checking remains independent.

Completion metadata is captured before waiting for the report lock. Under a stable system clock, a delayed older writer observes the newer completion metadata and reports `superseded` instead of replacing the later completed result. UTC wall nanoseconds are the primary order and monotonic nanoseconds break ties. A system wall-clock rollback can affect ordering; this does not claim universal real-time order across clock corrections or boots, and no platform boot-ID machinery was added. Status remains historical information in every case.

Killing a writer immediately before replacement leaves the older complete report readable without waiting for its lock. The OS releases the killed writer's lock, so a later explicit scan can proceed. A force-killed process can leave its private bounded temporary metadata file; there is no background cleanup, and status does not enumerate or remove such files. Atomic visibility is not a power-loss durability guarantee. Ordinary failure paths remove their own temporary files.

Deadlines bound maintained read/write loops and nonblocking lock acquisition, not a hung kernel filesystem call. The functional suites use outer process watchdogs. Worktree enumeration/capture remains non-atomic, as in T3b; a saved complete result covers the earlier captured scope, not later edits.

## Retained red/green observations

- The first status process returned invalid-command exit 3. After dispatch and metadata-only discovery, missing reports and outside-repository results return valid informational exit 0 without creating a data directory.
- Clean/finding checks initially reported `status_outcome: not_attempted` and status had no last scan. Explicit persistence now records clean, findings and incomplete history, retaining an earlier finding when a later unsafe candidate prevents complete coverage.
- Two actual separate-Git-directory repos, `admin` and `admin<SPACE>`, initially shared an identity because `.strip()` removed the meaningful final space. The second repo displayed the first repo's finding report. Terminator-only parsing now keeps both identities/results distinct.
- A real separate-Git-directory marker ending in CRLF initially worked for Git and check but status returned `repository_metadata_invalid`. Removing only trailing CR/LF terminators now preserves the directory space and round-trips LF, CR, CRLF and repeated CR/LF variants accepted by real Git.
- Replacing the copied status helper after its initial read initially caused persistence failure by executing the replacement. Passing the captured bytes now writes status using the original implementation; the replacement execution sentinel remains absent.
- Swapping a real separate-Git-directory `.git` pointer at the actual audit-file open boundary initially saved repo A's finding result as repo B's last scan. Carrying the already captured repository context now leaves repo B unscanned and stores repo A's correct history.
- A filesystem-boundary substitution renamed the validated app directory and replaced it with an external-directory symlink. Re-resolving the user hierarchy initially reported a successful redirected write. The no-follow descriptor walk now returns display failure and leaves the outside directory empty while retaining the correct content result.
- An actual macOS alternate-case repo path initially returned `not_scanned` with another identity. Descriptor-based canonical spelling now returns the same historical result for real, symlink and case aliases. A case-aliased data root under the scanned worktree also initially passed status location validation; physical ancestor identity now makes status/check reject it before storage mutation.
- A configured data-root ancestor symlink initially let the existing CLI required-audit path write into its target and return clean. Owned CLI path prevalidation now rejects static redirected roots and preserves the target. The primary separately reproduced an audit ancestor-substitution race and routed T3b-A to repair the maintained writer. The final composed public suites now pass with that integrated repair; this macOS result does not prove native Windows behavior.
- Human missing-helper and missing-parser status fallbacks initially omitted the historical scan wording. Both now explicitly report unavailable last-scan time/scope while retaining stderr and versioned JSON contracts.
- An additional actual caller-boundary swap replaced a validated user data ancestor before full parent resolution. Even with the candidate anchored audit writer, full resolution still changed another repository's tracked source and its mode to 0600. Preserving the validated user hierarchy plus that same candidate writer passed the focused public copied-bundle control. The old unanchored writer remained red until T3b-A integration. The final source CLI now passes the retained public caller-boundary test with the integrated maintained writer.
- Removing the new shared filesystem helper initially let status return informational 0 on POSIX because it had not been loaded. Explicit dependency loading now reports safe runtime-unavailable exit 2 for status and incomplete check exit 2, with no traceback; help remains available. The missing-detector sentinel keeps this neutral primitive while removing all detector/acquisition helpers.
- The first concurrency fixture accidentally paused the required-audit lock, before status completion metadata existed. Its older process correctly finished later and wrote its result. Narrowing the actual OS boundary injection to the report lock tests the intended case: an older completed result delayed before persistence cannot replace the newer completed index result.
- A normal linked-worktree check without `extensions.worktreeConfig` initially failed at Git's worktree-config query. Original-owner T3b-R repaired that independent source-CLI bug. T4 then rebased over it and the linked status process tests passed without weakening their assertions.
