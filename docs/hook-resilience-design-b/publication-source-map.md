## Protected repository acquisition: useful isolation, incomplete publication boundary

**Observation.** [scan_repository:113](../../hooks/runtime/scan_repository.py#L113) rebuilds the environment from a small platform allowlist, supplies a private home, disables global/system config and optional locks, sets `GIT_NO_REPLACE_OBJECTS=1` and `GIT_NO_LAZY_FETCH=1`, disables fsmonitor/hooks/maintenance, and resolves one Git executable. Only discovery/config queries see original repository config. [Lines 146-169](../../hooks/runtime/scan_repository.py#L146) parse scope-framed config and select a small set of conversion/diff settings. This preserves ordinary and enabled-extension linked-worktree precedence without executing content helpers.

**Limits that T5 must resolve explicitly:**

- [Discovery:131](../../hooks/runtime/scan_repository.py#L131) requires a worktree/top-level and accepts SHA-1/SHA-256, but stores no public captured object-format field. [Lines 177-210](../../hooks/runtime/scan_repository.py#L177) copy only HEAD, raw index, bounded shared indexes, and selected attributes/excludes into the private Git directory. Original branches, packed refs, replacement refs and other publication refs are not copied. The incoming local/remote OIDs must drive traversal; neither this private HEAD nor live branch re-resolution supplies the transaction.
- [Line 210](../../hooks/runtime/scan_repository.py#L210) sets `GIT_OBJECT_DIRECTORY` to `common / "objects"`. It does not validate/freeze that root's ancestry, on-disk `objects/info/alternates` or their target roots, packs, or object availability as a complete graph. Ambient alternate-directory variables are removed by environment rebuilding, but that does not establish an on-disk alternate-store boundary. `read` at [line 65](../../hooks/runtime/scan_repository.py#L65) protects bounded regular metadata leaf reads and detects descriptor/content metadata drift; it is not a protected traversal of every original metadata parent or object-store root.
- Original shallow/graft metadata is neither explicitly rejected nor carried into the private view. No source check here establishes complete ancestry for outgoing tips or remote-old tips. A private view that omits those files is not evidence that unsupported source substitutions were rejected. B5 requires explicit handling before clean coverage can be claimed.
- Original config is queried with includes, while the reconstructed content view has no remote/filter/textconv definitions. This is a useful execution boundary, not permission to copy the original config into a publication traversal or uploader. `capture_git` without a repository context otherwise inherits ambient environment. Its `private_operation`/literal-diff branch strips `GIT_*` again and does not retain the explicit replacement/lazy-fetch settings at [scan_git:60](../../hooks/runtime/scan_git.py#L60); do not assume every capture mode automatically supplies the publication boundary.

**Candidate.** Extend or separate the protected acquisition preparation in `scan_repository.py` so publication receives captured format, canonical source roots and an explicitly supported object-store/history view while reusing the isolated executable/environment machinery. Keep index/worktree conversion preparation separate from immutable publication traversal. The exact supported alternate-store and metadata-race handling remains a production implementation/verification question; this map does not bless the current roots unchanged.

Public evidence boundaries: [CLI helper isolation:101](../../scripts/test-scan-secrets-cli.py#L101), [replacement objects:289](../../scripts/test-scan-secrets-cli.py#L289), [missing promisor object/no fetch:298](../../scripts/test-scan-secrets-cli.py#L298), and [ordinary linked worktree:217](../../scripts/test-scan-secrets-cli.py#L217) are pending/index tests. They do not prove publication refs, complete alternate graphs, shallow/graft rejection, or SHA-256 publication.

## Transaction input and complete graph selection

**Observation.** Production check/status deliberately do not read stdin. [D0 gate:67](d0/d0-probe.py#L67) reads up to 1 MiB plus one byte synchronously; [lines 90-104](d0/d0-probe.py#L90) validate newline framing, four fields, SHA-1 OIDs and a record cap, then check `.git/shallow`/`.git/info/grafts` through ordinary paths. D0 is a laboratory binding demonstration, not the production bounded reader: it lacks the adversarial open-pipe/terminal/two-second parser and generalized captured repository metadata.

**Candidate edit seam.** `scan_cli.parser/_main` and a transaction collector in `scan_git.py` need one bounded acquisition of original stdin plus destination arguments, format-specific OID validation, strict complete framing, and a transaction digest retained through result/handoff/replay. B4 fixes independent limits at 1,048,576 bytes, 4,096 records and two seconds absolute acquisition/parse time. Reject terminal/unavailable/malformed/trailing input; completed empty input is a valid no-op. Help/version must never enter this seam. Gate result validation must bind schema, action/scope/policy/build, digest and consistent exit status before any downstream action. A parser response, empty output, or mismatched result cannot pass.

**Observation.** No production outgoing graph collector or remote-old subtraction exists. D0 [lines 104-126](d0/d0-probe.py#L104) demonstrates nonzero local positives and same-transaction remote-old negatives; it captures each remote graph and checks availability before subtraction. [Lines 129-184](d0/d0-probe.py#L129) acquire supported object kinds and enumerate commit tree occurrences. The retained [transaction/path controls](publication-contract.md#transaction-and-delivery-binding) establish feasibility for the documented laboratory support set, including a secret removed in later history and a known blob reused under `credentials`.

**Required implementation boundary, unchanged from B5:** traverse all immutable nonzero local tips, including non-HEAD/explicit OIDs, multi-ref, tags, new refs and forced updates; deletions add no content. Subtract only fully verified local graphs reachable from nonzero remote-old OIDs in this transaction. Missing/unavailable remote-old history means conservative full-local traversal, with no fetch; missing required local content, malformed/unsupported objects and unsupported shallow/graft substitutions mean incomplete. A failed remote baseline probe must not contribute partial exclusions. Stale remote-tracking refs, unrelated local refs, current HEAD and a clean final tree are never baselines. Complete graph verification and fallback must share bounded acquisition/deadline accounting; they are not an unmetered preflight.

## Full bytes, messages and every path occurrence

**Reusable primitives.** [capture_git:23](../../hooks/runtime/scan_git.py#L23) captures stdout to a private regular temporary file, suppresses raw stderr, bounds input/output and child waits, checks descendants, and releases temp charges. Its contexts own captures; they are not reusable after exit. [VerifiedCapture.chunks/records:245](../../hooks/runtime/scan_git.py#L245) stream bounded ranges and terminated records with deadline/size validation. `run_git` at [line 287](../../hooks/runtime/scan_git.py#L287) joins the full capture and is appropriate only for bounded control output, not arbitrary history/blob bodies. Each Git call still has a five-second ceiling in addition to the scan deadline.

[Snapshot.classify:716](../../hooks/runtime/scan_git.py#L716) traverses all captured bytes for digest/classification before replay. [full_line_events:18](../../hooks/runtime/scan_stream.py#L18) and [scan_line_events:320](../../hooks/runtime/scan_stream.py#L320) provide the maintained full text/binary projection and token matcher. Reuse those rather than copying patterns or invoking worktree conversion helpers. [SnapshotSource.acquire:959](../../hooks/runtime/scan_git.py#L959) provides protected worktree spooling, but resolves staged candidates through the index and supports only blob snapshots. It is not a general commit/tree/tag graph source.

**Candidate.** Give the publication collector immutable object ranges and explicit occurrence records, then feed full captured blobs and selected commit/annotated-tag messages to the maintained matcher. Include intermediate history even when the newest tree is clean. Validate object headers/types/sizes/framing and tree occurrences before treating enumeration as complete. Trees supply paths, not diff additions. Direct blob/tree/tag tips need complete supported treatment or an explicit incomplete result; commit-only path enumeration is not sufficient evidence for every accepted tip form.

[Credential path rules:93](../../hooks/runtime/scan_engine.py#L93) and their insertion before tokens at [line 173](../../hooks/runtime/scan_engine.py#L173) can be reused. Run path policy for every relevant tree occurrence **before** byte-storage or token-scan dedup skips, including an already-published blob appearing at a new sensitive path. Preserve separate occurrence identity and object identity. Never collapse `(commit/tree occurrence, path, object)` into just an OID for filename rules or logical-byte accounting. Publication must not call `scan_diff_added_lines` or treat its pending suppression as coverage. Existing exact allowlist behavior is explicit in `ScanPolicy`; ambient hook skip/warn/allowlist settings must not become gate permission.

## Later LFS handoff and dispatcher lifecycle

**Observation.** There is no production pointer parser, LFS local storage resolver, verified uploader handoff, or dispatcher. D0 [pointer/payload acquisition:156](d0/d0-probe.py#L156) demonstrates strict SHA-256 pointer syntax, local size/digest verification, scanning protected bytes, and read-only private payload copies. [Dispatcher:241](d0/d0-probe.py#L241) owns the invocation directory across a separate scanner process, validates transaction identity and payload bytes again, replays original arguments/stdin to preserved hooks in order, invokes LFS with private `lfs.storage`, and removes the directory in `finally`. These are feasibility examples only: its ordinary `.git/lfs/objects` paths and whole-object `read_bytes()` calls are not production generalized storage/streaming/ownership proof.

**Candidate.** T6 can reuse protected descriptor/spool and full-stream primitives, but needs strict bounded pointer recognition, canonical supported local LFS acquisition, no download, declared size/hash verification, complete logical/capture/temp/count accounting, and a dispatcher-owned private store that survives scanner exit. Bind the short-lived handoff to this invocation/transaction and validate ownership, paths, schema, OID/size set and payload bytes before upload. Missing/corrupt/oversized/unavailable original or handed-off content must reject before upload while preserving known findings. Neither saved status nor an old handoff can authorize a retry.

The parent owns cleanup until downstream hooks and the controlled pinned uploader finish, including cancellation and descendant cleanup. An empty transaction must run no upload-capable downstream work. [B5/B6](ExecPlan.md#b5-publication-transaction-and-lfs-contract) require exact supported standard LFS hook recognition/replacement, preserving user-visible behavior and preventing a second upload from unverified storage; T7 owns installation and refuses custom/ambiguous composition. T5/T6 do not acquire permission to install hooks. The [D0 support boundary](publication-contract.md#decision-and-support-boundary) is macOS/SHA-1/basic HTTP only. Active-transfer cancellation, native Windows/Linux, SHA-256 publication, authenticated/other transports and host delivery require their own evidence or explicit refusal; this map supplies none.
