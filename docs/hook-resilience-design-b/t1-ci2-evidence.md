The existing public CLI observation test retains its 0.3-second ordinary case and 60-second stall, and adds a 0.65-second ordinary case to cover the scale of the observed 0.621-second metadata delay. The repair removes only observations whose preceding snapshot and fresh exact-child reap already establish no living owned descendants. Running children retain full-host discovery, retained ancestry, PID/group/start matching and post-leader cleanup. `/bin/ps` still returns only PID, parent, group, start and state metadata into a regular file bounded at 1 MiB. It never requests command text. On macOS/BSD, exact observer-child exit notification now uses `kqueue` before reaping that same `Popen` child, avoiding timeout busy-loop sleeps. Other supported POSIX hosts retain bounded `Popen.wait`. The new API was checked against the [official Python 3.13 select documentation](https://docs.python.org/3.13/library/select.html#kqueue-objects) and [Apple kevent manual](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/kevent.2.html): `KQ_FILTER_PROC` with `KQ_NOTE_EXIT` observes the registered PID's exit. The queue is explicitly closed; a PID that disappears before registration is reaped only through its exact child handle within the same remaining absolute wait allowance. An initial implementation incorrectly treated a kqueue as a context manager, failed closed before Git launch, and was corrected to explicit closing before any successful candidate proof.

Each metadata observation can use half of the unchanged absolute two-second cleanup envelope, clipped to its remaining deadline with a separate 0.1-second observer reap allowance. This one-second maximum accommodates the retained ordinary latency and leaves the overall invocation, child and cleanup deadlines unchanged. Help and recovery text state that allocation. No existing test watchdog or assertion changes. The 180-second invocation, 12-second child, two-second stdin, two-second cleanup and 256-observed-process limits remain. Verification-only live bytes, executable mode, index and status fingerprints, six independent active/candidate credential controls, redaction, cancellation and failure-closed results remain required. No automatic product retries or hook/trust/enablement changes are added.
