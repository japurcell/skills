## Effective Git configuration and repository identity

[discover:100](../../hooks/runtime/scan_status.py#L100) obtains bounded root/gitdir/common metadata without running Git. Content gate identity and historical status identity are distinct domains. The installer independently verifies Git's metadata view and evaluates configuration with NUL framing, origins, scopes and includes; it never mistakes scanner acquisition's neutralized hooksPath for the user's effective hook selection.

Normal repositories use repository scope. Already enabled worktree configuration requires explicit `--scope worktree`; installation never enables the extension or broadens sibling coverage. Shared multi-worktree scope and included local bindings are refused. Stable inherited/global includes and relative original hook paths are supported. Relative paths resolve from Git's hook-specific cwd, including receive-hook Git-directory cwd. Branch-dependent includes, URL rewrites, ambiguous destinations and unsupported managers are explicit refusals. [Git configuration 2.54.0](https://git-scm.com/docs/git-config/2.54.0) and [Git hooks 2.54.0](https://git-scm.com/docs/githooks/2.54.0) describe the underlying semantics; tested Apple Git 2.54.0 does not establish a new universal minimum or Git-for-Windows proof.

Installation records the previous direct binding and original effective hook selection. Runtime gates reject relevant inherited hook-selection drift while preserving unrelated setting edits. All original paths are validated before execution; an explicit install recaptures admitted original additions/edits. The exact Git filesystem identity is pinned, so an explicit reinstall must refresh a legitimate same-path Git replacement rather than incorrectly return a no-op.

## Composition, destination binding and uninstall

Complete owner-only generations live at `.git/scan-secrets/installations/<id>`, with a root phase journal, copied neutral bundle, all 28 launchers, bindings and private configuration backups. Old complete generations remain retained and valid until configuration promotion. At most 16 generations are admitted; reviewed retired generations require explicit archiving when that bound is reached. Unknown or changed owned content is preserved and diagnosed.

Identical desired state is a no-op. Changed explicit bindings/runtime selections create a new complete generation. Install after completed uninstall captures current original config bytes directly, preserving exact comments/order across repeated cycles. Prepared recovery refuses conflicting explicit selections with uninstall-then-install guidance. An unfinished retiring journal requires explicit uninstall recovery first. Exact journaled owned stale locks may be recovered under installer lock; foreign, partially changed or ambiguous locks are not guessed away. Unjournaled preparation is retained for review.

Uninstall removes only the still-owned configuration binding and retains generation/backups. It preserves unrelated current settings and original hook edits, restores originally absent config.worktree to absence, and can use a healthy external CLI when installed scanner helpers are missing. Changed/unknown owned bytes still require review rather than deletion. Original hooks are never copied to an execution path that would change `$0` or sibling-resource lookup. Their binary and duplex protocols remain inherited; they do not acquire scanner capture deadlines.

Pre-commit captures Git's actual selected index, including partial/alternate-index commits, and privately captures trusted current budget bytes. Pre-push selects an exact installed remote-name/URL binding. [run:199](../../hooks/runtime/scan_dispatch.py#L199) replays identical transaction stdin in declared order only after strict fresh result admission. Rejected pushes show bounded validated path/rule locations without raw child output, credentials or secret matches.

## Windows seams, implementation gaps and proof limits

[WindowsDirectoryHandles:12](../../hooks/runtime/scan_native_file.py#L12) is the canonical dependency-neutral native handle primitive. It holds ancestry, uses relative opens with reparse rejection, and provides native file identity/rename/delete building blocks. It does not own ACL, budget or scanner policy. [private:17](../../scripts/scan_install_windows.py#L17) and [PackageDirectory:127](../../scripts/scan_install_windows.py#L127) supply existing private DACL and package operations; their package limits and owner-only tree rules are not generic repository-parent mutation policy.

Accepted X3 identifies the remaining concrete gaps: fuller handle-backed ownership identities; shared private-directory/ACL/enumeration operations; Git config exclusive locks and sharing-safe promotion; a pinned staging cwd for CreateProcess rather than POSIX pass_fds/fchdir; Git-for-Windows shell/argv/shebang delivery; binary/duplex passthrough; and bounded native child-tree cancellation. Keep one shared native helper and one scanner/result policy. Native LFS needs complete proof or explicit refusal before transfer. Native repository mutation/dispatch currently refuse safely.

X3 inspected an evolving POSIX read set. Final T7b-P differs from its observed build in repository activation/ownership details, while the native helper, private directory, capture, dispatch and their native gaps remain byte-identical. Its snapshot coordinates are historical; the links in this map are current. Native source dispatch still requires bounded task decomposition and an actual Windows public-test environment. Only a Local macOS execution host is exposed; environment availability has been requested. macOS PowerShell, mocked NTFS, source imports and skips cannot establish Windows acceptance. Actual source/source-free installed positive and adversarial Git/NTFS proof remains mandatory.
