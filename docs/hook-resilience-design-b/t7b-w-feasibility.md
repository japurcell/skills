## Native choices and required refusals

Use held root/ancestor handles and one validated relative component for opens. Microsoft documents `NtCreateFile`'s `RootDirectory` relative resolution and exclusive `FILE_CREATE`; `OBJ_DONT_REPARSE` fails when parsing encounters a reparse. The existing helper also checks returned attributes and rejects regular files with multiple hard links. Retain both defenses. These support a local NTFS starting set, subject to proof. Refuse unproved UNC/network filesystems, device/extended namespaces, drive-relative paths, ADS, reserved DOS names, trailing dot/space aliases, case collisions and case-sensitive-directory ambiguity. Do not infer that `validate_name()` currently implements that complete path policy. Normal drive-absolute paths with spaces and Unicode need positive controls. [NtCreateFile](https://learn.microsoft.com/en-us/windows/win32/api/winternl/nf-winternl-ntcreatefile), [OBJECT_ATTRIBUTES](https://learn.microsoft.com/en-us/windows/win32/api/ntdef/ns-ntdef-_object_attributes), [Windows naming rules](https://learn.microsoft.com/en-us/windows/win32/fileio/naming-a-file).

Keep security decisions on held handles. The current ACL routine applies a protected owner DACL on creation, checks the current SID and exact private ACE, and validates trusted ancestors/creation parents. Reuse that implementation without broadening trust. New private files/directories must never be exposed through a permissive creation parent before ACL protection; either retain the verified safe-creation-parent rule or supply the explicit security descriptor at creation. Reject unsupported ACEs, null/broad DACLs, unsafe inheritance or inability to inspect ACLs. Do not treat `chmod(0600)` or readonly attributes as privacy. Existing config/original hooks need trust verification, not unsolicited ACL ownership changes. `SetSecurityInfo` operates on a handle, and a null DACL grants everyone access. [SetSecurityInfo](https://learn.microsoft.com/en-us/windows/win32/api/aclapi/nf-aclapi-setsecurityinfo).

Identity must come from the opened object. Record/check volume serial plus file index, regular/directory type, reparse attributes, link count, size, last-write/change metadata as available, owner SID/DACL admission and bounded content SHA-256. Compare before/after reads and before promotion/cleanup. [information:62](../../hooks/runtime/scan_native_file.py#L62) already exposes volume/index, size, attributes, links and timestamps; [stat:119](../../hooks/runtime/scan_native_file.py#L119) currently returns reduced metadata, insufficient alone for the candidate's seven-field manifest comparisons. Reconcile the ownership identity representation explicitly, without weakening exact ownership or changing T6 binding keys. File IDs identify an object, not its content or authority; retain the held lifetime, hashes and ACL checks. Microsoft documents volume+file index comparison and warns network responses may be partial. [GetFileInformationByHandle](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getfileinformationbyhandle).

Use the existing nonblocking byte lock for the installer, with a validated private lock file, fixed offset and symmetric unlock/close. Use a separate exclusively created `config.lock` for Git writers. `LK_NBLCK` raises immediately on contention; do not choose the retrying `LK_LOCK`. Do not remove a foreign/orphan lock based only on its name. Capture its exact identity in the recoverable phase and reclaim only an exact owned match under the installer lock. [Python msvcrt](https://docs.python.org/3.13/library/msvcrt.html), [Git lockfile protocol](https://git-scm.com/docs/api-lockfile).

Promote complete, flushed assets before config activation. Use same-volume held-parent `SetFileInformationByHandle` rename, choosing replacement only for validated owned targets; fresh generation promotion refuses an existing destination. `FILE_RENAME_INFO` supports a relative destination under `RootDirectory` and controls replacement. Its current helper opens a separate DELETE handle: close or deliberately share-delete the invocation's existing lock handle before rename, while preserving installer lock, exact identity and Git lock ownership. Otherwise Windows sharing can reject an operation that POSIX allows. Flush writable file handles before promotion and retain phase journals/backups; POSIX directory fsync is not a portable Windows durability proof. Test process-interruption recovery and do not claim power-loss durability from file flushing alone. D2 covers cooperating writers; arbitrary simultaneous direct replacement remains excluded. [FILE_RENAME_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_rename_info), [FlushFileBuffers](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-flushfilebuffers).

For staged `git config` editing, retain every ancestor and staging directory without delete sharing while passing its validated absolute pathname as child cwd. Under documented sharing rules this prevents ordinary rename/delete substitution during pathname-based process launch; validate identity before/after the child and fail on sharing/access errors. `CreateProcessW` takes a cwd pathname, not a directory handle, and Python `pass_fds` is POSIX-only. Never substitute a bare check-then-reopen pathname or use the process-global cwd. This is a supported API-based candidate requiring actual native substitution proof, not a verified solution. [NtCreateFile sharing](https://learn.microsoft.com/en-us/windows/win32/api/winternl/nf-winternl-ntcreatefile), [CreateProcessW](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-createprocessw), [Python subprocess](https://docs.python.org/3.13/library/subprocess.html).

Deliver extensionless Git hooks using the Git-for-Windows hook interpreter path established by the tested distribution. Candidate choice: a minimal LF shell trampoline invokes the pinned absolute Python interpreter, and the standalone stdlib passthrough invokes an ordinary original shell hook through a separately pinned trusted Git-for-Windows shell, with the original absolute hook path as its script argument. Preserve its `$0` and sibling lookup. Do not assume Python `CreateProcess` executes arbitrary extensionless/shebang files. Bound the supported original-hook interpreter set and refuse unsupported shebangs, batch/PowerShell hooks or managers until proved; do not reinterpret them through `cmd /c`, `shell=True` or file associations. Gate support cannot be accepted while ordinary supported original-path hooks are unavailable. Git documents hook cwd/argument/stdin contracts, but those alone do not establish this Windows launch path. [Git hooks 2.54.0](https://git-scm.com/docs/githooks/2.54.0), [CreateProcessW](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-createprocessw).

Use argument-list launch with absolute pinned executables, binary files/pipes and `msvcrt.setmode(..., O_BINARY)` wherever CRT standard descriptors are read/written. Preserve empty arguments, Unicode, quotes, backslashes and shell metacharacters across both trampoline and Python-to-shell boundaries. Inherit unrelated-hook stdin/stdout/stderr directly, including interactive/duplex protocols; do not pre-read or parse them as pre-push. For gated downstream steps, replay a fresh identical transaction byte stream in declared order and propagate each nonzero exit without reporting clean. Keep shared strict result admission and cancellation semantics, including explicit interruption exit 130. Python documents binary defaults, standard-handle inheritance and Windows argument conversion; those are building blocks, not proof of shell round trips. [Python subprocess](https://docs.python.org/3.13/library/subprocess.html), [Python msvcrt](https://docs.python.org/3.13/library/msvcrt.html).

For bounded scanner/dispatch/config children, prefer containment in a Job Object with kill-on-close, no breakaway, and assignment before the child can spawn descendants. The documented sequence is suspended process creation, assignment, then thread resume; integrate behind the existing shared capture/process seam rather than create another scanner runner. Assignment failure or incompatible host job constraints must refuse safely and clean up the suspended child. Nested-job behavior, cancellation signals, all-handle closure and survivor checks require native proof. Keep snapshot termination as a reviewed existing seam, not evidence that descendants cannot escape. Unrelated passthrough hooks retain inherited protocol delivery and need interrupt/exit propagation without a scanner deadline. [Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects), [AssignProcessToJobObject](https://learn.microsoft.com/en-us/windows/win32/api/jobapi2/nf-jobapi2-assignprocesstojobobject), [job limits](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_basic_limit_information), [creation flags](https://learn.microsoft.com/en-us/windows/win32/procthread/process-creation-flags), [ResumeThread](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-resumethread).

Native LFS upload remains explicitly unsupported until the complete checked-byte/uploaded-byte proof exists. Do not silently run the original standard LFS hook around that refusal. Native non-LFS dispatch must work independently. Preserve the exact T6 binding schema: `schema_version`, `build`, `repository_identity`, `budget_file`, `interpreter`, `data_directory`, `downstream_seconds`, `endpoint`, `lfs`, `steps`, `remote`, `url`. The location-bound budget is captured afresh each invocation. No saved result, manifest phase or handoff is publication permission.

## Indivisible invariants

An active config value implies a complete trusted generation, native usable gate launchers, preserved supported unrelated hooks, exact current destination binding and usable private storage. A native adapter pass or partial launcher pass cannot activate that binding early. Both installer and Git config locks remain held during their applicable transaction; recheck scope/identity/drift, preserve unrelated current config and original hook paths, retain private backups, and restore only the still-owned binding. Unknown files, original-hook drift, ambiguous includes/managers, unsupported worktree scope and ACL/namespace ambiguity cause bounded refusal, with safe actionable recovery text and no credential URLs in diagnostics.

Scanner/pre-commit/pre-push retain the same policy, selected-index/outgoing-object inputs, limits, checked-result identity, bytes and downstream ordering on all platforms. Preserve all 28 hook names and the unrelated-hook repair path. Cleanup touches only the held owned object/inventory with finite allowances; it must preserve substituted foreign directories. There are no background checkpoints, workers, queues, watchers, automatic scan retries or continuation turns. These obligations cannot be split away from final T7 acceptance.
