## Existing acquisition interfaces and coupling

- `capture_git(args, *, cwd, allow_nonzero=False, deadline=None, input_bytes=None)` lends `VerifiedCapture | None` only inside its context. It caps each command at five seconds and the shared deadline, redirects stderr to DEVNULL, uses owner-only regular temporary files, checks descendants after the parent exits, and retries only launch-time EAGAIN before any child ran. `allow_nonzero` recognizes only the exact HEAD/show-ref empty-output cases. `run_git` materializes only small control responses; blob bodies use ranges.
- `VerifiedCapture(handle, size, deadline, operation).chunks(offset=0, length=None, chunk_bytes=65536)` rechecks size/deadline and rejects short reads; `.records(separator, maximum=...)` requires terminated bounded records. These are borrowed handles, never paths to reopen later.
- `ScanBudget(deadline)` currently closes over `MAX_TOTAL_BYTES`; `.charge(size, operation)` and `.reserve_index(candidate, size)` share `used_bytes`. Index bytes are reserved before capture, once per `(source, path)`, not once per object ID. Replace globals with explicit validated limits without changing charge order during extraction.
- `SnapshotSource(root, candidates, budget)` resolves every index candidate to an immutable OID, validates `cat-file --batch-check` headers, then acquires batches that fit capture framing. A single object uses direct `cat-file blob` when framing would exceed the capture limit. `acquire(candidate)` lends `Snapshot | None`, classifies the entire content first, and invalidates the snapshot when its context exits. `None` is allowed only for a missing conflict worktree version. Worktree content is spooled once through a protected descriptor; matching replays that spool. Do not return live snapshots after context exit or reopen worktree paths for matching.
- The source currently relies on `SCAN_PHASE`, `SCAN_REPORT`, `SCAN_FINDINGS`, `SCAN_SECURITY_OUTCOME`, `INCOMPLETE_LOG`, build/provider/action and numeric globals. Replace these with invocation-owned state. Safe errors must retain the first cause even if failure reporting also fails.

## Matching and coverage: explicit hazard

`full_line_events(chunks, classification, check_budget)` and `diff_added_line_events(chunks, check_budget)` feed `scan_line_events(path, events, report, is_allowlisted, redact, check_budget)`. Events are start/data/end; chunks are bytes of at most 65,536. Classification covers the full snapshot, including late NUL/invalid UTF-8, before projection. Preserve logical line numbering, CRLF/Unicode separators, regex restart, greedy extension across chunks, and line/pattern order. Allowlist keys contain the full logical token, not a clipped prefix. Overlong keys cannot match. [allowlist.py](../../hooks/families/allowlist.py) owns exact space-only normalization and forbidden control/escaped-separator rules shared with Guardian.

The 100 retained-finding limit is display/storage truncation and can coexist with continued inspection. The 1,000 processed limit currently affects actual coverage:

1. `StreamReport.__init__/record_findings`, `scanner_stream.py:238-246`, set `stopped` at 1,000. `_StreamPattern.finish_match/feed`, lines 289, 298 and 310, stop counting/matching at the per-pattern cap.
2. `scan_line_events:339-340` continues draining events after `report.stopped` but skips further matching. Line-end processing breaks at lines 371-372; line-final validation at 378 is conditional on not stopped. Draining still validates late diff structure and deadlines, but does not inspect later tokens.
3. Legacy `main:1823-1824` breaks the candidate loop after a path finding reaches the cap, before that snapshot's token scan. `main:1838-1839` breaks after token scanning reaches it, leaving later candidates unacquired/unmatched.
4. `main:1862` records this only as `findings_truncated`; it still logs legacy `status=findings`. There is no independent complete-coverage field.

**Required T3 interpretation:** bounded displayed findings alone must not imply incomplete coverage; any actual early inspection stop must return `incomplete`, `coverage_complete=false`, with known redacted findings retained and an explicit safe reason. A finding does not establish full coverage. Keep the legacy adapter's native denial/warning presentation compatible while giving the new CLI truthful exit 2 for incomplete inspection. If implementation instead continues inspection with capped retention/counts, prove the continuation through later candidates and late validation; never mark complete merely because the current legacy log says findings. This is the selected plan's coverage rule, not a new universal scanner policy.

## Environment, persistence, and provider separation

Current hook inputs are `SCAN_MODE` (invalid means block), `SCAN_SCOPE` (invalid means diff), `SKIP_SECRETS_SCAN=true`, `SECRETS_ALLOWLIST`, `SECRETS_LOG_DIR`, `AUDIT_LOG_MAX_BYTES/BACKUPS`, normal HOME/USERPROFILE and temporary-directory settings. Gemini additionally accepts payload cwd then `GEMINI_PROJECT_DIR`. Copilot uses process cwd; Codex accepts payload cwd. `capture_git:308-311` copies the whole ambient environment and sets only prompt, askpass and literal-pathspec controls. It does not currently neutralize replacement objects or all inherited Git routing/configuration.

**Recommendation:** hook adapters translate existing settings into an explicit compatibility policy. `scan_cli.py` parses only B3's public options and trusted configuration, captures validated configuration bytes once, constructs explicit policy/budget/audit bindings and calls the engine. Never let hook warning/skip/ambient allowlist values authorize a CLI gate. New index scope must reject unresolved indexes; existing `collect_files(..., 'staged', ...)` deliberately includes conflict stages, so renaming that collector is insufficient. Pending worktree semantics and publication full-content policy remain separate. Publication environment hardening belongs to the D0/T5 contract, not an unreviewed X0 rewrite.

Two audit layers exist. `main:1711-1720` imports provider-local `helpers.audit.audit_init()` and fails closed on helper absence/init failure. [audit.py:131-140](../../hooks/families/audit.py) only prepares parent directories; scan-result persistence is the separate `append_scan_log` implementation. `append_scan_log:1328-1338` tracks security outcome before a later write can fail. `handle_unexpected_exception:1514-1545` retains prior findings, attempts an incomplete record, and independently reports audit written/failed without exposing raw errors. Preserve these independent dimensions in ScanResult. A status write is separate again (T4); it must not overwrite the security result or grant permission. Do not import provider `helpers.common` into the normal engine: it is hook JSON/transport behavior and optional observability, not a detector dependency.

Shared report redaction currently has a subtle dependency: `REPORT_SOURCE` is only `reporting.BODY_SOURCE`; `credential_label` arrives through `diagnostics.collector_source`. Extracting report functions alone must explicitly supply that primitive. [reporting.py](../../hooks/families/reporting.py) also owns NFKC/control filtering, label credential suppression before clipping and exact escaped-JSON sizing. Move/reuse shared bodies once for both scanner and Guardian; do not maintain a runtime fork. A small normal shared reporting/allowlist module is preferable to importing renderer strings at runtime. Keep the build-time `build_identity` renderer helper separate from these runtime bodies.

## Proposed small interfaces and safe extraction order

Recommended dependency direction: CLI/adapters -> engine -> protected Git acquisition. Engine never imports CLI, provider families, configuration templates, installed paths, stdin readers or provider helpers. Keep types/failure vocabulary in an acyclic shared location if both engine and Git need them.

- `scan_git.py`: explicit `CapturePolicy`/budget/deadline context, pending/index collectors, protected captures, `SnapshotSource` and borrowed `Snapshot.chunks()`. A collector returns ordered candidates plus a scope identity; it does not emit JSON or declare permission. Maintain full snapshots and added-line events as explicit inspection choices.
- `scan_engine.py`: `scan(snapshot_source, policy, budget) -> ScanResult`, using invocation state rather than globals. Result contains schema/build/policy/scope identities, coverage flag, outcome, safe findings/omission counts, acquisition/inspection counts, elapsed time and safe failure metadata. Result assembly preserves partial findings. Acquisition and persistence failure cannot become clean.
- `scan_cli.py`: `main(argv=None) -> int` owns argument errors (3), complete clean (0), complete findings (1), incomplete/required infrastructure (2), interruption (130), output streams and broken pipes. Load scan code only for actions requiring inspection; status is T4's bounded independent path. A `scripts/scan-secrets.py` bootstrap adds only its explicitly resolved source/bundle root before importing this CLI under `-I -S -B`.

1. Freeze public baseline observations and current tests. Move safe shared types/report/suppression bodies to normal source, preserving existing renderer behavior with build-time composition. Move streaming matcher and capture/acquisition code without changing patterns, ordering, byte charging or provider envelopes. Adapt internal component imports; keep public tests authoritative.
2. Replace legacy orchestration with one result-producing engine. Keep the provider entrypoint bootstrap/diagnostic bypass and native presentation as thin adapters consuming that same result. Remove old maintained bodies in the same slice, so additive compatibility means two entrypoints, not two implementations. Establish coverage semantics explicitly before claiming parity.
3. Add standalone CLI and source bootstrap. Expose new contracts intentionally (worktree/index, outside-repo failure, truthful exits, validated D0 budgets) without reusing skipped or exit-zero hook success. Exercise real processes, stdout/stderr, open stdin, interruption, hostile environment and late findings.
4. Integrator adds deterministic manifest-owned provider helper copies and standalone bundle closure; regenerate/check and verify installed execution with the checkout unavailable. Only switch lifecycle registrations after later gates and migration acceptance. X0 does not own those shared edits.
