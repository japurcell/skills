# Generate checked-in provider-local hooks from canonical sources

Shared hook behavior is maintained as canonical source under `hooks/` and rendered by `scripts/generate-hooks.py` into checked-in, provider-local Python files under `.copilot/`, `.gemini/`, and `.github/`. Generated files remain self-contained at runtime and never import across provider directories; this preserves runtime isolation while replacing duplicated human-maintained logic with one source of truth. Generated outputs carry a do-not-edit marker, pass `python3 scripts/generate-hooks.py --check`, and preserve provider behavior before a confirmed defect is corrected separately. Installers copy those checked-in outputs and never generate repository source. This model was chosen over cross-provider runtime imports, which weaken deployment isolation, and parity tests alone, which detect drift without removing duplicate maintenance.

Phase 1 owned 20 executable outputs across the three provider trees. Phase 2 added the Copilot and Gemini RTK forwarders, bringing the explicit manifest to 22 outputs. Both installers now run the read-only generator freshness check before changing an installation destination; a stale output stops installation with the exact `--write` recovery command, while an invalid generator source stops without write advice. The Phase 2 RTK family is 273 lines of canonical source in place of 420 manually maintained provider-script lines, a measured reduction of 147 maintained lines. The 26-suite maintained run and generator freshness checks passed on 2026-09-17. Temporary-home installer fixtures are installed-copy proof; the PowerShell fixture could not create a junction on its Linux host, so native-Windows junction behavior still needs a Windows-capable run. Real-home backup, installation, generated-file comparison, and executable checks passed. Live deployed Gemini `AfterAgent` delivery remains unverified and is tracked in `docs/generated-provider-hooks/handoff.md`.

Future generation candidates require at least two runtime outputs, meaningful shared logic beyond boilerplate, provider differences that fit explicit adapters, a continuing need for runtime-local files, and a net reduction in maintained complexity after accounting for the renderer. Similar filenames alone do not qualify a family for generation.
