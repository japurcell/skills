# Generate checked-in provider-local hooks from canonical sources

Shared hook behavior is maintained as canonical source under `hooks/` and rendered by `scripts/generate-hooks.py` into checked-in, provider-local Python files under `.copilot/`, `.gemini/`, and `.github/`. Generated files remain self-contained at runtime and never import across provider directories; this preserves runtime isolation while replacing duplicated human-maintained logic with one source of truth. Generated outputs carry a do-not-edit marker, pass `python3 scripts/generate-hooks.py --check`, and preserve provider behavior before a confirmed defect is corrected separately. Installers copy those checked-in outputs and never generate repository source. This model was chosen over cross-provider runtime imports, which weaken deployment isolation, and parity tests alone, which detect drift without removing duplicate maintenance.

Phase 1 owns 20 executable outputs across the three provider trees. Its full maintained suite and generator freshness check passed on 2026-09-17. A direct real-home installer smoke test was unavailable in that environment because `/root/.agents/skills` was read-only; temporary-home installer coverage remains the installed-copy proof. Deferred candidates require the Phase 2 admission test in `docs/generated-provider-hooks/EXEC_PLAN.md`; they are not approved merely because they have similar filenames.
