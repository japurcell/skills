# Make agent guidance and local hooks reliable across providers

This ExecPlan is a living document. Keep `Progress`, `Surprises & Discoveries`, `Decision Log`, and `Outcomes & Retrospective` current as work proceeds. Follow `.agents/skills/exec-plans/SKILL.md`.

## Purpose / Big Picture

Agent sessions currently expose a misleading RTK notice, can miss broken Markdown, and have inconsistent security feedback. A Windows session-end secret scan can stall, while guidance can cause wasted reading or misplaced scripts. After this plan is implemented, local Copilot CLI and VS Code, Gemini CLI, and Codex agents will have the agreed guidance and hooks. A user can see concise Markdown diagnostics and security decisions, run explicit RTK commands without the false notice, and finish a stalled secret scan without waiting on a pipe reader. The plan also protects Git metadata and local edits as far as provider hooks and verified platform controls permit.

This plan covers all eight former Ready ideas. It creates one independently verifiable milestone for each and one shared hook setup milestone. It does not claim that a hook can monitor every child process or that a live Windows run is required to finish. The [Disposable Probe Files] guidance is intentionally narrower: only three instruction files change for that milestone, with no installer, agent-run, or Windows checks.

## Surprises & Discoveries

- Current `hooks/manifest.py` generates Copilot and Gemini Tool Guardian, scan-secrets, and RTK files, but no Codex equivalents. `scripts/install-codex-hooks.py` merges only a `SessionStart` group today. These are implementation dependencies, not evidence that Codex security hooks already work.
- `hooks/families/scan_secrets.py:176-265` uses a threaded pipe reader. On Windows, a descendant holding stdout open can outlive the parent, so `subprocess.run(capture_output=True)` is not a safe substitute: it also uses pipe communication. The replacement uses a regular temporary file and never waits for pipe EOF.
- The published RTK prerelease tag is `dev-0.50.0-rc.451`; its macOS arm64 archive matched SHA-256 `05a32507b07dc38bca835808deb8f32bd182446e8adc90b00209deda0404d321`. Its binary reports `rtk 0.48.0`, so the version string does not prove provenance. Stable v0.49.0 ignores `RTK_SUPPRESS_HOOK_WARNING`.
- Provider hook documentation and installed versions can differ. In particular, Gemini `AfterAgent` delivery and Copilot/Codex RTK rewrite payloads have not been proved in installed sessions. Record actual outcomes here before claiming final behavior.
- An initial milestone-1 patch to `AGENTS.md` and `.agents/memory/INDEX.md` was rejected by automatic approval review as weakening mandatory orientation and falling outside a three-provider-file scope. No edit occurred. The milestone's own scope names both files and preserves all edit-time guidance; retry only with a narrower patch that makes this explicit, or obtain user approval if review still rejects it.
- A narrower milestone-1 edit passed automatic review. It adds the read-only exception while retaining all edit-time orientation and end-of-session documentation requirements. `rtk test python3 scripts/lint-okf.py` and `rtk git diff --check` exited `0`.

## Context and Orientation

Work from the repository root shown by `git rev-parse --show-toplevel`; do not assume this author's worktree path is yours. First inspect `rtk git status --short`, staged and unstaged diffs, and untracked files. Preserve user work and do not reset or overwrite it. Read `.agents/memory/INDEX.md`, then `ARCHITECTURE.md` and `CONVENTIONS.md` for nontrivial edits, followed by each affected `.agents/instructions/<area>.md` and its matching known-issues/testing files. Apply the read-only exception only after milestone 1 changes the checked-in rule. Before source edits, follow `.agents/skills/exec-plans/SKILL.md` and the repository's `tdd` skill; at the end of an implementation work session run `update-agent-docs` once. No new dependencies are authorized.

The repository stores agent instructions for three providers in `.copilot/copilot-instructions.md`, `.gemini/GEMINI.md`, and `.codex/AGENTS.md`. `scripts/install.sh` and `scripts/install.ps1` copy them into each user's home directory; checked-in source changes do not instantly change a running agent. A **provider hook** is a local command that an agent application calls before a tool, after a tool, or before finishing. Copilot user-level hook JSON lives under `.copilot/hooks/`; Gemini user settings start at `.gemini/global-settings.json`; Codex's template is `.codex/global-hooks.json`, merged into the user's `~/.codex/hooks.json` by `scripts/install-codex-hooks.py`. A **provider envelope** is the JSON input and output shape for one provider event. Expected block or warning decisions must use the provider's structured JSON, with stdout reserved for JSON and exit `0` for normal control flow.

Canonical Copilot/Gemini hook code lives under `hooks/families/`. `hooks/manifest.py` names generated executable outputs under `.copilot/hooks/scripts/` and `.gemini/hooks/scripts/`; `scripts/generate-hooks.py --write` refreshes them. Never hand-edit an output with a `Generated from hooks/families/...` header. Extend build-time renderers and the manifest for Codex policy adapters in milestone 4; installed runtime files must never import a sibling provider's installed code. The current Codex `load-required-skills.py` startup hook is hand-maintained and remains intact.

The first installed scope is local Copilot CLI, VS Code's local Copilot hooks, Gemini CLI, and Codex on supported platforms. Copilot cloud runs repository hooks in a separate ephemeral sandbox and is outside the user-level Markdown and security notification milestones. Provider pre-tool hooks see tool calls, not every later effect of a script or child process. Copilot pre-tool timeouts are documented as fail-open; no rule in this plan may claim complete blocking in that case.

The user-approved test seams are public hook JSON input/output, the generated provider executable, temporary-home installer output, native provider display, and native Windows process behavior. Write a failing behavior test at one of those seams before each source change, make the smallest code change that passes, then repeat. Do not test private helpers merely because they are convenient or mirror implementation text in assertions. Milestone 3 is intentionally guidance-only and has no test seam. Test fixtures must use independent expected messages, exit codes, and file effects from the decisions in this plan.

Provider event names and limits matter. Copilot CLI uses lower-camel `preToolUse`, `postToolUse`, and `agentStop`; VS Code uses compatible Pascal-case variants and must be tested with its own payload. Copilot command hooks need `bash` and `powershell` entries for native Windows. Gemini uses `BeforeTool`, `AfterTool`, `AfterAgent`, and `SessionEnd`; its timeout configuration is in milliseconds. Codex uses `PreToolUse` and `Stop`, with `commandWindows` for Windows. Some Codex local tools bypass `PreToolUse` and `write_stdin` does not re-enter it. Test the deployed event and display behavior before relying on a final gate. Official contracts are at [Copilot](https://docs.github.com/en/copilot/reference/hooks-reference), [VS Code](https://code.visualstudio.com/docs/agents/reference/hooks-reference), [Gemini](https://geminicli.com/docs/hooks/reference/), and [Codex](https://developers.openai.com/codex/hooks); the instructions in this plan state the required behavior even if those sites are unavailable.
