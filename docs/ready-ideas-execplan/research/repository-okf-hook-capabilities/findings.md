# Repository-local OKF hook capabilities

Checked 2026-09-28 against current first-party reference pages. This is a design input, not a verified live compatibility matrix for every installed version.

| Surface | Repository-local placement and stop event | Trust and installation | Lint output and enforcement |
| --- | --- | --- | --- |
| Copilot CLI | `.github/hooks/*.json` with version `1`; `agentStop` fires after the main agent finishes a turn; `sessionEnd` fires when a session completes or terminates, including `/clear` (the `/clear` dispatch is detached). | Local hooks run on the developer machine. CLI asks the user to trust the working directory; configurations load at CLI startup. User hooks under `~/.copilot/hooks/` are separate and cannot supply the repo-local mechanism. | Command hook receives JSON on stdin. `agentStop` can write `{"decision":"block","reason":"..."}` on stdout to force another turn; the CLI overrides after eight consecutive blocks. Exit `2` is only a warning for most events. `sessionEnd` has no documented continuation decision, so it is suitable for reporting or logging, not an end-of-session gate. [Reference](https://docs.github.com/en/copilot/reference/hooks-reference), [trust](https://docs.github.com/en/copilot/how-tos/copilot-cli/set-up-copilot-cli/configure-copilot-cli), [setup](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/use-hooks). |
| VS Code Local harness | Workspace `.github/hooks/*.json`; native `Stop` fires as the current agent execution is about to stop, not when the whole session ends. No `SessionEnd` event is listed. Copilot-format files are mapped to Local schema, so the payload/decisions differ from CLI. | Hooks are in Preview. `chat.useHooks` is on by default; workspace hook execution requires Workspace Trust. User `~/.copilot/hooks/*.json` is separate. | JSON stdin; `Stop` can return `hookSpecificOutput: {hookEventName:"Stop", decision:"block", reason:"..."}` on stdout to require another action. Native commands have cross-platform `command` plus `windows`/`linux`/`osx` overrides, selected for the extension host (which may be remote). [Configure hooks](https://code.visualstudio.com/docs/agent-customization/hooks), [Local reference](https://code.visualstudio.com/docs/agents/reference/hooks-reference). |
| VS Code Copilot Agent Host | The selected Copilot harness uses Copilot SDK hooks and the GitHub Copilot reference; it is distinct from VS Code Local even when it discovers the same `.github/hooks/*.json`. | Agent Host and Local settings are separate. VS Code says to verify event availability against the selected VS Code version. | Use the Copilot `agentStop` contract above, not Local `Stop` output. [Configure hooks](https://code.visualstudio.com/docs/agent-customization/hooks). |
| Gemini CLI | Project `.gemini/settings.json` can configure `AfterAgent`, which fires once after a turn's final response. `SessionEnd` fires on exit or `/clear` but is best-effort asynchronous. | User hooks in `~/.gemini/settings.json` are separate. Trusted Folders is disabled by default; when enabled, untrusted projects ignore project settings. Project hook name/command changes are fingerprinted and warned as new or untrusted. | JSON stdin, with `prompt`, `prompt_response`, and `stop_hook_active` for `AfterAgent`. Exit `0` parses one JSON object from stdout; `{"decision":"deny","reason":"..."}` rejects the response and requests retry. Exit `2` sends stderr feedback and also retries; other nonzero exits warn and continue. `SessionEnd` ignores flow control. Default timeout is 60 seconds. Official examples cover Bash on macOS/Linux and PowerShell on Windows. [Reference](https://geminicli.com/docs/hooks/reference/), [overview](https://geminicli.com/docs/hooks/), [writing guide](https://geminicli.com/docs/hooks/writing-hooks/), [trusted folders](https://geminicli.com/docs/cli/trusted-folders/). |
| Codex CLI | `<repo>/.codex/hooks.json` or inline `[hooks]` in `<repo>/.codex/config.toml`; `Stop` runs at turn completion. `SessionEnd` runs for the main thread on archive/delete while open, normal close, or after 30 minutes idle with no connected client; merely switching conversation does not fire it. | Hooks are enabled by default. Project `.codex/` layer must be trusted; each non-managed hook definition must also be reviewed and trusted by hash with `/hooks`, and edits require renewed trust. User `~/.codex/hooks.json` is a separate source. | JSON stdin. On `Stop`, exit `0` requires JSON stdout; `{"decision":"block","reason":"..."}` or exit `2` with stderr asks Codex to continue via a new prompt. `SessionEnd` is advisory and synchronous, with a 1-second default and 3-second max timeout; its output cannot steer Codex or keep the thread open. `commandWindows` is available for Windows; commands otherwise run at session `cwd`, so repo scripts should resolve from git root. [Codex hooks](https://developers.openai.com/codex/hooks/). |

## Design implications and gaps

- Use a turn-end event to report OKF lint failures to the agent and optionally require another turn. An end-of-session event is too late to guarantee repair and, for Codex, is explicitly advisory. Keep deterministic lint in CI or a direct user command if the repository needs a hard merge gate. This is an inference from the contracts above.
- The surfaces do not share one event name, file schema, decision shape, or trust mechanism. A shared lint executable can be reused, but each provider needs a small configuration/adapter. VS Code Local's `Stop` must not be mistaken for `SessionEnd`.
- UNVERIFIED: minimum shipped CLI/VS Code versions for these current reference contracts, and whether a particular user's installed versions fire hooks in Git worktrees or headless runs. Validate with a live probe before relying on a deployment.
