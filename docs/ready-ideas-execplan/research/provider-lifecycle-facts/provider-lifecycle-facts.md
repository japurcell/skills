# Provider lifecycle hook facts

Checked 2026-09-28 against current first-party references. This is a planning input, not a live compatibility test of every event or renderer.

## Event coverage and likely call rate

| Provider | Documented events | Events that can fire at tool frequency or higher |
| --- | --- | --- |
| Copilot CLI | `sessionStart`, `sessionEnd`, `userPromptSubmitted`, `userPromptTransformed`, `preToolUse`, `postToolUse`, `postToolUseFailure`, `permissionRequest`, `agentStop`, `subagentStart`, `subagentStop`, `preCompact`, `notification`, `errorOccurred`. The CLI supports all listed events; cloud agent has different behavior. [GitHub reference](https://docs.github.com/en/copilot/reference/hooks-reference#hook-events) | `preToolUse` before each tool; `postToolUse` after each successful tool; `postToolUseFailure` after each failed tool. `permissionRequest` can run for each permission request. `userPromptTransformed` runs for the primary and every preceding message in a batched submission. Asynchronous `notification` can occur on shell, agent, permission, or elicitation events; `errorOccurred` can repeat with errors. [GitHub events](https://docs.github.com/en/copilot/reference/hooks-reference#hook-events), [permission details](https://docs.github.com/en/copilot/reference/hooks-reference#permissionrequest-decision-control), [notification details](https://docs.github.com/en/copilot/reference/hooks-reference#notification-hook) |
| Gemini CLI | `SessionStart`, `SessionEnd`, `BeforeAgent`, `AfterAgent`, `BeforeModel`, `BeforeToolSelection`, `AfterModel`, `BeforeTool`, `AfterTool`, `Notification`, `PreCompress`. [Gemini hook reference](https://github.com/google-gemini/gemini-cli/blob/main/docs/hooks/reference.md) | `BeforeTool` and `AfterTool` bracket each matched tool. `BeforeModel` runs for each model request; `BeforeToolSelection` runs before model tool selection; `AfterModel` runs for **every streaming response chunk**, potentially much more often than tool calls. `BeforeAgent`/`AfterAgent` are turn oriented, while `Notification` follows alerts. [Gemini hook reference](https://github.com/google-gemini/gemini-cli/blob/main/docs/hooks/reference.md#model-hooks) |
| Codex CLI | `PreToolUse`, `PermissionRequest`, `PostToolUse`, `PreCompact`, `PostCompact`, `SessionStart`, `SessionEnd`, `UserPromptSubmit`, `SubagentStart`, `SubagentStop`, `Stop`, `Interrupt`. [Codex hooks](https://developers.openai.com/codex/hooks), [event enum](https://github.com/openai/codex/blob/main/codex-rs/hooks/src/lib.rs) | `PreToolUse`/`PostToolUse` run on supported local function tool invocations; `PermissionRequest` follows approval requests. A unified exec `write_stdin` poll does not repeat `PreToolUse`, but may deliver the original command's `PostToolUse`. Hosted tools such as `WebSearch` do not use this hook path; specialized paths may opt out. `Stop` and `SubagentStop` can recur through continuation, and compaction events depend on history pressure. ## User-visible output and latency constraints

- **Copilot CLI:** command hooks can stream `{"type":"progress","message":"..."}` JSON lines to the CLI timeline. `temporary: true` replaces the previous transient status and clears on assistant response. Progress is display-only, and one final non-progress JSON object remains the decision payload. The reference does not document a general hook `systemMessage` response field. Command and HTTP hooks default to `timeoutSec: 30`; output is bounded to 10 MiB per invocation. Command-hook timeouts are fail-open, including `preToolUse`. [Progress contract](https://docs.github.com/en/copilot/reference/hooks-reference#progress-messages), [configuration](https://docs.github.com/en/copilot/reference/hooks-reference#command-hooks), [output bound](https://docs.github.com/en/copilot/reference/hooks-reference#userpromptsubmitted--userpromptsubmit), [timeout semantics](https://docs.github.com/en/copilot/reference/hooks-reference#exit-codes-for-command-hooks)
- **Gemini CLI:** most hooks accept JSON `systemMessage`, documented as displayed immediately in the terminal; `stopReason` is displayed when `continue` is false. `BeforeToolSelection` expressly does **not** support `systemMessage`. `SessionStart`, `SessionEnd`, `Notification`, and `PreCompress` each document `systemMessage` output; `SessionEnd` is best effort and not awaited, while `PreCompress` is asynchronous. Hook stdout must contain only the final JSON, so the Copilot progress-line protocol is not portable. Command timeout defaults to 60,000 **milliseconds**. The official hook reference gives no explicit hook stdout byte cap, so that limit remains unverified. [Gemini common output](https://github.com/google-gemini/gemini-cli/blob/main/docs/hooks/reference.md#common-output-fields), [model hooks](https://github.com/google-gemini/gemini-cli/blob/main/docs/hooks/reference.md#model-hooks), [lifecycle hooks](https://github.com/google-gemini/gemini-cli/blob/main/docs/hooks/reference.md#lifecycle--system-hooks), [configuration](https://github.com/google-gemini/gemini-cli/blob/main/docs/hooks/reference.md#configuration-schema)
- **Codex CLI:** handler config `statusMessage` is an optional while-running message; JSON `systemMessage` surfaces as a **warning** in the UI or event stream, including on tool hooks. It is not a neutral progress line. Most command hooks default to 600 **seconds** and are synchronous unless configured `async`; `SessionEnd` and `Interrupt` default to one second and cap at three seconds. Background hooks deliver informational output at a later safe point, cannot control the triggering operation, and have an eight-concurrent-hook session limit. Model-visible output spills above roughly 2,500 tokens by default to a file plus preview; this is a model-context threshold, not a proven stdout byte cap. [Codex config](https://developers.openai.com/codex/hooks#config-shape), [common output and spill](https://developers.openai.com/codex/hooks#common-output-fields), [background hooks](https://developers.openai.com/codex/hooks#run-hooks-in-the-background)

## Surface and evidence boundaries

- Copilot cloud agent is non-interactive: it does not surface notifications to a user; `notification` does not fire there, and `permissionRequest` may not fire or affect already-approved tools. A local CLI message policy should not be claimed for cloud agent. [GitHub surface table](https://docs.github.com/en/copilot/reference/hooks-reference#hook-events), [cloud environment](https://docs.github.com/en/copilot/reference/hooks-reference#cloud-agent-execution-environment)
- The user's report that installed `load-required-skills` messages appear is **live evidence for that installed hook and observed surface only**. It does not establish that other events, output fields, background modes, or provider versions show the same message. Verify chosen sparse-message events live in each local CLI before promising visibility.
- First-party documentation establishes potential invocation frequency and contracts, not measured overhead. In particular, the per-chunk Gemini `AfterModel` event, per-tool hooks, and Codex synchronous defaults deserve latency probes before any broad registration. [Gemini model hooks](https://github.com/google-gemini/gemini-cli/blob/main/docs/hooks/reference.md#model-hooks), [Codex background behavior](https://developers.openai.com/codex/hooks#run-hooks-in-the-background)
