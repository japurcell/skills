# Provider Hook Capabilities

**Question:** What can current user-scope hook contracts do for file and shell interception, visible warning or denial output, Windows, timeouts, and the limitations that shape Ready items 2–4?

**Method:** Read the current official documentation on 2026-09-22. Statements below are documented facts unless marked **Inference**.

## Capability matrix

| Surface | User-scope configuration and interception | Visible outcome | Windows and timeout contract | Material limits |
| --- | --- | --- | --- | --- |
| Copilot CLI | User JSON files are loaded from `~/.copilot/hooks/` (or `%USERPROFILE%\\.copilot\\hooks\\` on Windows). `preToolUse` matches `bash`, `powershell`, `create`, and `edit`; it may deny a tool. [`Hooks reference`](https://docs.github.com/en/copilot/reference/hooks-reference) | A hook may return `permissionDecision: "deny"`; command-hook exit 2 surfaces `stderr` and denies `preToolUse`. Progress JSON is shown in the CLI timeline. [`Hooks reference`](https://docs.github.com/en/copilot/reference/hooks-reference) | `powershell` is the Windows command field. `timeoutSec` defaults to 30 seconds. A timeout surfaces a warning but is always fail-open, including `preToolUse`. [`Hooks reference`](https://docs.github.com/en/copilot/reference/hooks-reference) | A command `preToolUse` error is fail-closed, but a timeout is fail-open; HTTP `preToolUse` failures are fail-open. Use `exec`/`args` only in CLI, and do not depend on that form for cloud agent. [`Hooks reference`](https://docs.github.com/en/copilot/reference/hooks-reference) |
| VS Code agent hooks | **Preview.** User files are loaded from `~/.copilot/hooks`. `PreToolUse` receives `tool_name`, `tool_input`, and `tool_use_id`; it can deny, ask, allow, or rewrite `updatedInput`. [`Agent hooks`](https://code.visualstudio.com/docs/agent-customization/hooks), [`reference`](https://code.visualstudio.com/docs/agents/reference/hooks-reference) | `permissionDecisionReason` is explicitly shown to the user. Restrictive decisions win: deny, then ask, then allow. [`VS Code hook reference`](https://code.visualstudio.com/docs/agents/reference/hooks-reference) | `windows` is a Windows-only override; `command` is cross-platform; `timeout` is seconds and defaults to 30. [`VS Code hook reference`](https://code.visualstudio.com/docs/agents/reference/hooks-reference) | An invalid `updatedInput` is ignored. Post-tool blocking cannot reverse an already-completed file/shell action. The preview contract may change. [`VS Code hook reference`](https://code.visualstudio.com/docs/agents/reference/hooks-reference) |
| Gemini CLI | User hooks live in `~/.gemini/settings.json`. `BeforeTool` matches built-in names such as `read_file` and `run_shell_command`, and can deny or rewrite `hookSpecificOutput.tool_input`. [`Hooks overview`](https://geminicli.com/docs/hooks/), [`reference`](https://geminicli.com/docs/hooks/reference/) | `systemMessage` is displayed immediately to the user in the terminal; denied `BeforeTool` reasons are returned to the agent as tool errors. Exit 2 blocks and uses `stderr`; other non-zero exits show a warning and continue. [`Hooks reference`](https://geminicli.com/docs/hooks/reference/) | Hook `timeout` is milliseconds, default 60,000. Official examples document Windows PowerShell hooks, and Windows may require a permissive PowerShell execution policy. [`Hooks overview`](https://geminicli.com/docs/hooks/), [`best practices`](https://geminicli.com/docs/hooks/best-practices/) | Hooks are synchronous, so every matching hook delays the agent loop. Hooks execute arbitrary code with user privileges; changed project hooks are re-trusted. Plain text on stdout breaks JSON parsing and defaults to allow. [`Hooks overview`](https://geminicli.com/docs/hooks/) |
| Codex | User scope loads `~/.codex/hooks.json` and inline `[hooks]` from `~/.codex/config.toml`. `PreToolUse` covers `Bash`, `apply_patch` (aliases `Edit`/`Write`), MCP, and most local function tools; it can deny or rewrite. [`Codex Hooks`](https://developers.openai.com/codex/hooks) | `systemMessage` is surfaced as a warning in the UI/event stream. `PreToolUse` denial uses `permissionDecision: "deny"` plus `permissionDecisionReason`; exit 2 plus `stderr` also blocks. [`Codex Hooks`](https://developers.openai.com/codex/hooks) | `commandWindows` is the Windows-only override. Timeouts are seconds: most hooks default to 600; `SessionEnd`/`Interrupt` default to 1 and allow at most 3 seconds. [`Codex Hooks`](https://developers.openai.com/codex/hooks) | Hosted tools such as `WebSearch` do not use the local hook path. `write_stdin` does not re-run `PreToolUse`. Specialized paths can opt out, so hooks are a guardrail rather than complete enforcement. Unmanaged hooks require explicit hash-based trust before execution. [`Codex Hooks`](https://developers.openai.com/codex/hooks) |

## Implementation implications for Ready items 2–4

1. A cross-provider policy can use pre-tool interception for shell and edit calls, but it must use provider-specific event names and tool names: Copilot CLI `preToolUse` (`bash`/`powershell`/`create`/`edit`), VS Code `PreToolUse`, Gemini `BeforeTool`, and Codex `PreToolUse` (`Bash`/`apply_patch`). This is a documented compatibility boundary, not a portable common schema.
2. Design visible denials as concise human messages. VS Code documents a user-visible denial reason; Gemini documents terminal `systemMessage` and error feedback; Codex documents UI/event-stream warnings; Copilot CLI documents timeline progress, surfaced `stderr`, and timeout warnings.
3. Windows support is documented for all four surfaces through platform-specific command fields or PowerShell examples. Automated rendering/schema tests can cover configuration selection; a live Windows checklist should confirm hook discovery, PowerShell execution policy, visible denial text, and timeout behavior. **Inference:** vendor docs do not establish that one live Windows run proves every provider version.
4. Treat timeout behavior as provider-specific: Copilot CLI is explicitly fail-open on timeout; Gemini documentation establishes a default timeout but does not state a universal timeout decision rule in the cited contract; Codex documents defaults and hook failures but does not state a `PreToolUse` timeout disposition. **Inference:** a policy that must block reliably needs local, bounded checks and an explicit failure posture per provider.

## Source notes

- GitHub’s Copilot reference covers Copilot CLI and cloud agent, not VS Code; VS Code behavior above comes only from the VS Code documentation.
- The Codex URL redirects to official ChatGPT Learn documentation. Its current runtime contract distinguishes local function tools from hosted tools.
- **Inference:** no described contract is an OS-wide filesystem or process monitor; each applies to provider tool invocations that reach its documented hook event.
- Configuration and behavior can change by installed provider version. Recheck the cited contracts before implementing generated output.
