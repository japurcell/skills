01

THE CORE RELATIONSHIP

Who does the thinking?

Your existing foreground agent reasons. agent-brain gives it a shared procedure and checked tools.

Recall

Interpret the task and retrieve the map plus applicable guidance.

Learn

Add or correct evidenced knowledge, then refresh affected guidance.

Dream

Review, reorganize and prune under the same evidence policy.

Where tokens go: semantic stages use the active agent's model context. The core launches no model, daemon or required maintenance subagent. Foreground execution still uses tokens; lower cost is a measurement question.
What about task subagents?

Optional, authorized task children get verified scoped context and return outcomes or candidates. The parent owns aggregate learning and its routine dream batch. A child stop does not create another full maintenance pass.

02

ONE OBJECTIVE, MANY TURNS

When does the work really finish?

Waiting for your answer or stopping a turn keeps an unfinished objective open.

Before work

Load applicable instructions, universal policy, a compact map and the retrieval procedure. Recover eligible pending work.

Before successful completion

Finish assigned task work, learn/refresh and any required due dream batch. A checked no-change result is valid.

Completion has evidence: a hook prompt, command exit or agent self-report alone cannot prove required semantic work ran. Missing context pauses only dependent actions. Interruption remains visibly incomplete.
What is automatic?

Certified integrations initiate required stages or register enforced obligations. You do not invoke recall, learn or dream manually. Native hook behavior is different per provider; paths that cannot meet this contract remain unsupported.

03

CONTEXT JUST BEFORE IT MATTERS

How does less context stay sufficient?

Retrieve the smallest complete unit that preserves the rule, its scope, exceptions and required references.

Example in this repository

You ask the agent to edit a skill

Startup still preserves the required INDEX and core-document order. Before changing skills/, recall obtains .agents/instructions/skills.md and applicable known-issue/testing guidance. A later hook change expands scope and retrieves hook guidance before that work.

Any explicit whole-document requirement still loads the whole document. Optimization cannot weaken policy.

Focused lookup

Stable section/document IDs, explicit routes and text search. Derived indexes can be rebuilt; Markdown stays authoritative.

Honest uncertainty

Established guidance comes first. Relevant conflicts/freshness warnings are visible. Unverified candidates are for investigation.

04

FROM OBSERVATION TO GUIDANCE

How does a lesson become trusted knowledge?

The agent proposes meaning. The CLI checks authority, evidence, current inputs and the actual result.

Evidence stays proportional

A low-risk tip can record the observed failure, successful workaround and applicability. Broader rules, corrections or pruning require stronger checks.

Learning can add nothing

A scoped review with required checks can produce no_change. An empty diff or a claimed “done” does not establish that result.

Active-agent guard: mutating learn and dream require valid integration-issued context. Unsupported direct invocation fails before mutation. Help and informational recall work everywhere.
What joins this pass?

Activated legacy update-agent-docs delegates to learn without duplicate execution. Optional source ingestion keeps one scanner/manifest owner and calls its focused ingestion procedure once. Repositories without ingestion need no source adapter.

05

FAILURE IS A VISIBLE STATE

What if the agent stops halfway through a change?

A recoverable change journal precedes writes. The next eligible event reconciles the actual files.

Safe reconciliation

Finish a valid prepared set, or reverse only safely attributable writes. Preserve unexpected edits and unresolved conflict records.

Bounded concurrency

One mutating owner per worktree. Duplicate events join the same obligation. Old ownership generations cannot publish.

Limits: default 30-minute renewable leases; three total attempts and at most one semantic repair. Tighter provider caps win. SQLite does not make multiple Markdown files atomic. Managed recall sees coherent guidance or an affected gap.

Recovery respects pauses and cancellation. An idle or closed provider session promises no execution until a validated eligible event occurs.

06

SMALL MAINTENANCE PASSES

How does maintenance happen without a background agent?

Due work waits for an eligible foreground completion. Each completion receives one bounded batch.

Keep review bounded

At most five primary units/candidates. Target 32 KiB of complete guidance, including references. An indivisible oversized closure runs alone.

Keep coverage real

Rotate quiet areas when available. Credit reviewed target revisions. New or changed inputs cannot hide behind old completion.

Keep pruning justified

Prune only error, obsolescence or complete redundancy. Age and inactivity prioritize review; they do not authorize deletion.

Two pending states matter: an unfinished assigned batch blocks work-session completion. Remaining unassigned cycle coverage stays pending and can run at later eligible completions. Urgent factual repair never waits for the routine schedule.
What gets cleaned up after 30 days?

Only closed, unreferenced operational records, unless recovery or validation still needs them. Pending work, unresolved candidates, required evidence and reversible history remain protected.

Plan source: ExecPlan / milestone 5 complete bounded dream batches without losing coverage

07

ONE KB, SEPARATE STATE

Which files are knowledge, and which are bookkeeping?

Keep existing Markdown in place first. A new repository starts with a minimal map and configuration.

Knowledge travels with the repo

Stable section/document units use compact JSON comments. Existing frontmatter survives. Protected or externally owned artifacts can be mapped without rewriting them.

Runtime stays local

Persistent ignored SQLite tracks this worktree's execution. It is not a second authoritative knowledge store. First version does not share writable KB roots across worktrees.

Setup is separate from install: setup plans changes; explicit apply enables matching certified paths. Preserve unrelated hooks, record inverse changes and reject stale plans. Consumers need neither hooks nor canonical hook families already present.
What ships as software?

One progressively loaded skill, a Python 3.12+ standard-library core, six commands (recall, learn, dream, setup, doctor, status), native adapter assets and platform launchers. Installation and diagnostics make no model calls.

08

BUILD, PROVE, THEN ENABLE

What do the 12 milestones deliver, in order?

Process tests prove shared logic. Native tests prove real provider behavior. Paired trials prove the product targets.

Shared foundation

  1. CLI, help, informational recall
  2. Complete units and metadata lint
  3. Automatic checkpoints and state
  4. Evidenced learn and safe recovery
  5. Finite dream cycles and retention

Integration and evidence

  1. Legacy and source-ingestion joins
  2. Thin native provider adapters
  3. Versioned install and reversible setup
  4. Offline acceptance and frozen live plan
  5. Native certification
  6. Paired pilot measurements
  7. Verified release and documentation
Targeted surfaces: Codex desktop, Codex CLI, Copilot CLI and Gemini CLI. Certify exact build/configuration, entry mode and child path separately. VS Code harnesses are deferred. Initial pilot: macOS ARM64 / local APFS. Native Windows live tests are limited to Copilot and Gemini.

How large is the live evaluation?

At least 60 paired observations per cohort: 40 isolated pairs plus two sequences of at least ten pairs each. Each sequence covers two full dream cycles and fresh-session checks. Seven initial cohorts imply at least 840 baseline/candidate task executions if all certify; additional critical probes or longer sequences can add runs. Freeze and publish exact counts and usage visibility before live authorization.
