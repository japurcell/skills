# Provider lifecycle capabilities

Research date: 2026-09-29. Current official web contracts were inspected; no provider was launched, configured, upgraded, or live-tested. Installed CLI, desktop, VS Code, and extension versions are unverified. This is a capability inventory, not an architecture selection.

## Contracts that materially limit automation

- Codex: user/project JSON or inline TOML and plugin hooks compose; non-managed definitions require hash-based trust. Matching commands run concurrently. Async output waits for a safe point or next user turn, never starts an idle turn, and is discarded on session end. `SessionEnd` excludes subagents and may follow 30 minutes closed/idle; switching chats is insufficient. Hosted web tools lack tool hooks. Transcript format is unstable. [Official hooks](https://learn.chatgpt.com/docs/hooks).
- Codex hooks are command or MCP execution rather than a promise that the model performs injected instructions. Plugin docs establish shared runtime applicability including ChatGPT Work and Codex, but scripts must exist in the execution environment; web installation does not deploy scripts. Installed desktop/CLI parity still needs a surface probe. [Plugin packaging](https://developers.openai.com/plugins/build/plugins).
- Copilot: repository, user, inline-settings, plugin and managed-policy sources exist. `type: prompt` actually submits work only at new interactive `sessionStart`, excluding resume and `-p`. Notification context can trigger idle processing. `/clear` end hooks run detached; subsequent CLI exit terminates unfinished work. Tool decisions and post-tool context are separate outputs. [Official reference](https://docs.github.com/en/copilot/reference/hooks-reference).
- VS Code: hooks are Preview. Local workspace `.github/hooks/*.json`, user `~/.copilot/hooks/*.json`, custom-agent and plugin scopes exist; trust and `chat.useHooks` apply. Compatible source formats are mapped into Local payloads, not provider semantics. [Configuration](https://code.visualstudio.com/docs/agent-customization/hooks). Local transcripts and common session identifiers are optional; transcript format is unstable. Exit `2` blocks, other nonzero exits warn; use event-specific JSON for context and decisions. Stop retries consume credits. [Local reference](https://code.visualstudio.com/docs/agents/reference/hooks-reference).
- Gemini: common fields include session ID, transcript path, cwd and timestamp. `AfterAgent` additionally supplies original prompt, final response and retry flag. `BeforeModel` can rewrite requests; `AfterModel` is per response chunk, not task completion. `AfterTool` context reaches the model; tool denials cannot undo side effects. [Reference](https://geminicli.com/docs/hooks/reference/). Only command hooks are supported; project/user/system/extension settings merge, and changed project name/command requires renewed trust. Malformed non-JSON stdout defaults to Allow. The overview's synchronous generalization has explicit asynchronous exceptions in the reference. [Overview](https://geminicli.com/docs/hooks/).
- Gemini subagents have independent context loops and are exposed as tools. This does not establish which ordinary hooks execute inside them or whether parent context injections propagate. [Subagents](https://geminicli.com/docs/core/subagents/).

## Repository evidence versus deployment proof

The [source-inspected baseline](../../baseline.md) remains the repository authority. Exact registration checks confirm Copilot `sessionStart`, `userPromptTransformed`, `agentStop`, `subagentStop`; Gemini `SessionStart`, `BeforeAgent`, `AfterAgent`; Codex project `Stop`, plus maintained global-template `SessionStart`/`Stop`. Codex source auto-ingest is not wired here. Required-skill injection and scanner state changes do not themselves execute semantic retrieval, integration, or maintenance.

Local [hook compatibility notes](../../../../.agents/memory/known-issues/hooks.md) record Copilot CLI 1.0.88 message-display limitations, Gemini 0.45.0 AfterAgent concerns, and Windows Gemini 0.60.0 event-entry differences at one versus two seconds. [Auto-ingest notes](../../../../.agents/memory/known-issues/hooks-auto-ingest.md) record Copilot first-prompt transformation before startup scanning. These are historical observations, not proof about today's binaries. Official current contracts support these event names but do not certify local handler execution, installation, trust, timeout enforcement, or output delivery.

Before claiming a guarantee, capture deployed product/version/harness, hook entry and completion markers, exact injected nonce visible to the model, first-prompt order, resumed and headless behavior, compaction recovery, final-answer retry, nested-agent behavior, timeout/failure handling, and graceful versus abrupt exit. No inspected contract guarantees maintenance after crashes, forced process termination, or unavailable scripts. Codex transcript-dependent logic and VS Code transcript-dependent logic require version-specific adapters.

[Harness configuration](https://code.visualstudio.com/docs/agent-customization/hooks).

- No direct contradiction was found in the explicitly version-scoped `.agents/memory/known-issues/hooks.md` observations. Newly documented capabilities do not prove deployment upgrades.

## Unresolved product decisions

1. Which Codex surfaces and VS Code harnesses are in the support contract, and which deployed-version probes are required for admission?
2. Must maintenance finish before a response, occur on the next turn, or run independently while idle? Injection, continuation gates, prompt hooks and detached cleanup provide different guarantees.
3. What fallback satisfies the product when hooks are disabled/untrusted, unavailable in nested agents, time out, or cannot finish at shutdown?
4. What identifies a task across turns/resume/compaction, and what bounds continuation cost? Providers expose sessions and turns, not this product's semantic task boundary.

These remain human decisions. Facts permit automatic event-triggered script work and several forms of context delivery; they do not establish a universal autonomous semantic-maintenance lifecycle.
