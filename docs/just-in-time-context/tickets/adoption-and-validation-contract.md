### Installation, migration, certification, and comparison

1. **Setup and activation (accepted).** The user accepts the recommended contract on 2026-09-30. Separate software installation from repository activation. Provide an inspection/setup plan, an explicit apply operation, and a read-only diagnostic command. The plan identifies knowledge mappings, managed registrations, prerequisites, and exact changes. Apply validates those inputs, preserves unrelated configuration, records reversible managed changes, and enables only certified provider paths. Repeating setup is idempotent. Setup and diagnostics do not call a model; automatic semantic stages begin through enabled integrations during actual work.
2. **Existing knowledge migration (accepted).** Start by mapping existing authoritative artifacts in place, including protected whole documents and explicit loading requirements. In the pilot, introduce section metadata only after authoring and lint support exists; convert selected documents where focused retrieval helps without changing meaning, scope, exceptions, or required reads. Do not require a wholesale rewrite or duplicate KB. Repositories without a KB receive a minimal map/configuration and grow knowledge from actual work. Baseline equivalence and required guidance remain acceptance gates.
3. **Certification and upgrades (accepted).** Record a support manifest for each tested combination of agent-brain/adapter version, provider build, operating system/filesystem, entry mode, permissions, and lifecycle configuration. Record the model/configuration separately for semantic and performance results. Native and fallback paths have distinct records, including child delivery when used. Enable automatic lifecycle guarantees only for matching certified combinations. An upgrade outside that record needs certification before re-enablement; report the unsupported path clearly rather than assuming compatibility. The initial platform/runtime and version freeze are specified below.
4. **Comparison structure (accepted).** Freeze the current workflow and evaluation fixtures before measurement. Run baseline and candidate in separate worktree-local state with equivalent initial knowledge, tasks, sources, models, and provider settings. Pair equivalent runs and vary their order. Include isolated task pairs and longitudinal sequences in which each arm performs its own maintenance, then test retained knowledge in fresh sessions. Count setup separately from task performance, but include every task-triggered recall, learn, dream, retry, repair, and recovery operation in the applicable workload. Concrete workloads, repetitions, instrumentation, and independent checks are specified below.

### Configuration, stage operations, scheduling, and durability

9. **Configuration and precedence (accepted).** Use .agents/context/config.json with schema_version, repository_id, knowledge_roots, mapped_units, startup, providers, source_ingestion, maintenance, limits, state_dir, candidate_dir, and history_dir. Map startup units in their required order; list native registrations and certification references under providers; disable unconfigured integrations. Default durable candidates/history to .agents/context/candidates/ and .agents/context/history/, with runtime state ignored at the accepted worktree-local location. A --config option selects an explicit repository configuration; enabled stages remain bound to its identity/revision. Presentation and search options may override defaults, but flags/environment/user preferences cannot silently override authoritative guidance, workspace identity, mutation scope, or certification. Reject unknown schema versions, malformed metadata, duplicate unit identities, and unresolved required references before publication. Setup plans identify their base revisions, exact managed changes, inverse changes, and certification inputs, and apply rejects stale plans.
10. **Cooperative stage protocol (accepted).** Use the same start, prepare, publish, and complete operations under learn and dream, with bare learn/dream equivalent to start when valid integration context exists. Pass the integration-issued handle through an invocation file; support JSON input from a file or --input - for stdin. Start delivers a scope-bound work package and progressively loaded procedure; it does not claim semantic completion. Prepare validates the foreground agent's proposed changes and evidence; publish performs only that checked change set; complete verifies the actual artifacts, required checks, and scoped completed/no-change/incomplete outcome. No-change skips publication but still needs review/check evidence. Common records carry worktree/work-session/task/agent identity, stage/attempt/obligation and ownership/input/context generations, scope, relevant revisions, checks, and evidence references. Portable history retains attributable forward/inverse changes, before/after hashes, and compact rationale/evidence. Keep source/applicability/verification notes proportional to the claim, without routine transcripts or a dedicated replay for every tip. Machine errors identify code, cause, affected scope, retry eligibility, and next action. CLI process success remains separate from verified stage/work-session completion.

11. **Lease, waits, and interruption defaults (accepted).** Give invocation registrations and mutating ownership leases a 30-minute lifetime. Renew through checked eligible integration events/operations while the binding remains active and valid; no idle heartbeat or model job is added. Completion, pause/cancellation, expiry, or changed binding revokes authority under the closed contract. Use a two-second cumulative contention-wait budget per deterministic CLI operation, checked with a monotonic clock and remaining lock timeouts. Transient retries use 250 ms then 750 ms delays within that wait budget and the shared three-total-attempt stage/event budget; at most one semantic repair remains allowed. Do not wait for another owner's whole lease: return a joined/pending or explicit incomplete result and continue independent work. Provider caps may lower these limits. Ctrl-C interrupts the CLI attempt promptly, allows up to two seconds of deterministic reconciliation where safe, and preserves pending/recovery state; a second interrupt exits immediately. Interruption of one CLI attempt is distinct from cancellation of the user objective. Use exit codes 0 for a successful command operation, 1 for execution/check failure or incomplete required stage completion, 2 for invalid usage/input/invocation, and 130 for Ctrl-C. Status queries can succeed while reporting pending work; command success never substitutes for semantic completion. SQLite busy_timeout is not a whole-operation deadline, and actual waits/overruns belong in measured task timing.

12. **Dream initialization and batch limits (accepted).** Activation sets the first routine review cycle due; the next eligible work-session completion runs its required batch. Use UTC calendar dates for the seven-day cadence, while human timestamps may render locally. Each routine batch selects at most five primary units/candidates and targets at most 32 KiB of UTF-8 guidance including required references, not a claimed model-token count. Reserve one slot for rotating quiet-area review when available. Keep units, exceptions, required references, and explicit whole-artifact reads intact. If one indivisible guidance closure exceeds the byte target, process that closure alone, mark the oversized batch, and measure all its cost; an undeliverable closure stays incomplete with whole guidance preserved. Urgent repair follows its existing immediate contract and is not deferred by routine limits. Full structural checks remain deterministic across mapped knowledge. Preserve finite cycle targets, revision-bound credits, later additions, and verified full-cycle clock reset. Treat these as initial configurable limits; change them only through a refrozen validation run if the accepted performance targets require it.

13. **SQLite and publication durability (accepted).** Use brain.sqlite3 in the configured worktree-local state directory, short transactions, journal_mode=DELETE, synchronous=EXTRA, and foreign_keys=ON on every connection before transactions. For the initial macOS target, request fullfsync=ON and validate the deployed SQLite/VFS/filesystem assumptions. Use remaining bounded lock waits rather than assuming busy_timeout bounds the whole operation. Journal before/after content and intent durably before canonical writes; prepare temporary files on each destination's filesystem, flush/sync content, replace individual paths, sync relevant directory metadata where the supported platform requires it, and verify files/references before completion. Managed retrieval exposes a coherent verified view or an affected gap during unfinished publication/recovery. Certification covers predetermined process-interruption and recovery points; OS/power-loss claims need their own documented/tested evidence. A killed process does not prove those claims. Preserve the closed no-group-atomicity, unexpected-edit protection, and next-eligible-event recovery contracts. [SQLite setting facts](../research/sqlite-settings/findings.md) describes the settings and evidence boundary; no probe is performed here.
