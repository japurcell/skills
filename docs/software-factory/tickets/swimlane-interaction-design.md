## Question

How should the UI expose arbitrary workflow structure, concurrent sessions, and human intervention without hardcoded stage columns?

Work with the human using the prototype skill when this ticket is selected. Existing HTML designs are reference material, not the answer.

Choose lane grouping, nesting, planned versus observed work, dynamic task insertion, session/attempt drilldown, active output, wait/failure/skipped states, and live versus historical navigation. Make any pause, steering, and approval controls match the decided human-control contract.

Use representative workflows: the default task graph, a review-only run, and a custom workflow with a branch and loop. Resolve through human review of a cheap interactive artifact; link that artifact rather than embedding it in this ticket.
