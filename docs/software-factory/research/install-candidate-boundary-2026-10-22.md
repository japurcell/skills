## Candidate construction and binding

Derive `MaintenanceSelection` inside `install.ts` from `VerifiedInstallSelection`, never take its digest as a user-supplied string. Use the manifest SHA as `targetReleaseSha256`; use sorted names `bundle`, `node`, and each selected qualified provider/helper in `artifactDigests`; SHA256 a canonical versioned serialization of release version, platform, exact manifest/archive digests, selected provider canonical paths, digests and modes, Windows helper selection, and target schema 7 as `selectionDigest`. Persist a private descriptor with those immutable external provider paths/modes. `beginRepositoryBootstrap` may retain its shape-only selection interface for controller tests, but a shape-only install claim cannot advance to install handoff or ready.

After Python authentication and `validateInstallSelection()`, call `beginRepositoryBootstrap(repository, derivedSelection, currentOwner())`. Under the returned Git-common `factory/`, create `install-candidate-<operationId>/` **absent-only and nonrecursive**. Require new private directory identity (device/inode plus canonical path), private permissions/ACL qualification, no links, and no preexisting target. Its exact children at bind are `install/`, `toolchain/`, and `candidate-receipt.json`; `install/runtime/` is the complete manifest-bound release bundle, `install/node/` is the extracted regular Node distribution with only the three exact POSIX convenience links omitted, and `toolchain/` contains the manifest-bound declaration/lock, installed closure, and `manifest.json`. Copy files with exclusive create, stream source and destination hashes, verify size/mode/identity after writes, flush files and owned directories, and revalidate the frozen source descriptor after copy. A source change, dirty Git index/worktree mutation, foreign candidate entry, linked destination, or ambiguous partial directory fails closed. A crash before binding retains the incomplete claim and partial tree for inspection; it is never adopted by a retry. Reclaim may rotate an unbound claim only if its deterministic candidate path is absent. A bound candidate survives token rotation only after full validation.

Run the candidate's direct Node and npm script from `install/node/`: POSIX `bin/node lib/node_modules/npm/bin/npm-cli.js`, Windows `node.exe node_modules/npm/bin/npm-cli.js`. Run `ci --ignore-scripts --no-bin-links --audit=false --fund=false --update-notifier=false` in the fresh candidate toolchain using its exact schema-2 lock, private cache and isolated user/global npm configs, controlled HOME/environment, no inherited `NODE_OPTIONS` or npm config, and no shell. An explicit offline mode must use `--offline` and refuse a missing cache; the normal explicit install may fetch only lock-integrity-bound artifacts. Reject declaration/lock changes, extra packages or files, links/shims, unexpected package versions/integrities, and incomplete platform optional closure. Record exact lock digest and validated closure inventory, then write `toolchain/manifest.json` with schema 1, Node 24.22.1, TypeScript 7.0.2 and `@types/node` 24.19.2 as `build.ts` requires. npm v11 documents frozen `ci`, `ignore-scripts`, `bin-links`, and user/global config precedence: https://docs.npmjs.com/cli/v11/commands/npm-ci/ and https://docs.npmjs.com/cli/v11/using-npm/config/ .

Keep Codex/Copilot source artifacts **outside** candidate, stage and replaceable old install. `installation-bindings.ts:104-123` validates their qualified source hashes/closure; do not copy provider packages, auth, home or config. Reject any selected provider source rooted under an old `factory/install`, current candidate/stage or another replaceable target. Bind canonical paths/digests/modes in the receipt; publication and installed adapter wiring later revalidate them. A non-stable source blocks that selected mode.

Add `CandidateBinding` to `store.ts` as `{ path: string; identity: string; treeDigest: string; receiptId: string; receiptSha256: string }`, with `candidate: CandidateBinding | null` on `MaintenanceIntent`, initially null. Add `RepositoryStore.bindInstallCandidate(input: { handle: MaintenanceHandle; candidate: CandidateBinding }): Promise<MaintenanceIntent>`: inside `BEGIN IMMEDIATE`, require exact claim ID, token, repository ID, operation ID, `kind === 'install'`, `phase === 'preparing'`, candidate null, no competing claim and deterministic `path === <common>/factory/install-candidate-<operationId>`, then persist the compact binding in `owner_claims.data`, enforce its existing 8-KiB bound and emit a bounded event. The verifier in `maintenance.ts` must compare the on-disk root identity, private regular receipt identity/hash, exact receipt operation/repository/claim/selection fields, full inventory/tree digest and no extras **before** this CAS and at every subsequent gate. Do not reuse `ownedReceiptId` (eventual installed ownership) or `backupId`.

The candidate receipt is separate from the 8-KiB marker/ticket. Version 1 stores receipt UUID; operation/repository/claim IDs; release manifest, Node archive/omission, and toolchain lock digests; external provider descriptors; root identity; sorted directory records `(relative path, mode)` and file records `(relative path, size, mode, sha256)` for `install/` and `toolchain/`; and a canonical tree digest. It excludes itself from the tree digest, then the claim binds its separately measured receipt SHA. Require **at most 8,192 total inventory entries, 512 MiB total regular bytes, 128 MiB per regular file, 512 UTF-8 bytes per relative path, 32 path components, and 8 MiB receipt bytes before JSON parse**. Reject duplicates/case-fold collisions, unsafe/Windows-reserved names, links/reparse/special entries, hard links, unknown fields, unsorted rows, non-safe integers, identity or mtime changes during streamed hashing and any extra file/empty directory. This deliberately accommodates the measured 5,888 archive members (at most 201,757,420 regular bytes) plus 652 toolchain files (32,728,715 bytes) and the bounded runtime, without changing `stageEvidence()` or the ticket/marker cap. If an actual selected bundle exceeds these limits, fail explicitly and revise the candidate contract after measurement; never silently relax stage bounds.

Extend `maintenance.ts` `assertRecordedIntent()` to shape-check nullable binding; `redacted()` may expose only path/identity/digest/receipt ID and hash, never tokens or provider-auth paths. Add `verifyBoundInstallCandidate(common, claim)` with a bounded read/parse/hash interface. `prepareMaintenanceHandoff()` requires a verified binding for `kind === 'install'`, copies that compact binding into `HandoffTicket`, and rechecks it after stage measurement before issuing the ticket. `consumeMaintenanceHandoff()` requires ticket-binding equality to current claim and fresh on-disk validation before owner transfer; a missing or changed binding refuses. `reclaimMaintenance()` validates any bound candidate **even in `preparing`** before owner/token rotation, and refuses an unbound but present candidate. `recordMaintenanceStage()` can validate the intact candidate before publication; the publication node must replace that check with ordered source/target receipt validation after moves begin. Likewise, reclaim after any partial move must validate the distributed inventory and step receipts rather than expect the original candidate tree to remain intact. Noninstall controller fixtures keep their current meaningful handoff behavior without a candidate. The marker remains the original bootstrap fact; `sameBootstrapOperation()` compares immutable operation/selection facts and need not acquire a mutable candidate copy.
