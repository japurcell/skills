# Pi 1.4.0 adapter feasibility, 2026-10-22

Decision scope: T8 Pi research only. This is a source-level candidate contract, not an implemented or qualified adapter. No Pi model request, credential inspection, authentication, native configuration change, global installation, or notification was made. Native Pi, Gemini CLI, and OpenCode qualification remain blocked while authentication is absent.

The [official v1.4.0 release](https://github.com/earendil-works/pi/releases/tag/v1.4.0) points to immutable commit [`4a080252f06caf63a525d7873c5d94d3c23887e0`](https://github.com/earendil-works/pi/commit/4a080252f06caf63a525d7873c5d94d3c23887e0). **Decision: refuse both factory `read-only` and `workspace-write` routes for Pi 1.4.0 today.** Pi's native tool allowlist is not a whole-process filesystem boundary. Its [1.4.0 security guide](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/security.md) explicitly says Pi, extensions and children run with the launching account's permissions, and project trust does not constrain tool access. The [isolation guide](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/containerization.md) distinguishes isolating the whole Pi process from isolating selected tools. Neither permission profile can be honestly claimed from `--tools` or the working directory. A future candidate needs an already accepted, measured whole-process boundary for the actual host, credentials and native extensions, plus authenticated conformance runs. This is a scoped refusal, not a claim that no OS sandbox can ever host Pi.

## Smallest candidate subprocess contract

If the permission gate is later met, use **one fresh JSON-mode Pi process per factory attempt**. The adapter owns the child, working directory, argument array, input bytes, timeout, stdout/stderr drains, artifact snapshot and final process reaping. Proposed stable arguments are `--mode json --no-session --provider <exact provider> --model <exact model id> --thinking <requested level> -- <one adapter-owned prompt>`; avoid `--continue`, `--resume`, `--session`, `--fork`, implicit model selection, `--api-key`, and credential-printing commands. `--no-session` gives an in-memory conversation, but does not suppress startup migrations or other configured side effects. A fresh child with a single prompt and no resume avoids intentional conversation reuse; it does not disable native user extensions or guarantee that they will not inject follow-up work. The CLI [mode guide](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/cli-integration.md) says JSON mode is one invocation and writes JSONL, while RPC is long-lived and accepts later commands. [Source: session selection](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/src/main.ts#L361-L448), [source: print/JSON runner](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/src/modes/print-mode.ts#L33-L162).

Model routing is a **requested** control until proved in the response. `--provider` requires `--model`; model lookup can still fuzzy-match, and `--thinking` overrides a model suffix but is clamped to model capabilities. Pin a full provider and exact model ID in factory configuration, reject ambiguous/unavailable startup, and compare every completed assistant message's `provider`, `model`, and reported `thinkingLevel` with the accepted route. Extensions can register providers or select a request model, so a launch flag alone is not proof of the effective route. Treat the actual provider/model fields as provenance and reject an unapproved route rather than silently charging or attributing it to the requested model. [CLI model options](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/cli.md#L52-L75), [model resolution source](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/src/core/model-resolver.ts#L440-L500), [message types](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/message-types.md#L80-L114).

Close the child's stdin for this one-shot form and pass exactly one prompt argument. Pi reads *all* non-TTY stdin before starting, trims it, and concatenates stdin, processed `@file` text and the first positional message **without separators**. `--` ends option parsing but positional arguments beginning with `@` are still interpreted as file references. A raw prompt beginning with `/` can execute an extension command or expand a skill/template; an extension `input` handler can also transform or handle the prompt before the model sees it. Prefix task data with fixed adapter-owned prose so it cannot begin with `/` or `@`, bound its size, and record the `message_end` user message as observed input. For an exact prompt or skill-use guarantee, this is still insufficient if native extensions may transform input; either qualify the installed extensions under the chosen trust policy or refuse. `--skill` only makes a skill discoverable, and skill metadata is advertised without full instructions until the model reads it or a `/skill:name` command expands it. Requesting or discovering a skill is not evidence that its instructions were followed. [CLI input reference](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/cli.md#L32-L41), [argument parser](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/src/cli/args.ts#L72-L93), [initial-message builder](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/src/cli/initial-message.ts#L20-L44), [prompt processing](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/src/core/agent-session.ts#L2093-L2140), [skills guide](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/skills.md#L40-L56).

## JSONL normalization and terminal result

The [1.4.0 JSON stream reference](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/json.md) specifies LF-delimited JSON objects, an initial `session` header in JSON mode, and events including `agent_start`, `turn_start`, `message_start`, `message_update`, `message_end`, `turn_end`, `agent_end`, `agent_settled`, tool execution, retry and compaction records. Split on LF bytes, allow a preceding CR, keep reading stdout to avoid backpressure, and store raw bounded records plus separately bounded stderr. The source [JSON runner](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/src/modes/print-mode.ts#L106-L127) emits a header before subscription and emits session events through [`toJsonEvent`](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/src/modes/json-event.ts#L1-L64). If startup throws before the runner, the stream may have no header, so classify it as failed launch rather than inventing a session.

For live display, append `message_update.assistantMessageEvent.text_delta` by `contentIndex`; `text_end.content` and then `message_end.message` are authoritative. Keep thinking blocks, signatures, image data, tool arguments/results and custom messages as distinct provenance, with appropriate redaction in the factory viewer. Do not expose private reasoning as a promised capability. Match `tool_execution_start` and `tool_execution_end` by `toolCallId`; `isError` is a tool outcome, not necessarily a terminal run failure, since Pi can recover and continue. Track retries and compaction separately. `agent_end` closes one low-level run, while `agent_settled` marks the end of its automatic recovery and queued work. The adapter must then wait for stdout EOF, child exit and owned descendant cleanup before closing the attempt. [JSON stream](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/json.md#L30-L196), [message types and usage](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/message-types.md#L49-L145).

**Terminal classification proposal:** a successful one-shot attempt requires one expected session header, a completed user message for the intended task, at least one completed assistant `message_end`, the final assistant message for the final settled run with `stopReason: "stop"`, `agent_settled.aborted: false`, no pending tool executions, no unresolved retry or compaction, complete JSONL through EOF, process exit 0, and a separately validated workflow result. `stopReason: "toolUse"` is intermediate; `"length"` is incomplete; `"error"`, `"aborted"`, or a nonzero process exit is failure or cancellation; `"deferred"` needs a separate retrieval contract and is unsupported here. A tool error that Pi explicitly recovered from need not erase final success, but preserve it in the trace and let the workflow gate decide. The 1.4.0 [message union](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/message-types.md#L80-L114) defines these stop reasons. The [runner source](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/src/modes/print-mode.ts#L139-L160) only assigns nonzero status for bad assistant stop reasons in **text** mode; JSON mode can exit 0 after an assistant error or abort. Exit 0 alone therefore cannot mean success. This stricter final-stop rule is a factory inference, not a native success event; it needs authenticated transcript fixtures.

There is no generic JSON-mode `needs_input`, approval request, or refusal status in this event union. A model's refusal is assistant text and can also end with `stopReason: "stop"`; classify it from a workflow schema or explicit model output contract, never from process exit. A permission extension can block a call and produce a tool error; this may be a denial, not a request for live approval. JSON and print modes have no extension UI. RPC exposes `extension_ui_request`/`extension_ui_response` for `select`, `confirm`, `input` and `editor`, but that is a **separate** long-lived protocol and must preserve exact installed extension semantics, cancellation and authorization before advertising `needs-input`. [Extension UI protocol](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/rpc-extension-ui.md#L1-L31), [extension mode behavior](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/extensions.md#L355-L377).

## Permission, native state and lifecycle blockers

`--tools read,grep,find,ls` is not a read-only boundary. In 1.4.0, `--tools` does not remove MCP tools unless an entry starts with `mcp__`; an MCP tool can remain reachable through codemode. `--no-mcp` disables built-in MCP support but not a replacement extension. `--no-extensions` suppresses discovered, configured and built-in extensions, including any installed permission gate or user behavior, so an adapter must not add it just to claim safety. Likewise, do not force `--no-approve`, `--approve`, `--no-skills`, `--no-context-files`, a new agent directory, or a replacement system prompt as a generic permission shortcut. These change native trust, configuration or instructions. Pi has no native `read-only`/`workspace-write` enforcement flag. [Tool and MCP options](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/cli.md#L112-L140), [resource flags](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/cli.md#L185-L215), [MCP exposure](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/mcp.md#L189-L254).

Project trust governs loading project settings, MCP, extensions, skills and packages, not what an already running tool can access. In JSON mode the built-in trust prompt cannot appear; an existing trust decision, global fallback or user extension chooses whether protected project resources load. Forcing `--approve` could activate unreviewed project code; forcing `--no-approve` could remove the user's native guards. Preserve the user's effective native decision and refuse when the required project resources or security behavior cannot be established. Context files can load regardless of project trust. Pi even reads the project `sessionDir` setting before trust resolution. [Trust source](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/src/core/project-trust.ts#L44-L105), [security guide](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/security.md#L25-L82), [configuration guide](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/configuration.md).

A Pi launch is also not guaranteed to leave native state untouched: [`main.ts:667-670`](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/src/main.ts#L667-L670) calls `runMigrations(cwd)` before runtime/session setup; [`migrations.ts:1-76,305-315`](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/src/migrations.ts#L1-L76) includes auth, settings, session, tool and keybinding migration paths. This audit did not inspect credential contents or run a launch to determine whether any migration is pending on this host. A future adapter must account for that possibility before starting Pi under the user's native profile; do not silently copy or rewrite the profile to evade it.

Pi's print/JSON runner handles `SIGTERM` and, on Unix, `SIGHUP`, calls `killTrackedDetachedChildren()`, disposes the runtime and exits. The shell helper tracks some detached subprocesses and sends a process-group `SIGKILL` on Unix, with a single-PID fallback; it uses `taskkill /T /F` on Windows. These are source behaviors, not a guarantee that arbitrary extension-spawned children, MCP servers, nested processes or late writes are gone. The factory must own the process tree, request graceful stop, enforce a bounded deadline, reap it, verify quiescence and snapshot workspace/config/artifacts only after shutdown. A replacement attempt gets a new factory attempt ID and fresh Pi session; never splice a previous partial JSONL stream into the replacement. [Runner signal handling](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/src/modes/print-mode.ts#L38-L66), [shell helper](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/src/utils/shell.ts#L194-L252), [RPC shutdown guide](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/rpc.md#L89-L96).

Raw JSONL and stderr, exact argv with secrets omitted, executable and source hashes, model/effort actually reported, trust/config provenance without credential values, outcome classification, tool-call lineage, process exit, and post-exit workspace diff are the factory artifact set. `--no-session` means Pi does not persist its own session transcript; the factory must durably capture the stream. Native `message_end` can contain user prompts, file contents, tool output, model responses and possibly credentials exposed during work, so apply the factory's sensitive-data handling before indexing or displaying it. A source code or shell tool event is not proof that an artifact exists or that all child writes have ended. [JSON stream](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/json.md#L9-L19), [Pi session security](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/coding-agent/docs/security.md#L88-L96).

## Gate before implementation or native support

1. Establish, on each intended host, a whole-process read-only or workspace-write boundary compatible with the user's normal Pi authentication, trust, extensions, MCP and configuration. Test actual file/network/process effects and preserve native security behavior. If the boundary requires turning off a user guard, changing account/profile or relying only on the built-in tool list, keep that route refused. This audit makes no universal OS sandbox claim.
2. With authentication supplied through the user's normal Pi setup, run controlled end-to-end fixtures for a plain answer, tools, recovered tool error, model error, output limit, abort, missing credential, refusal, extension UI gate, prompt transformation, model mismatch, retry/compaction, cancellation, force kill, restart and artifact closure. No such live call was authorized or performed here.
3. Only after those fixtures pass, bind the JSON process candidate to the factory event/result contract. Treat `needs-input` as unsupported in JSON mode; evaluate RPC separately if native interactive approvals are required. Keep explicit `unsupported_permission_profile` or `native_qualification_pending` dispatch errors until then.
