# OpenCode V2 adapter feasibility, source review (2026-10-22)

## Decision

**Retain OpenCode as a desired T8 harness, but do not register a qualified native mode yet.** The exact `@opencode/cli@2.1.3` V2 source supplies a plausible private, noninteractive run path and a richer private-server API. It does not by itself prove that either factory `read-only` or `workspace-write` profile is faithfully enforced with the user's native configuration, that all descendants are cleaned up on every platform, or that the released native binary behaves like this source. Native qualification is explicitly **USER BLOCKED**. Pure parser, policy-planning, and refusal fixtures can proceed without launching a provider. [V2 commands](https://opencode.ai/v2/docs/cli/commands), [pinned CLI command](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/packages/cli/src/commands/commands.ts#L376-L418), [factory adapter contract](../../../packages/software-factory/src/adapters/types.ts).

This is a source feasibility judgment, not a native acceptance result. ## Native process and transport

The V2 `run` command supports `--standalone`, `--server`, `--format default|json`, `--file`, `--model`, `--agent`, `--session`, `--continue`, `--fork`, `--thinking`, and permission-related flags. `--server` attaches to another server, while `--standalone` starts a private server. A factory-owned invocation should use a fresh private process, never attach to an unrelated background server. The CLI's `--auto`, hidden `--yolo`, and hidden `--dangerously-skip-permissions` all map to auto approval and are unsuitable for a mode that promises to retain user approval boundaries. [Command specification](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/packages/cli/src/commands/commands.ts#L15-L40), [run specification](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/packages/cli/src/commands/commands.ts#L376-L418), [run handler](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/packages/cli/src/commands/handlers/run.ts#L7-L30), [server resolution](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/packages/cli/src/services/server-connection.ts#L21-L52).

The standalone implementation spawns its own `serve --stdio --port 0` child in the startup directory, places a fresh random password in that child's environment, keeps a dedicated stdin pipe open as its ownership lease, reads a JSON readiness line containing the URL, and configures SIGTERM followed by a three-second forced kill. The stdio server binds loopback by default, removes its lease password from the environment inherited by agent tools, and shuts down on stdin EOF. This supports a process-owned route, but source alone does not prove that shell tools, plugins, local MCP subprocesses, persistent PTYs, or Windows descendants always remain inside the factory's owned process scope. The factory currently owns and stops one launched process/group; descendant cleanup must be observed natively before reporting `cleanup: complete`. [Standalone spawn](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/packages/cli/src/services/standalone.ts#L17-L56), [stdio server and lease](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/packages/cli/src/server-process.ts#L68-L108), [readiness and EOF](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/packages/cli/src/server-process.ts#L205-L244), [factory process management](../../../packages/software-factory/src/agents.ts).

`run` combines positional message text with piped stdin when stdin is not a TTY. It reads attached local files (at most 10 MiB each; only regular files), classifies UTF-8 text versus media, and submits the prompt as text plus prepared file attachments. The noninteractive client subscribes to events **before** prompt admission, uses a generated message ID and `delivery: "steer"`, and reconciles projected messages after waiting. This is a viable way to deliver the factory's explicit prompt, instruction text, and resource text through stdin, but must be bounded by the factory's 1 MiB stdin limit and independently captured. It does not prove OpenCode's own native skill loader selected any requested skill; `skillDelivery: native` stays unqualified. [Input and attachments](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/packages/cli/src/run/run.ts#L72-L80), [file preparation](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/packages/cli/src/run/run.ts#L185-L225), [event subscription and prompt admission](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/packages/cli/src/run/noninteractive.ts#L78-L102), [prompt submission](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/packages/cli/src/run/noninteractive.ts#L707-L724).

For `--format json`, stdout contains newline-delimited objects with `type`, `timestamp`, `sessionID`, and type-specific fields. The emitted kinds in this implementation are `step_start`, `text`, optional `reasoning`, `tool_use`, `step_finish`, and `error`. Text and tool events carry a `part`; errors carry `error`. A `step_finish` is an individual model step, **not** final success. `session.execution.succeeded` ends consumption without emitting a success record. `session.step.failed` and `session.execution.failed` set process exit code 1 and emit `error`; a user SIGINT sets 130; a non-user interruption generally emits an aborted error and sets 1. Pre-admission and setup failures also emit an `error` record with exit 1. Thus a decoder must require a clean exit, no native error or denied tool indication, one unambiguous valid final factory result, and complete capture; the stream alone cannot certify success or terminal lifecycle. Never treat a normal-looking last `text` or `step_finish` as authoritative success. [JSONL writer](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/packages/cli/src/run/noninteractive.ts#L99-L107), [event emissions](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/packages/cli/src/run/noninteractive.ts#L275-L286), [tool and step emissions](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/packages/cli/src/run/noninteractive.ts#L425-L545), [setup error output](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/packages/cli/src/run/run.ts#L248-L260).

The CLI follows child session parent links to reject permission asks and cancel forms belonging to its own subagents, while filtering ordinary output to its root `sessionID`. V2 API session records include `parentID`, and the list API accepts a `parentID` filter, so a private-server bridge could observe child relationships. The CLI JSONL stream alone does not expose a complete child session tree or a trustworthy child-inclusive usage total; record unavailable child telemetry as unknown. A private bridge must handle session/event pagination and concurrent child creation without borrowing events from another session. [Child ask ownership](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/packages/cli/src/run/noninteractive.ts#L139-L155), [root event filter](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/packages/cli/src/run/noninteractive.ts#L221-L243), [session parent schema and filter](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/packages/schema/src/session.ts#L28-L106), [list endpoint](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/packages/protocol/src/groups/session.ts#L103-L133).

Stop is local to the private invocation. The CLI intercepts SIGINT, requests `session.interrupt` for its root session, and marks 130; the factory must still close and prove absence of its owned process group. A remote `--server` target would outlive the CLI and its other sessions, so group termination and remote server shutdown are not interchangeable. The private API offers session `interrupt`, while the CLI's `--standalone` child uses the EOF lease for server teardown. Do not claim remote session cleanup or durable native permission callbacks after process death without separate evidence. [SIGINT handler](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/packages/cli/src/run/noninteractive.ts#L676-L685), [session interrupt API](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/packages/protocol/src/groups/session.ts#L685-L700), [connection modes](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/packages/cli/src/services/server-connection.ts#L21-L53).

## Permissions and configuration boundary

OpenCode V2's native permission actions include `read`, `edit`, `shell`, `external_directory`, `execute`, subagents, skills, web actions, and MCP tool names. Ordered rules use last match; configured denial is checked before saved approval. Built-in write tools call native `Permission.assert` for `edit`; shell checks scanned commands; MCP tools check their named action. A `deny` is meaningful native tool enforcement, though [OpenCode's own security policy](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/SECURITY.md#L11-L27) explicitly says the permission system is a user-facing control, not OS isolation. The factory itself does not promise an OS sandbox for all harnesses, so this statement is **not** a blanket reason to reject OpenCode. It is a reason to describe and test the exact tool-policy boundary instead of presenting it as filesystem or process isolation. [V2 permissions](https://opencode.ai/v2/docs/permissions), [rule evaluation](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/packages/core/src/permission.ts#L74-L88), [denial before saved approval](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/packages/core/src/permission.ts#L148-L177), [write check](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/packages/core/src/tool/plugin/write.ts#L74-L90), [MCP check](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/packages/core/src/tool/mcp.ts#L50-L73).

The CLI route **does not expose per-session permission rules on `run`**. By contrast, the V2 private API accepts `permissions` when creating or updating a session, and children inherit a parent's permissions. Native session rules are appended after agent rules; therefore a generated **allow** can override a user's earlier deny. A safe candidate is deny-only narrowing, with no synthetic allow, no saved `always` approval, and no `--auto`. But read-only still needs coverage of shell, Code Mode, plugin tools, and configured MCP tools; workspace-write still needs a proven worktree boundary. OpenCode's docs warn that shell commands run with host filesystem/process/network authority and that external-directory inference from shell text is best effort. The source also calls plugin permission hooks after built-in rule evaluation; that hook path must be qualified with the actual configured plugins and managed policy. [Run CLI creates session without permission payload](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/packages/cli/src/session-target.ts#L60-L79), [create-session API](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/packages/protocol/src/groups/session.ts#L153-L176), [child inheritance](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/packages/core/src/session.ts#L276-L304), [permission hook](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/packages/core/src/permission.ts#L160-L177), [shell and directories](https://opencode.ai/v2/docs/permissions).

Noninteractive `run` auto-rejects `ask` requests by default and sends model-visible feedback, allowing V2 to continue after a declined tool call. `--auto` replies `once` to asks but does not override a configured `deny`; it still broadens unanswered user approvals and is disallowed for this candidate. A denied tool can therefore be followed by plausible final text and exit zero. The adapter must detect permission-related failed `tool_use` records or use a private event/API bridge that sees explicit permission events; it must never convert native refusal into factory `needs_input` or claim success solely from exit zero. Question forms are similarly cancelled in the noninteractive path and are not durable factory questions. [Ask/reply behavior](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/packages/cli/src/run/noninteractive.ts#L159-L211), [tool failure JSONL](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/packages/cli/src/run/noninteractive.ts#L433-L480), [official approval semantics](https://opencode.ai/v2/docs/permissions).

Native startup/config side effects are separate from requested agent write permission. V2 discovers project, global, and managed configuration, and preserves configured agent instructions, plugins, MCP servers, providers, and policy when using normal discovery. Setting `OPENCODE_CONFIG_DIR` to an empty factory directory, disabling project config, or replacing the user's config would silently remove these guard and integration surfaces and is not acceptable as a default workaround. Conversely, preserving them can start configured local MCP processes and install missing package plugins during server startup, before the agent's requested `read-only` actions. The factory must document and qualify these as native launch effects rather than pretending its agent permission flag suppresses them. No global settings should be edited to run the adapter. [V2 config precedence](https://opencode.ai/v2/docs/config), [config discovery](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/packages/core/src/config/discovery.ts#L55-L150), [plugin startup](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/packages/core/src/plugin/supervisor.ts#L146-L183), [package install branch](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/packages/core/src/plugin/module.ts#L99-L123), [automatic MCP connect](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/packages/core/src/mcp/index.ts#L539-L558), [plugin docs](https://opencode.ai/v2/docs/plugins), [MCP docs](https://opencode.ai/v2/docs/mcp-servers).

Native hard policies can deny `tool.use` after ordinary permissions and saved approvals and should remain in force. The source gives organization policy the final say in policy evaluation; an adapter must neither strip those statements nor inject an allow that defeats user rules. An ephemeral deny-only policy layer may be explored, but its precedence, plugin hooks, and effect on user configuration need dedicated proof before use. [V2 policies](https://opencode.ai/v2/docs/policies), [policy hook](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/packages/core/src/config/plugin/policy.ts#L22-L67), [policy ordering](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/packages/core/src/managed-policy.ts#L50-L76).

## Bounded next work and refusal gates

The current factory `AgentAdapter` accepts one child argv/env/stdin and parses captured stdout/stderr. It has no public API for controlling a long-lived HTTP server or registering native session permissions. Consequently there are two possible future routes, each needing explicit qualification: (1) the simple `run --standalone --format json` route, if a deny-only ephemeral native policy and JSONL denial detection prove both requested modes without replacing configuration; (2) a factory-owned bridge process that starts `serve --stdio --port 0`, creates a session with native `permissions`, subscribes to events, prompts, interrupts, and emits bounded adapter records. The bridge would need its own lifecycle, auth secret handling, pagination, child tracking, and cleanup proof. The V2 API contains the required session-create, prompt, event, wait, and interrupt endpoints, but their existence is not an acceptance test for a bridge. [Factory adapter interface](../../../packages/software-factory/src/adapters/types.ts), [factory launch](../../../packages/software-factory/src/agents.ts), [V2 create](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/packages/protocol/src/groups/session.ts#L153-L176), [prompt](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/packages/protocol/src/groups/session.ts#L335-L354), [events](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/packages/protocol/src/groups/event.ts#L40-L51), [wait](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/packages/protocol/src/groups/session.ts#L459-L472), [interrupt](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/packages/protocol/src/groups/session.ts#L685-L700).

Work that can proceed while native qualification remains blocked is limited to deterministic fixtures and design checks: pin and verify the wrapper/platform package closure when an authorized native installation exists; model JSONL records for valid text, tool success/failure, `error`, missing/malformed/truncated lines, repeated `step_finish`, absent success marker, permission denial followed by final text, SIGINT, and process exit mismatch; prove the factory's final JSON contract rejects denial and ambiguity; map a deny-only policy proposal against `read-only` and `workspace-write` without changing real config; and test pure parent-child/session pagination mapping using recorded fixtures. Do not advertise these fixtures as native runtime proof. [JSONL implementation](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/packages/cli/src/run/noninteractive.ts#L99-L105), [factory adapter interface](../../../packages/software-factory/src/adapters/types.ts).

Native checks remain **USER BLOCKED**: execute only after explicit approval for provider execution/authentication and native installation. In a disposable worktree using the exact pinned platform package, verify read-only can inspect but cannot edit, write through shell, Code Mode, plugin/MCP, external paths, or child sessions; verify workspace-write can edit the worktree and cannot write outside the intended boundary or override a user/managed denial. Capture exact stdout/stderr JSONL and exit behavior for success, provider error, denied ask, configured deny, user interruption, child sessions, forms, and timeouts. Observe startup side effects, preservation of configured hooks/plugins/MCP/policy, server port/password handling, signal/EOF shutdown, and descendant cleanup on each intended OS. Do not infer a macOS result for Linux or Windows. If any required permission profile, result channel, or cleanup scope cannot be proven, `validateProfile` must refuse that exact mode with a specific diagnostic; OpenCode stays listed as desired but unqualified. [Security model](https://github.com/anomalyco/opencode/blob/bb25a2f4a3f3f04d7c344bec0c0574ea3510b3b1/SECURITY.md#L11-L27), [factory type contract](../../../packages/software-factory/src/adapters/types.ts).
