# T15b candidate preparer: npm cache and request contract

Read-only decision at integrated bootstrap `bc8d828a` plus reviewed registration `3648044`, 2026-10-22. This resolves the mismatch between the candidate packet's free `npmCache: string` argument and `/tmp/factory-install-preparer-interface.md`'s private request. Existing pins, release schema-2 authentication, candidate inventory, 8 KiB marker/ticket, and controller stage caps remain unchanged. This is no installation or test result.

## Decision

Keep all npm input state in the **same Python-owned `PrivateStage`** already holding the authenticated release snapshot and extracted Node (`skills/software-factory/scripts/install.py:137-222,681-707`). Create fixed absent-only children `npm/cache/`, `npm/home/`, `npm/user.npmrc`, and `npm/global.npmrc` there with private modes and empty configuration files. The copied selected bundle remains `stageRoot/bundle`, the selected archive `stageRoot/selected-node-archive`, and extracted Node `stageRoot/node`. Python records these identities and keeps the stage alive until the verified Node preparer and every owned npm child are closed. No cache, HOME, npmrc, npm log or downloaded tarball goes into `factory/install-candidate-<operationId>`, its receipt, `controller-staging/.../payload`, or a user home. `npm/cache` is a temporary tool input, never a second admission lock or installed artifact.

Amend `PrivatePrepareRequestV1` from `/tmp/factory-install-preparer-interface.md` with exactly one additional field:

```ts
npm: { offline: boolean }
```

Do **not** add caller-supplied cache/config/HOME paths or a cache digest to the request. Node derives the four paths above from the already checked `stageRoot`; verifies they are exact private nonlinked owned children before factory mutation and again before spawning npm; and rejects any extra npm config file in the candidate toolchain. Python's `prepare` command accepts explicit `--offline` (default false). An optional `--offline-cache-seed <absolute directory>` is allowed **only with `--offline`**, for disposable qualification. It is copied into `stageRoot/npm/cache/_cacache/` before writing the request. The seed path never reaches Node, the candidate receipt, or public output. Without a seed, offline preparation starts from an empty private cache and a cache miss fails. A normal explicit installation also starts with an empty private cache and may fetch only package URLs and integrity values bound by the selected schema-2 toolchain lock. No production cache parser/export layer, global cache reuse, automatic fallback or provider download is added.

This is a bounded file copy, not a cache format parser: Python requires a canonical regular `seed/_cacache` tree, refuses links/reparse/special entries, hardlinks, unsafe/case-colliding paths and changed source inodes or bytes while copying, and uses `PrivateStage.mkdir/create` for every destination. Cap the seed to 4,096 combined entries, 128 MiB regular bytes, 64 MiB per file, 512 UTF-8 path bytes and 32 components. The existing read-only qualification cache `/tmp/software-factory-npm-cache/_cacache` measures about 85 MiB, 66 files, 132 directories, no links, largest file 18,590,227 bytes, so a fixture can copy it within these limits without modifying it. The qualifier may choose a different exact local cache only when it passes the same bounded copy. npm itself verifies each consumed cache artifact against the frozen lock integrity; malformed/missing cached content fails. Do not use the existing release test's direct `--cache /tmp/software-factory-npm-cache` pattern (`test/release-packaging.test.mjs:185-200`) for the new installer acceptance route because npm would be allowed to write that shared cache.

Node invokes the **candidate's validated direct** `install/node/bin/node` plus `lib/node_modules/npm/bin/npm-cli.js` (or Windows `install/node/node.exe` plus `node_modules/npm/bin/npm-cli.js`) with argv `ci --ignore-scripts --no-bin-links --audit=false --fund=false --update-notifier=false --cache <stageRoot/npm/cache> --userconfig <stageRoot/npm/user.npmrc> --globalconfig <stageRoot/npm/global.npmrc>`, appending `--offline` iff the request's boolean is true. Use the fresh absent-only candidate `toolchain/` as cwd, set HOME to `stageRoot/npm/home`, pass a deliberately constructed environment with no inherited `NPM_CONFIG_*`, `NODE_OPTIONS`, proxy/auth variables or user/global rc paths, and never invoke through a shell or PATH-resolved npm. Keep the package declaration and exact pinned lock hash under `release.ts:199-227` and the existing closure validation; fail if npm changes either, installs extras, creates links/shims, skips required platform packages, or leaves an incomplete compiler/Node types closure. Online mode does not permit floating resolution or postinstall scripts. `offline` is an execution input, not a release-selection fact: the candidate receipt binds the resulting validated bytes/closure; the compact claim selection digest need not vary by cache mode.

Python still owns cleanup. Seed files are registered by `PrivateStage` as copied. npm may create cache files/logs while running, so after the verified Node preparer and **all descendants** are proven closed, Python performs one bounded, no-follow inventory of only `npm/cache` and `npm/home`, registers newly created regular files/directories by inode/type in `stage.owned`, rejects replaced seeded entries, links/special files, paths outside those roots or overflow, then uses the existing exact-identity reverse cleanup. Cap the *post-npm private cache* at 8,192 combined entries, 256 MiB regular bytes, 64 MiB/file and the same path/depth rules. Empty config files remain separately registered; any modification to them refuses. If process closure, cache ownership, inventory, or cleanup is uncertain, preserve the private stage and incomplete claim for inspection and report failure. Node never recursively deletes the private stage or borrows it as persistent cache. The candidate can bind only after npm's direct child and descendants are quiescent, its output/closure is validated and its own receipt is durable. Python success is reported only after its stage cleanup succeeds.

## Exact entry and implementation interface

Replace the path-only draft `prepareInstallCandidate({repository, selection, verifiedSourceRoot, extractedNodeRoot, npmCache})`. The sole external Node entry is:

```text
<verified stageRoot/node/bin/node> <authenticated stageRoot/bundle/dist/install-entry.js> --request <stageRoot/preparer-request.json>
```

Windows uses the verified direct `node.exe` equivalent. `install-entry.ts` parses that one option and calls `prepareInstallCandidate(requestPath: string): Promise<PreparedCandidateReceipt>` in `src/install.ts`. That module opens/parses the <=64 KiB private request, validates `PrivatePrepareRequestV1` plus `npm.offline`, rehashes the whole bundle/archive through `validateInstallSelection()` and the Python-computed extracted Node tree digest, validates original source descriptors, derives fixed npm paths, and only then calls `beginRepositoryBootstrap()`. It owns the candidate copy/npm execution, exact claim CAS, and fixed bounded public result. The private `MaintenanceHandle` and request paths never appear in stdout. No shape-only `verified` boolean, arbitrary extracted root, caller-provided cache path or second install gate is accepted. Python prevalidates original sources immediately before launch and again after child exit; a source change fails, leaving any acquired operation incomplete. The stage request remains temporary, and `prepare` stops with the candidate bound and claim in `preparing`, without ready/publication.
