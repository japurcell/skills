## Decision and exact claim boundary

**Implement an additive qualification-only, non-debug representative observation comparator.** It can independently expose whether real baseline/candidate Node launches produce the expected Git/TypeScript event graph and suspicious console-host events. It cannot make every transient helper a held, independently inspected process object. Keep those two claims explicit in its protocol; never reuse `HELD child` for event-only evidence. No product helper or no-children admission follows this tranche.

The supplied actual run 39881631722 establishes the known controlled Node/child prerequisite: two held objects and immutable pinned-file verification, six selected live events, exact mode 37748737, both all-true QUERY rows, API zeroes, zero session/header loss, finalized header and COMPLETE. Final source review is pending. The fixture deliberately keeps its child alive until OpenProcess/image/FileID/parent checks finish. It does not establish that a transient Git rev-parse can be opened before it exits.

For transient children, complete ETW start/end pairs with a nonzero matching kernel key, unique PID occurrence, parent relation to the held Node root, and an exact full image-load path matching a continuously held immutable pin provide **event identity and pinned-image-path evidence**. The key is a kernel process-object address, not a process HANDLE. No API contract here turns it into QueryFullProcessImageName/GetProcessTimes/FileID verification of the child's process object. The image event identifies an image loaded into a PID; it does not independently identify that process's main executable object. A name-only process field remains consistency only. Therefore the full stronger held-process/file predicate cannot be guaranteed by this offline observer for arbitrary transient children. Real-time callbacks also arrive after buffer flush and cannot guarantee acquisition before exit. Do not suspend, delay or wrap actual Git/TS to disguise that gap.

Keep helper-identity eligibility refused with `transient-process-identity-unverified` whenever the held-child predicate is absent, even if every graph/output comparison matches. A matching event graph may be reported independently; it cannot set a held-image or strict helper-admission flag. If a later acceptance rule requires held child identity, this route must refuse without that proof. The smallest useful authorized alternative is this explicitly narrower observation comparator with fixed refusals and the existing product uncertainty/manual fallback unchanged. It is useful evidence for the next decision even when its strict route result is failed or inconclusive.

## Collector and fixture lifetime

Start and verify one sequential file-backed PROCESS+IMAGE session before launching each held Node root. Keep the existing 30-second observation bound, <64 MiB ETL, 100,000 callback cap, 64 KiB metadata/property limits as currently applicable (property bytes <=32 KiB), 65,536-byte native receipt cap, and successful close/finalized-header/zero-loss requirements. Seven sequential sessions avoid one session spanning all compiler cases. No circular, real-time or extra provider profile is needed.

Open expected pins before launch, hash archive-member bytes through held files, retain FileID and complete DOS/NT spellings, and deny write/delete sharing through decode. Reopen only those known local pins for FileID stability checks. Unknown event paths are never opened or normalized by guessed prefixes. Unknown path spellings, changed pin identity, missing required images or DLLs cause typed refusal. Classify events as a path match to the held pin, not a held child process-image verification. Known system executables have separately labeled system-file provenance, never an archive-pinned label.

File sharing protects the held file object, not every ancestor directory or path alias. Exact path spelling is therefore evidence only unless namespace stability is independently established. Case-insensitive equality also cannot identify two names in a case-sensitive Windows directory. For this tranche use an exact-case expected-path-match category, reject ambiguous aliases/reparse/changed final paths, and recheck known local pins; do not claim those pre/post checks rule out an intervening ancestor rename or alias swap. Hard links and ancestor replacement are not resolved by an event path or an after-the-fact FileID reopen. A full immutable-namespace qualification would additionally have to prove applicable case rules and continuously prevent relevant ancestor/alias mutation, or use independent child process-image/file-object evidence. That is a remaining gate, not an implied capability of the current known-child pin. Keep this narrower category named `expected-pin-path-match`, with process-file-identity unverified, until such proof exists. Never open an arbitrary event path to try to recover it.

Launch Node without DEBUG_PROCESS using one recorded outer launch context identical across baseline/candidate. Verify and hold its process handle, creation/image/file identity, and keep it live. Its fixed launcher waits for a private root-only release before calling real spawn. Record precise wall-time before release and immediately after observing root exit; bind the root by its actual creation/exit and measured End bracket, preserving the recently repaired rule. Helpers run normally and may finish immediately. After child exit+close+both pipe closures and bounded local result persistence, the root reports completed, then exits on a bounded final release. Any failure/guard timeout refuses; no arbitrary grace interval repairs missing events.

Root holding prevents its PID reuse. For transient helpers do not invent GetProcessTimes values. Bind event times to the launch/finish bracket and complete ETW process intervals; require a unique reported direct PID event with ParentId=root PID, start/end matching nonzero key, consistent name, expected status and exactly one expected pinned-path image observation within that interval. Reject any repeated lifecycle for a relevant PID or key anywhere in the trace rather than selecting a convenient occupant. Store all start/end relationships before graph reduction because callback order is not a parent-first guarantee. Rundown is context only, never a live event substitute.

Add conservative aggregate limits, e.g. <=4096 lifecycle records, <=4096 retained image records and <=8 MiB retained private decoded text, with checked accounting before retention. A limit hit is inconclusive, not truncated success. These proposed extra caps bound the generalized collector and do not enlarge existing limits.

## Descendants and console hosts

Reconstruct the transitive graph from the held root using unique process intervals and ParentId at child creation. Do not key solely by PID or trust Node's reported PID as observation. Every descendant must have one matching end, coherent lifetime and class. For representative Git/TS the expected graph is root plus direct helper; nested cmd requires root, direct cmd and its intended second cmd with exact image-path evidence and zero statuses. Any other descendant is disqualifying. A missing/ambiguous parent interval, relevant PID/key reuse, unknown image or unmatched end refuses the route.

Also inspect **all** new process starts in the session for console-host name/path categories, including events outside the root graph. Process/image ETW does not provide a documented console-client association here. A conhost outside a proved parent chain remains `unassigned-console-host`; never join it by time, basename or session proximity. A new conhost with unresolved image remains suspicious, not invisible. Count bootstrap and post-release phases separately for diagnosis, but neither phase establishes who caused it. Any such ambiguity blocks strict console/no-extra qualification. This can create false refusals from ambient activity; that is preferable to calling an unrelated host benign or suppressing it. Preserve unrelated non-console ambient lifecycles privately for closure/reuse checks; upload only aggregate categories.

An observation can be complete and show a failed route. Baseline is calibration and must report extra/suspicious processes rather than use `allowAdditional` to label strict success. Candidate discrepancy from old debugger evidence is a measured difference under recorded outer contexts, not proof that the debugger caused it.

## Public seams and negative controls

Test only the pre-agreed launcher/driver + bounded artifact seam and native disposable subprocess observation seam. Portable public negatives must precede implementation slices; actual Windows runs remain the decisive event/schema proof. Do not create private-method/reflection tests as a substitute for those seams.

Public protocol must distinguish `observation-complete`, `route-refused` and `inconclusive`; held-root flags, event-only helper evidence, strict graph result and product-admission=false are separate fixed fields. On upload reconstruct only enumerated case/route labels, controlled root/direct PIDs where needed, run-local descendant ordinals, selected numeric times/statuses, class/count/boolean fields and closed failure codes. Never upload kernel keys, file IDs, ambient PIDs/paths/hashes, command lines, environment, output content, exceptions, raw bootstrap, ETL or an operational spec. Bound both source reads and reconstructed files; remove ETL before the exact allowlist upload even on failure. Grammar/cap/cleanup failure prevents upload.

Required negatives through those seams: forged direct PID or foreign same-Node PID (foreign survives); missing/duplicate/key-changed/start-without-end/end-without-start/reused-PID graph; wrong parent or nested child omitted; foreign same-basename image, name-only main-image, unknown namespace or pin mutation; unexpected descendant; both graph-member and unassigned console-host ambiguity; missing/zero/dirty header or stop counters; callback/cap/parse/close failure; forged completed summary and path-bearing/extra-field/oversize receipts. Native controls must actually demonstrate intended nested cmd, marker-before-stop, threshold-before-stop, nonzero observed stopped outcome, and pipe closure. Node's direct kill return alone proves none of descendant absence or safe external PID signaling.

The current control attempts exactly 4,194,304 flood bytes; the Node route intentionally stops after observed >262,144 bytes with 262,144 retained per stream. Do not claim it proved >4 MiB emitted. If literal >4 MiB emission is required, calibrate a separate producer/delivery case while retaining the unchanged production threshold/10-second stop and capture caps. Deadline marker remains exactly 15 bytes before the 500 ms stop request. Do not increase the 30-second observation bound to accommodate the control's un-stopped sleep; stop it through the actual Node API.

C# owns and may stop its launched root handle only. Event identity never authorizes terminating a child PID. Node may stop its actual ChildProcess through its own spawn handle while it owns that handle. On collector failure close root control input, attempt bounded cooperative Node cleanup, stop only the session successfully created by this invocation, independently close all resources and delete exact ETL. Unknown detached descendants mean typed cleanup uncertainty/manual intervention in the disposable job; no taskkill tree, global tracker, Job Object or guessed PID termination is added.

## Remaining gates and Microsoft contracts

This tranche needs real Windows 2025/PowerShell 5.1 execution of all seven cases and negative controls; actual Git/TS ETW name/path/schema forms and complete module coverage are unknown. Native rights are required facts: TOKEN category alone does not establish access, and successful hosted admin collection does not prove a normal nonadmin product can collect. Access denial or session collision is a fixed refusal. Never attach to, stop or overwrite another session; retain only the StartTrace-success handle as ownership authority. Keep this operator/disposable collector separate from product startup, with no elevation prompt, ACL/group mutation, service or background tracker.

Following representative evidence, the original exact 17 Git/3 TS alternate matrix, hostile inputs/PATH and package/DLL tamper controls, independent source/result reviews after all implementation, explicit live-process/image evidence gaps, and product admission decision remain. `src/native/process.ts` identity and Windows uncertainty remain unchanged; arbitrary children remain unknown/manual fallback.

Primary Microsoft sources checked for this decision:

- [Process_V2_TypeGroup1](https://learn.microsoft.com/en-us/windows/win32/etw/process-v2-typegroup1): live/rundown opcodes, PID/parent reuse caveats and kernel-address UniqueProcessKey. Supports event association, not user-mode handle recovery.
- [Image_Load](https://learn.microsoft.com/en-us/windows/win32/etw/image-load): image PID/FileName and live versus rundown image events. No process HANDLE/FileID or console-client link is supplied.
- [Naming Files, Paths, and Namespaces](https://learn.microsoft.com/en-us/windows/win32/fileio/naming-a-file): Windows path strings and linked files/directories have distinct namespace rules; NTFS can support case-sensitive semantics. Exact spelling alone is not an object identifier.
- [PROCESS_INFORMATION](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/ns-processthreadsapi-process_information): process HANDLE authority and PID lifetime while handles retain the object.
- [CreateFileW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew), [FILE_ID_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_id_info): compatible sharing remains until handle closure; volume+file identifier compares actual open files. A path event is not itself such an open handle.
- [ProcessTrace](https://learn.microsoft.com/en-us/windows/win32/api/evntrace/nf-evntrace-processtrace), [EVENT_TRACE_LOGFILEW](https://learn.microsoft.com/en-us/windows/win32/api/evntrace/ns-evntrace-event_trace_logfilew): consume through completion, callbacks can arrive out of timestamp order, default system-time conversion, unused EventsLost member. Do not select by callback arrival or use that unused field as completeness proof.
- [Logging Mode Constants](https://learn.microsoft.com/en-us/windows/win32/etw/logging-mode-constants): real-time delivery occurs when buffers flush, so switching to real-time does not guarantee live child acquisition; sequential mode stops at the cap.
- [TRACE_LOGFILE_HEADER](https://learn.microsoft.com/en-us/windows/win32/api/evntrace/ns-evntrace-trace_logfile_header): finalized EndTime and EventsLost/BuffersLost; retain stopped-session counters too.
- [TdhGetEventInformation](https://learn.microsoft.com/en-us/windows/win32/api/tdh/nf-tdh-tdhgeteventinformation), [TRACE_EVENT_INFO](https://learn.microsoft.com/en-us/windows/win32/api/tdh/ns-tdh-trace_event_info): validate actual classic schema/property metadata and pointer/string widths rather than emitting a hard-coded SCHEMA assertion from requested property names.
- [StartTraceW](https://learn.microsoft.com/en-us/windows/win32/api/evntrace/nf-evntrace-starttracew), [ControlTraceW](https://learn.microsoft.com/en-us/windows/win32/api/evntrace/nf-evntrace-controltracew): bounded owned sessions, collision/error and rights behavior. No nonadmin applicability is established by the admin run.
- [Creation of a Console](https://learn.microsoft.com/en-us/windows/console/creation-of-a-console): detached creation initially lacks an attached console; later AllocConsole remains possible. This is not a console-host process attribution contract.
