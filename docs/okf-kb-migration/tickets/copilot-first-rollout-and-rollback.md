# Copilot-First Rollout and Rollback

## Question

How should Copilot and Gemini move independently through legacy, shadow, canary, and default modes; what evidence and observation windows gate each transition; how do experimental Copilot extension upgrades requalify; which provider-specific failures trigger local rollback; and which shared failures roll back every enrolled provider?

## Accepted round 1

- Treat provider enrollment as capability state outside the rollout ladder. An unavailable Copilot extension remains unenrolled on legacy compatibility. Configured `legacy` means the adapter is installed and qualified but OKF serving is disabled. Each provider then advances independently through `legacy`, `shadow`, `canary`, and `default`; Copilot reaching `default` completes the migration while Gemini continues on its own ladder.
- Give the four modes exact behavior. `legacy` serves only established legacy context. `shadow` executes the complete replacement path and records privacy-safe comparisons but serves legacy context. `canary` serves OKF only in explicitly designated branches or worktrees through committed configuration, never hidden user bucketing. `default` serves OKF for every eligible invocation while retaining atomic legacy fallback. Forward transitions cannot skip stages, and rollback from any active mode goes directly to `legacy`.
- Never inherit Copilot qualification across CLI builds. Prequalify every exact deployment tuple before installation, and begin each planned candidate again at `shadow`. Unavailable extension support leaves Copilot unenrolled on legacy compatibility; an enrolled adapter with missing, mismatched, or behaviorally invalid evidence enters `advisory_stop` plus deny-all-tools until maintainers restore `legacy` or install valid qualified evidence.
- Immediately roll back for invalid, stale, partial, or mixed context; missing mandatory context; privacy leakage; nondeterminism; forbidden lifecycle content; cross-provider parity failure; or an incorrect safety disposition. An adapter or host defect rolls back only its provider. A defect in the shared profile, projection, producer, selector, runtime, legacy loader, corpus, or oracle returns every enrolled provider to `legacy`. Contract-correct `use_legacy`, Copilot `advisory_stop`, and Gemini `hard_stop` outcomes are not rollout failures by themselves.

## Accepted round 2

- Gate `legacy` to `shadow` on exact-build `agent-kb-evaluation@2.0.0` passes for `shared_core` and the provider, with both adapters already implemented and evaluated. Gate `shadow` to `canary` on an unchanged candidate completing one normal work cycle and at least 50 eligible prompts, whichever takes longer, with zero safety violations; then freeze that provider's operational envelope. Gate `canary` to `default` on a fresh normal work cycle and at least 50 eligible canary prompts within the frozen envelope. Rerun complete exact-commit CI before every transition.
- Freeze each provider's operational envelope from its completed shadow window. Track unexpected fallback or stop dispositions by reason, adapter errors, provider-envelope failures, and prompt-path latency. Keep safety and privacy invariants zero-tolerance and outside the statistical envelope, and never loosen or recompute the envelope during canary.
- Record separate qualification-affecting candidate and complete deployment-configuration digests. The candidate digest covers shared settings, provider settings, budgets, bindings, and every configuration field except rollout mode; the complete digest preserves auditability. A mode-only transition retains candidate evidence. Any other bound provider change restarts that provider at `shadow`, a shared candidate change restarts both providers, and prose-only changes that alter no bound digest invalidate nothing.
- Keep runtime code read-only with respect to rollout state. A maintainer performs one minimal reviewed configuration change returning the affected provider, or every provider for a shared defect, directly to `legacy`; canonical documents and the projection remain untouched. Re-promotion requires a documented root cause, regression coverage, new exact-build qualification, and a fresh complete ladder beginning at `shadow`.

## Accepted round 3

- Retire the dedicated Copilot and Gemini source-ingest hook registrations and scripts in one reviewed cross-provider cutover only after both replacement adapters pass exact-build qualification, source-ingest parity, and shared-runtime parity. Put both qualified adapters in `legacy` and validate legacy behavior before Copilot enters `shadow`. Configured `legacy` thereafter uses the replacement adapter for reconciliation and safe legacy loading. Unenrolled Copilot retains the accepted limitation of legacy KB loading without dynamic prompt-time freshness enforcement.
- Treat non-safety degradation by active mode. In `shadow`, exceeding the prospective envelope freezes promotion and triggers investigation while served context remains legacy. In `canary` or `default`, roll back only the affected provider when a complete rolling 50-eligible-prompt window exceeds its frozen envelope; a single non-safety spike alerts and investigates without automatic rollback. Missing required observability makes the period `incomplete`: freeze promotion immediately, and roll an active `canary` or `default` provider back if observability is not restored before another 50 eligible invocations. Zero-tolerance failures still roll back immediately.
- Require every promotion or rollback review record to identify the candidate commit, exact deployment tuple, evaluation run and artifact references, candidate and complete configuration digests, frozen envelope, observation dates, eligible invocation count, aggregate results, and transition reason. Keep prompt-level evidence only in protected provider-local storage; never commit prompts, rendered context, lexical evidence, concept bodies, absolute paths, or environment values.
- Do not retire atomic legacy fallback during this migration. Consider retirement only in a separate major-contract decision after every supported provider is safely at `default`, no supported path requires `use_legacy`, every fallback class has an equally safe replacement, older-checkout compatibility is addressed, and complete new promotion evidence validates the replacement.

## Resolution

Manage enrollment separately from rollout mode. Unavailable Copilot extension support leaves the repository unenrolled on its accepted legacy compatibility path; configured `legacy` means a qualified adapter is installed but serves established legacy context. Advance Copilot and Gemini independently through `legacy`, `shadow`, `canary`, and `default`, without skipped forward stages or hidden user bucketing. `Shadow` runs the complete candidate path read-only while serving legacy context, `canary` serves OKF only in designated branches or worktrees through committed configuration, and `default` serves OKF for every eligible invocation with atomic legacy fallback. Copilot reaches `default` first and thereby completes this migration; Gemini remains fully supported on its independent ladder.

Require exact-build `agent-kb-evaluation@2.0.0` passes for `shared_core` and the provider before `shadow`, with both adapters implemented and evaluated before the first production transition. An unchanged shadow candidate must complete one normal work cycle and at least 50 eligible prompts, whichever takes longer, with zero safety violations before its provider-specific operational envelope is frozen. Canary then completes a fresh normal work cycle and at least 50 eligible prompts within that envelope before default. Run complete exact-commit CI before every transition. Track unexpected fallback or stop reasons, adapter errors, provider-envelope failures, and prompt-path latency; never dilute zero-tolerance safety or privacy invariants into the statistical envelope or loosen the frozen envelope during canary.

Bind qualification to a candidate digest that covers every qualification-affecting setting except rollout mode, and separately record the complete deployment-configuration digest. A mode-only transition preserves candidate evidence. Any other bound provider change restarts that provider at `shadow`; a shared candidate change restarts both providers; prose-only changes that alter no bound digest invalidate nothing. Every Copilot CLI build and deployment tuple requires fresh qualification and starts at `shadow` rather than inheriting prior evidence. Unavailable extension support remains unenrolled legacy compatibility, while a loaded enrolled adapter with missing, mismatched, or invalid evidence enters `advisory_stop` plus deny-all-tools pending maintainer action.

Immediately roll back for invalid, stale, partial, or mixed context; missing mandatory context; privacy leakage; nondeterminism; forbidden lifecycle content; cross-provider parity failure; or an incorrect safety disposition. Provider adapter or host defects return only that provider to `legacy`; shared profile, projection, producer, selector, runtime, legacy-loader, corpus, or oracle defects return every enrolled provider to `legacy`. Contract-correct `use_legacy`, Copilot `advisory_stop`, and Gemini `hard_stop` outcomes are not failures by themselves. In shadow, non-safety degradation freezes promotion while legacy service continues. In canary or default, roll back the affected provider only after a complete rolling 50-eligible-prompt window exceeds its frozen envelope. Missing required observability makes evidence incomplete, freezes promotion immediately, and causes canary or default rollback if it remains unavailable for another 50 eligible invocations.

Keep rollout state read-only at runtime. Maintainers use one minimal reviewed configuration change for rollback, never deleting the projection or mutating canonical documents. Re-promotion requires a documented root cause, regression coverage, new exact-build qualification, and a fresh full ladder from shadow. Each transition or rollback record identifies the candidate commit, exact deployment tuple, evaluation artifacts, candidate and complete configuration digests, frozen envelope, observation dates and counts, aggregate results, and reason without committing sensitive prompt-level evidence.

Retire both dedicated source-ingest hook registrations and scripts together only after both replacement adapters pass exact-build, source-ingest, and shared-runtime parity. Put both qualified adapters in `legacy` and validate replacement-backed legacy behavior before Copilot enters shadow. Configured legacy then uses the replacement adapter for reconciliation and safe loading; unenrolled Copilot retains the explicitly accepted lack of dynamic prompt-time freshness enforcement. Keep atomic legacy fallback for this migration. Its retirement requires a separate major-contract decision after all supported providers are default, no supported path requires `use_legacy`, every fallback class has an equally safe replacement, older-checkout compatibility is addressed, and new promotion evidence validates the replacement.
