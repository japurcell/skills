## Question

How should the repository-scoped Copilot project extension and fully supported Gemini adapter share the provider-neutral runtime while preserving existing hooks, active-workspace discovery, source-ingest reconciliation, runtime configuration, session state, extension lifecycle, advisory-stop tool denial, Gemini hard stops, privacy-safe diagnostics, and capability-tested enrollment?

## Accepted round 1

- Use one stateless, standard-library Python runtime for provider-neutral request validation, source-state evaluation, selection, fallback direction, rendered context, and privacy-safe audit results. The Copilot JavaScript extension invokes it as a fresh subprocess per eligible prompt; the Gemini Python adapter calls the same entry point or underlying module. Subprocess management remains outside the selector, and no persistent worker or runtime cache is introduced.
- Derive the active repository root from the repository-owned project extension or Gemini adapter location. Canonicalize and require the provider-supplied working directory to remain within that same root. Reject symlink escapes and cross-workspace paths; never search parent repositories, home directories, environment overrides, adjacent workspaces, or Git output for project KB content.
- Enrollment requires valid committed `.agents/okf-runtime.json` intent, a successfully loaded provider adapter, committed behavioral qualification evidence matching the actual host build, and passing lightweight runtime surface checks. Missing configuration or unavailable extension support preserves the unchanged legacy path. An adapter that loads while configured as enrolled but has missing, mismatched, or invalid capability evidence enters Copilot `advisory_stop` plus deny-all-tools or Gemini `hard_stop`. Runtime code never writes or repairs configuration or qualification evidence.

## Accepted round 2

- Retire the dedicated Copilot and Gemini source-ingest hook registrations and scripts after the replacement adapters prove parity. Move manifest reconciliation and pending-state evaluation into the shared runtime invoked by the Copilot project extension and the unified Gemini adapter. Keep unrelated global observability, Tool Guardian, secret-scanning, and skill-loading hooks independent. When the Copilot extension is unavailable, preserve legacy `AGENTS.md` and `.agents/memory/INDEX.md` loading but explicitly accept that dynamic prompt-time source-freshness enforcement is unavailable; contributor and CI preflight checks are not represented as equivalent runtime enforcement.
- On every eligible prompt, reconcile source-ingest state under the existing manifest-v1 lock before projection validation or selection, then release the lock before reading one projection snapshot. Reconciliation may update only the source-ingest manifest and scaffolds under its existing contract; selection, the committed projection, runtime configuration, and qualification evidence remain read-only. Startup reconciliation is warmup only. Copilot stop events and Gemini `AfterAgent` reconcile source state without rerunning selection. Capture one injectable UTC event timestamp per prompt and reuse it throughout the invocation.
- Keep Copilot safety state in memory and scope it to one session and validated workspace. Start or reload in `unverified`; deny tools while evaluation is pending or the latest disposition is `advisory_stop`; clear the latch only after a later prompt completes with valid `use_okf` or successfully loaded `use_legacy`; and serialize queued or steered evaluations so stale completions cannot overwrite newer state. Reset to `unverified` on `/clear`, resume, workspace change, or extension reload, and discard state at session end. Persist no task text, rendered context, or latch state. Gemini remains invocation-stateless: `BeforeAgent` enforces each `hard_stop`, and `AfterAgent` independently rechecks source state.

## Accepted round 3

- Use a strict one-request/one-result UTF-8 JSON subprocess protocol: one request on stdin, one schema-valid result on stdout, and exit `0` as the only successful transport. Only an explicit trusted-runtime `use_legacy` result permits fallback. Startup failure, timeout, signal termination, malformed or multiple output, unsupported result version, or unknown disposition maps to Copilot `advisory_stop` or Gemini `hard_stop`. Do not retry within the same prompt; derive the production timeout through evaluation and kill and reap timed-out children.
- Keep source-ingest manifest v1, projection manifest v1, `agent-kb-runtime@1.0.0` configuration, qualification evidence, and provider-local observability stores independent. `.agents/okf-runtime.json` owns shared budgets, concept limit, default task scope, provider enrollment intent, and exact provider-build qualification binding. Read and hash one configuration snapshot per prompt and record its digest. Rollout-mode semantics remain for the rollout ticket. Runtime code never migrates or repairs state; malformed or unsupported enabled configuration is unsafe, and only explicitly compatible additive fields are tolerated.
- The shared runtime returns structured audit metadata but persists nothing. Adapters may forward contract versions and digests, disposition and reason codes, timings and counts, normalized logical paths, lifecycle substitutions, capability state, and sanitized session/workspace identifiers to existing provider-local observability. Never record task text, concept bodies, rendered context, lexical evidence, absolute workspace paths, environment values, or subprocess payloads. Reserve subprocess stdout for its result and extension stdout for SDK JSON-RPC; bound and sanitize stderr. Observability remains fail-open and cannot alter a valid context or safety disposition.

## Accepted round 4

- For selector v1, adapters pass only the current submitted prompt as task text, the validated workspace identity, one validated or adapter-generated UTC timestamp, and runtime-configured `task-scope: nontrivial`. Omit task kind and repository paths unless a future documented provider field supplies them structurally. Never infer selector inputs from prompt prose, conversation history, Git state, environment variables, or filesystem enumeration.
- Map `use_okf` to one delimited rendered OKF context block and `use_legacy` to one legacy block containing canonical `AGENTS.md` and `.agents/memory/INDEX.md` plus the existing loading-map instruction. Copilot returns the block once through `onUserPromptSubmitted.additionalContext` without changing the visible prompt; Gemini returns it through `BeforeAgent.hookSpecificOutput.additionalContext`. Copilot `advisory_stop` injects one minimal privacy-safe stop message and activates its tool-denial latch; Gemini `hard_stop` uses its native turn-denial envelope. Never mix OKF, legacy, audit, or diagnostic content.
- Copilot `onAgentStop` reconciles source state without selecting again. If newly unsafe, it latches deny-all-tools and requests at most one bounded continuation per submitted prompt with a privacy-safe reason; a repeated stop may complete with the limitation recorded and must not be called a hard stop. Gemini `AfterAgent` rechecks and enforces native hard denial. Process launch, `onSessionStart`, `/clear`, resume, and reload start `unverified`; `onSessionEnd` cancels and reaps children and clears queues and latches without persistence. Every handler catches errors and enters its provider's unsafe disposition rather than relying on the SDK's fail-open exception handling.

## Resolution

Use one stateless, standard-library Python runtime as the provider-neutral boundary. The Copilot project extension invokes it through a fresh one-request/one-result JSON subprocess for each eligible prompt; the Gemini adapter calls the same entry point or underlying module. The runtime owns request validation, source-ingest reconciliation and state evaluation, projection and selector orchestration, atomic legacy direction, rendered context, and privacy-safe audit results. It persists no runtime or session state, introduces no cache, never repairs configuration or qualification evidence, and never mutates the committed projection.

Derive the repository root from each repository-owned adapter, canonicalize it, and require the provider working directory to remain inside it. Use only explicit selector inputs: current prompt text, validated workspace identity, one invocation-stable UTC timestamp, and configured `task-scope: nontrivial`; omit task kind and repository paths unless a future documented provider field supplies them structurally. Do not infer inputs from prose, conversation, Git, environment variables, filesystem enumeration, or neighboring workspaces.

Enroll a provider only when valid `agent-kb-runtime@1.0.0` configuration intent, a loaded adapter, exact build-matched behavioral qualification evidence, and lightweight runtime surface checks all agree. Keep source-ingest manifest v1, projection manifest v1, runtime configuration, qualification evidence, and provider-local observability as independent versioned contracts with no silent migration. Missing configuration or unavailable Copilot extension support preserves legacy KB loading; an enabled adapter with invalid or mismatched evidence enters its unsafe disposition.

Retire the dedicated Copilot and Gemini source-ingest hooks after the replacement adapters prove parity. The accepted unsupported-Copilot limitation is explicit: legacy `AGENTS.md` and `.agents/memory/INDEX.md` loading remains available, but dynamic prompt-time source-freshness enforcement does not. For enrolled providers, reconcile on every prompt under the existing manifest lock, release the lock before validating one projection snapshot, and reconcile again at the final-response event without rerunning selection. Only the existing source manifest and scaffold contract may be updated during reconciliation.

Map `use_okf` to one complete delimited OKF block and `use_legacy` to one complete legacy block containing canonical `AGENTS.md`, `.agents/memory/INDEX.md`, and the existing loading-map instruction. Copilot injects the block once through `onUserPromptSubmitted.additionalContext`; Gemini uses `BeforeAgent.hookSpecificOutput.additionalContext`. Never mix OKF, legacy, audit, or diagnostic content. Only a schema-valid runtime result with exit `0` can direct legacy fallback. Transport, schema, timeout, signal, or handler failures before trustworthy state is established map to Copilot `advisory_stop` or Gemini `hard_stop`, with no same-prompt retry.

Keep Copilot's deny-all-tools latch in memory, serialized per validated session and workspace. Launch, reload, resume, `/clear`, workspace change, and `onSessionStart` begin `unverified`; pending evaluation and `advisory_stop` deny tools; a later valid `use_okf` or successfully loaded `use_legacy` clears the latch. `onAgentStop` rechecks source state and may request at most one privacy-safe continuation per submitted prompt, never claiming a hard stop. `onSessionEnd` reaps children and clears state. Gemini remains invocation-stateless and enforces native denial at `BeforeAgent` and `AfterAgent`.

Return structured audits without persistence. Provider observability may receive only versions and digests, disposition and reason codes, timings and counts, normalized logical paths, lifecycle substitutions, capability state, and sanitized identifiers. Never record prompt text, concept bodies, rendered context, lexical evidence, absolute workspace paths, environment values, or subprocess payloads. Reserve transport stdout for protocol data, sanitize and bound stderr, and keep observability fail-open without changing context or safety decisions.
