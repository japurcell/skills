# Subagent model and effort dispatch evidence

Research snapshot: 2026-11-18. This note supports the routing gates in [delegate-to-subagents](../skills/default/delegate-to-subagents/SKILL.md#pre-dispatch-gate) and [execplan-implement](../skills/default/execplan-implement/SKILL.md#pre-dispatch-gate). It distinguishes source/docs behavior from live dispatch observations. No native dispatch or new eval was run for this note.

## Wording to compare with today's two gates

Candidate for both callers:

> Before each new assignment, including reuse, run the router. Save its invocation, unchanged JSON, and intended dispatch arguments. Apply the exact model through the host's worker controls. For `explicit`, set the requested effort. For `host_default`, omit the effort override. Follow the router skill's reuse, override, and rejection rules. Record the actual call and worker ID or blocker.

The router skill would own the detailed rules. An exact user model takes precedence over a missing catalog route. A model absent from descriptive help can still be tried when permitted. Enforced allowlists still apply. For explicit effort, the user's selection takes precedence over the router's. Reuse requires useful prior context and matching original controls, including the absence of an effort override for a host-default assignment. A permitted fallback must preserve the effort policy and capability floor. A model-wide rejection rules out every effort for that model. Preserve the primary result and record any override or fallback separately. Keep this metadata in the assignment record and the worker brief focused on its task.

## Evidence and limits

### OpenAI Codex

- Codex source defines separate optional `model` and `reasoning_effort` spawn fields. Its child config begins with the active model/effort, applies explicit spawn values or configured `[agents]` defaults, and sets the selected model's default effort when a model override is given without effort. Unsupported model IDs and effort levels return errors in this source path; this code does not establish substitution fallback. [Spawn schema](https://github.com/openai/codex/blob/main/codex-rs/core/src/tools/handlers/multi_agents_spec.rs) · [Child configuration](https://github.com/openai/codex/blob/main/codex-rs/core/src/agent/child_config.rs)
- V2 prompt guidance says omission inherits the parent; full-history forks (`fork_turns: "all"`, the tool default) inherit model and effort and do not accept overrides. The runtime schema may hide controls on some surfaces, and system instructions may limit model changes. Check the actual live tool. Codex activity includes effective model/effort, but the spawn result returns an ID/nickname rather than those resolved values. [V2 instructions](https://github.com/openai/codex/blob/main/codex-rs/prompts/src/multi_agent_instructions.rs) · [Spawn event](https://github.com/openai/codex/blob/main/codex-rs/core/src/tools/handlers/multi_agents/spawn.rs)
- Local `codex --help` exposes top-level `--model`; it does not document the subagent effort argument. This local check is not evidence that every Codex UI or version exposes the same subagent schema.
- An OpenAI-maintained plugin skill explicitly supplies both model and effort on each spawn and sets `default_subagent_model` / `default_subagent_reasoning_effort` as backstops. Treat that as one authored policy, not a universal rule: [Codex tool guidance](https://github.com/openai/plugins/blob/main/plugins/superpowers/skills/using-superpowers/references/codex-tools.md).
- OpenAI's skill-eval guide recommends scoring captured `codex exec --json` traces and artifacts, with deterministic checks on actual tool events and command order. For this work, score requested arguments, returned agent ID, and observed effective values independently; final text alone cannot prove dispatch. [Testing Agent Skills Systematically with Evals](https://developers.openai.com/blog/eval-skills).

OpenAI's configuration examples also show where a role declares its model and reasoning effort. Those fields belong to the agent definition. The current session's spawn schema determines which overrides the caller can supply. [Codex subagent configuration](https://developers.openai.com/codex/subagents/)

### Anthropic Claude Code

- Claude Code documents model precedence as invocation parameter, agent definition, `CLAUDE_CODE_SUBAGENT_MODEL`, then parent model. Effort is also independent: invocation/definition effort applies, with `CLAUDE_CODE_EFFORT_LEVEL` taking precedence. If effort is omitted, the session setting applies only when the child is on the main model; a different model uses its own default. Model aliases, allowlists, provider, and nested delegation affect resolution. `/tasks` reports the effective model and effort in supported versions. [Subagent docs](https://code.claude.com/docs/en/sub-agents).
- Claude Code documents fallback model chains for covered API failures and reports when a child switched models. Codex source above shows rejection for unknown model/effort, not a fallback. Keep each host's fallback contract distinct. [Claude API errors and fallback](https://code.claude.com/docs/en/sub-agents#api-errors-in-subagents).
- The official code-review plugin provides a concrete tiered example: Haiku checks PR status and enumerates instruction files, Sonnet summarizes and checks instruction compliance, and Opus performs independent bug reviews and validates findings. It does not specify effort, so the example supports model specialization but not an assumption that effort must always be pinned. [Code review command](https://github.com/anthropics/claude-plugins-official/blob/main/plugins/code-review/commands/code-review.md).
- Anthropic's Research team inspected traces to discover delegation mistakes, then used concrete examples and clearer tool descriptions to revise the lead agent's instructions. That suggests anchoring this wording comparison in a reported Copilot failure before choosing the first trial. [How we built our multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system)
- Reuse and routing are separate: Claude's fork mode reuses the parent prompt/cache when system prompt and tools match. That is context behavior, not a model/effort guarantee. Reuse an assignment only after the normal gate confirms the same route and effort policy remains appropriate. [Forks](https://code.claude.com/docs/en/sub-agents#fork-the-current-conversation).

### GitHub Copilot CLI boundary

Current GitHub CLI docs say agent frontmatter `model`, `models`, `modelPolicy`, and `reasoningEffort` apply through `task`; precedence includes an explicit per-call value. `models` is an ordered authored list, unavailable options can fall back to session settings, and `modelPolicy: required` refuses an unauthored model rather than substituting. The SDK documents that a different-model child gets that model's default when effort is omitted. Do not conflate CLI and SDK resolution. A read-only inspection of Copilot CLI 1.0.114 found a helper reading `arguments.reasoning_effort` from `task` execution-start events. This proves that the event reader recognizes this snake_case key; it does not prove the raw tool schema advertised it, the host accepted it, or the executed effort. No successful dispatch was observed. [CLI reference](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference#custom-agent-frontmatter-fields) · [SDK custom agents](https://docs.github.com/en/copilot/how-tos/copilot-sdk/features/custom-agents).

## Evaluation implications

The user reports that Copilot attempted a model missing from its model selection. The available material does not identify the exact ID or the worker controls the parent could see at that moment. GitHub documents the interactive `/model` picker for the session and separate configuration for selecting a subagent model. For a reproduction, capture the routed ID, the availability information visible to the parent before launch, its scope, the actual dispatch arguments, and the host response. [Copilot model selection](https://docs.github.com/en/copilot/how-tos/copilot-cli/use-copilot-cli/choose-a-model)

Use matched cases with the same routed ID. In one, an authoritative worker restriction rules it out before launch. In another, tool help merely omits it and the worker accepts it. In a third, availability is unknown until the host rejects the call. Score whether the parent avoids the known-invalid call, attempts the permitted call, and handles the rejection once without trying the same unavailable model at different efforts. Use three fresh old/new pairs per caller on the reported failure case. Retain failures and distinguish ties from observed improvements.

The earlier comparison improved from 18/43 to 43/43 field assertions across seven paired cases. It graded structured answers about dispatch. The November 10 local research identified the raw Copilot effort field as unresolved and explicitly recorded that its examples had never launched a worker. Inspecting the 1.0.114 event reader narrows that uncertainty. A new live trace is needed to grade the parent's actual call and the host's response. [Archived comparison](../brain/archive/plans/25-router-effort-policy/exec-plan.md) · [Prior dispatch-controls research, local scratchpad](../.agents/scratchpad/subagent-dispatch-model-and-reasoning-controls.md)

For future capability evals, capture a before record (unchanged router JSON, assignment ID, intended args, host-control path) and after record (actual args, agent ID/blocker, effective model/effort if exposed). Distinguish descriptive suggestions from enforced allowlists, and assert exact user-selected model dispatch through host controls. Exercise omission, explicit effort, unavailable model, unsupported effort, model-wide rejection, allowed fallback, and reuse with unchanged settings. Grade accepted ID, observed execution, and work outcome as separate fields; use `unknown` when the host provides no execution evidence. OpenAI's trace-based method supports these process checks without turning routing policy into new runtime blockers.

Other examples considered: [Cursor swarm](https://github.com/cursor/plugins/blob/main/pstack/skills/swarm/SKILL.md) separates routing from fan-out and defines a surface-specific fallback; the [pinned EGM brainstorm skill](https://github.com/google/elephant-goldfish-model/blob/bbfb62eb49abcd428931f1eeb6d66de065e52ac6/skills/egm-brainstorm/SKILL.md) selects host-specific tools/personas but contains no model/effort ladder. Neither is evidence of Codex or Claude dispatch behavior.
