## Existing behavior and costs

- `_command_segments` normalizes text, splits physical and escaped newlines plus shell separators without quote awareness, replaces double quotes and commas with spaces, and falls back to whitespace splitting after `shlex` errors. This loses literal boundaries and executable nesting. The writer fixtures fail their segment budget despite being ordinary file-content transformations.
- `build_threats` parses once for limits; four recursive-removal matchers and two protected-push matchers parse again. SQL deletion separately normalizes. `build_input_threats` repeats this work for leaf strings and the serialized object. Milestone 2 owns removal of redundant object scans; milestone 3 must consume its executable and strict-fallback fragments without reintroducing serialization.
- `_match_git_push` checks every Git-looking token and creates a new suffix, folded suffix, force-index list, branch-index list, and forced-refspec list for each candidate. Repeated valid push prefixes in one token stream can produce quadratic suffix work. The 256-token cap bounds today's damage but does not justify retaining this growth when limits change.
- Environment-file and Git-metadata removal searches already restrict each suffix search to approximately 100 characters and one logical line. Do not claim those windows are unbounded quadratic scans. Their command-position and literal-data semantics still need correction.
- Some matchers use normalized tokens, while simple, pipeline, and upload matchers search the original lowercased text. Preserve NFKC protection consistently, including the corpus's fullwidth operation, with byte/character accounting before and after normalization.

## One bounded shell representation

Build one source-offset representation per executable fragment: commands and pipeline edges; words with literal/expanded pieces; redirections with destination descriptor and ordered position; heredoc bodies; nested executable fragments; and a strict-fallback flag. Cache lowercase values and executable basenames once. Keep original text for accounting only, never as trusted banner context. Count executable commands and tokens separately from literal body lines. Nested work shares aggregate budgets with its parent.

Use a forward scanner with explicit unquoted, single-quoted, double-quoted, escape, substitution, comment, and heredoc states. Preserve adjacent word pieces rather than splitting `"a"b` into two words. Only active separators create commands; literal semicolons and the two-character escaped-newline spelling do not. Backslash-newline continuation is distinct from a literal backslash followed by `n`. Recognize comments only at their shell boundary. Do not strip arbitrary commas or quotes.

Queue heredoc descriptors while reading each command line, then consume bodies in descriptor order, requiring the exact delimiter line and respecting `<<-` tab handling. Track partially quoted delimiters too. Quoting suppresses shell expansion but says nothing about the consumer's language. A body for `python3 -` is Python; one for `sh` or `bash` is shell; a proven guard-script JSON stdin body is data. An unquoted body still has shell substitutions even when its destination treats the resulting bytes as data. Ordered redirections matter: a later stdin redirection can supersede an earlier heredoc, but expansions in earlier redirections still require inspection. Ambiguous descriptor duplication or unsupported ordering stays strict.

Recursively inspect `$()` and backticks inside unquoted/double-quoted words and unquoted heredocs; escaped or single-quoted forms remain literal. Inspect process substitution when supported; otherwise retain strict scanning and mark incomplete executable extraction as an inspection failure. Apply finite depth/byte/token bounds to every nested extraction. Arithmetic expansion, parameter operators, shell functions, `eval`, source commands, non-POSIX syntax, aliases, and unsupported wrappers must not receive data exemptions. Malformed quoting or incomplete heredocs cannot use the old whitespace fallback to produce an allow.

`shlex` can help decode a proven simple word, but cannot be the semantic parser: it removes quotation provenance, does not supply the required heredoc/substitution model, and is documented as short of a full shell parser. Its Unix scope also means Windows or PowerShell syntax must stay on a separate strict path. [Python shlex documentation](https://docs.python.org/3/library/shlex.html#improved-compatibility-with-shells)

Recognize search data only for an exact supported command/option grammar and identified literal pattern operands, including `-e`, `--regexp=`, and `--`. Do not suppress substitutions, redirections, pipeline neighbors, or commands before/after a search. Unknown options, expanded patterns, shell wrappers, and commands whose search expressions can execute code stay strict. Initially prove the observed `rg -n` form; add other forms only with paired public-envelope cases. A quoted argument to `sh -c`, Python `-c`, a SQL client command option, or another interpreter remains executable language input.

## Narrow Python proof

Lazy-import parsing only after the shell representation establishes an exact Python invocation with inline `-c` code or a supported stdin heredoc. Python script filenames, module execution, arbitrary launchers, additional unsupported options, and unquoted expanding heredocs retain strict inspection. No file-content reads, subprocesses, Python execution, or imports of payload modules are needed.

Before `ast.parse`, cap source UTF-8 bytes and syntax tokens, nesting, and long operator chains with a quote-aware lexical preflight. Large string constants are data bytes, not thousands of Python statements. Post-parse, iteratively cap AST nodes/depth and total decoded constant bytes. A post-parse node limit alone is inadequate: Python documents parser stack exhaustion. Avoid `eval`, `compile`, and `ast.literal_eval`; resolve only explicit supported AST node shapes. Local interpreter was Python 3.14.6; official 3.14 documentation was consulted, but repository compatibility requires verifying the same subset on supported older runtimes. New grammar nodes default to unsupported. [Python AST documentation](https://docs.python.org/3/library/ast.html#ast.parse)

Prove the entire observed straight-line writer program before masking any constants:

1. Exact `from pathlib import Path`, optionally a statically tracked import alias; no relative, wildcard, dynamic, or additional imports.
2. A simple-name assignment to `Path` of one literal destination, then `read_text` on that tracked path; track read content as opaque data and never read the actual file.
3. Simple-name assignments of literal strings, including triple-quoted constants, and bounded ordinary string transformations required by the fixtures.
4. `write_text` on the same tracked path, with `old.replace(literal_old, body)` in the observed fixture. Validate every argument and keyword. Track transformations symbolically when the read value is unknown; never materialize an unbounded replacement or repeated string.

Imported aliases, path objects, read-data values, and literal strings are distinct symbol-table kinds. Rebinding, attribute assignment, shadowing, unresolved names, or unsupported calls invalidate the whole-program proof. Do not accept a writer merely because one valid `write_text` call occurs somewhere in it. Calls nested in f-strings, defaults, comprehensions, argument expressions, and keyword values remain executable. Initially reject control flow, functions/classes, decorators, lambdas, comprehensions, f-strings with expressions, unpacking, arbitrary attributes, and every call outside the proven subset. The classifier trusts the specified standard-library operation contract, not payload claims about safety.

Separate proof of harmless data from discovery of execution sinks. Even if the harmless-writer proof fails, inspect known `os.system`, shell-command subprocess calls, `eval`/`exec`, and interpreter arguments. Resolve tracked literal strings and bounded literal concatenations without executing them, then route each resolved sink argument back through strict shell/language inspection. This is needed for `danger.interpreter-sink`, which baseline allows despite the represented protected push. Track exact import aliases and invalidate them on rebinding. Unknown alias/value flows retain whole-source strict scanning; unresolved executable sink input is incomplete inspection and must deny rather than silently skip. This remains a bounded subset, not a general proof of arbitrary Python programs.

Unsupported well-formed constructs receive complete strict scanning of their original code, with no partially masked constants and with any established nested sinks still inspected. Resource overflow, parser failure that prevents complete inspection, malformed input, or unresolved required sink extraction emits `inspection_failure`/input-limit denial before allowlisting and irrespective of warn mode. Unsupported classification alone is not a new blanket denial rule; incomplete inspection is.

## Linear rule work and banner preservation

Keep all 21 `PATTERNS` entries, numeric pattern construction, corresponding `RULE_DETAILS`, severity/category/rule identities, and rule-order reporting. Two push patterns intentionally share one rule identity; final deduplication must preserve current first-match behavior.

- Parse and fold once, then precompute nearest matching tail positions backward for force options and protected destination/refspec variants. Each Git candidate resolves its supported global-option prefix once and obtains suffix answers by index. Use token ranges, not copied suffix lists. Equivalent forward accumulators are acceptable if earliest-match and rule-order behavior are proven.
- For recursive removal, compute flags/options and protected operand categories in one pass per candidate command. Repeated command-looking operands must not restart full tail scans; either suffix summaries preserve the strict legacy interpretation or a proven executable command position avoids those restarts. Wrapper handling must be explicit.
- Scan fixed textual needles once per bounded executable/strict fragment using precompiled matching or a fixed number of linear passes. Twenty-one fixed rules already make a constant-factor linear design plausible; do not add a generic automaton unless measurements justify it. SQL masking occurs once per relevant language fragment, with statement-local WHERE handling retained.
- Pipeline/upload checks must preserve existing rule coverage while distinguishing literal operators from real pipeline edges. First establish parity on existing protection cases; treat semantic corrections as separately tested changes, not incidental optimization.

Produce the existing threat dictionaries from safe operation summaries. Do not pass AST source spans, heredoc bodies, paths, remote URLs, headers, or nested JSON to banner context. Preserve redaction before truncation, the 160-character Action cap, three displayed causes plus omitted count, safe protected-push/network summaries, and identical banner/log excerpts. Inspection failures use `command omitted` and never suggest allowlisting.
