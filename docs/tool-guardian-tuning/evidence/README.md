# Tool Guardian validation evidence

Final accepted source results are in `cold-profile-final-comparison.json`, with frozen hashes and raw reports retained alongside it. Both 147-case warm pairs pass; the 7,350-launch cold report retains its three initial failures and the exact 150-launch repeat passes. The 90-case resource run stays below 500 ms, and repeated four-worker comparisons improve for each provider. See `../cold-profile-notes.md` for the measured repair and `../final-doc-notes.md` for canonical documentation verification. Native Windows proof remains unavailable; real installation is user-owned.

The baseline history below describes unchanged pre-implementation hooks. Its failed observations retain their original meaning. Current acceptance uses the revised per-case warm +2/+5 ms and fresh-copy cold +5/+10 ms median/p95 budgets in `../ExecPlan.md`.

The maintained corpus is `scripts/tool_guard_corpus.py`. It constructs inert tool inputs from sanitized operation roles and sizes. Neither correctness nor timing tools execute those represented operations. They invoke only fixed generated guardian entrypoints with disposable homes, working directories, and log paths. No user hooks are installed.

`corpus.json` records fixture names, categories, provenance, paired protection controls, sizes, and independent baseline/candidate expectations. Provider adapters use Copilot `create`/`edit`/`grep`, Gemini `write_file`/`replace`/`grep_search`, and Codex `apply_patch` plus shell literal searches. The same content operation is represented through each provider's native tool schema. Native Codex replacement cases use an update patch. Unsupported and malformed schema controls retain strict inspection expectations.

The exact original private payloads are unavailable and deliberately absent. These are sanitized reproductions of operation, data role, and important geometry, rather than transcript copies. The native patch fixtures preserve 46,899 UTF-8 bytes, 330 physical lines, and 124 lines with 142 naive segments. The two fixed pathlib writers preserve 8,787 characters with 183 naive segments and 120 physical lines with 139 naive segments, including 18 literal semicolons and one escaped newline. The Python survey passes JSON input to a fixed guardian subprocess. Its precise historical source schema is unavailable; that fixture records this limitation. A direct guardian invocation with JSON stdin is a separate useful control.

Incident provenance references the planning survey and existing guardian log locations rather than depending on those mutable logs at test time. Deduplication uses invocation identity where available, otherwise provider, timestamp, tool, and matched failure. Log and transcript sightings of one invocation count once. Captured guardian output inside a test or survey is a result of that represented invocation, never a denial of the outer test runner. Archived duplicate Copilot transcript copies are excluded from primary incident counts. This corpus does not publish a new combined unique incident total. Plan-authoring prose and synthetic adversarial cases remain separate from the original survey count.

`baseline-scripts.sha256.json` fingerprints the saved Python scripts and local helpers under `/private/tmp/tool-guardian-baseline`. The snapshot was copied before any policy edits and is preserved outside the checkout. It must never be installed. The baseline verification command is:

```sh
rtk proxy python3 scripts/test-tool-guard-false-positives.py --script-root /private/tmp/tool-guardian-baseline --expected-behavior baseline
```

Default candidate mode intentionally fails against unchanged hooks. Baseline mode validates known false denials separately from desired behavior, and does not relax candidate protections. Direct executable controls cover all 20 distinct existing rules. Shell substitution and interpreter execution controls exposed existing baseline gaps: their baseline expectation is allow, but the candidate must deny. The shell literal search is already permitted. Codex's patch representation also already permits the force-push example text that native Copilot and Gemini writes currently reject.

`baseline-1.json` and `baseline-2.json` retain sequential repeated complete subprocess timing for the final corpus, including 25 raw samples per provider/scenario, three discarded warmups, one first-run measurement, exact expected/actual decisions, input sizes, environment, medians, p95, median absolute deviation, and four-worker concurrent clean calls. Each invocation starts a new Python process. Original `guard.clean`, `guard.finding`, `guard.large`, and `guard.failure` payloads and case names are retained separately. Large unknown harmless commands remain measured even when already allowed.

`baseline-exploratory.json` is retained as failed-attempt evidence. It uses an earlier provider-adapter revision and had a brief overlap with an aborted second benchmark run. It is excluded from acceptance comparisons. Interrupted runs do not yield complete reports. Final baseline/candidate comparisons must use the final corpus and repeat paired runs in alternating order when needed to distinguish noise.

First-run timing uses a fresh disposable log home with uncleared operating-system file caches. It is not a fully cold measurement. These are macOS entrypoint timings, not provider delivery or native Windows evidence. Background host load is not controlled by the runner. A baseline report alone does not establish candidate acceptance; compare the same scenarios separately for every provider against the current agreed budgets.

`baseline-variation.json` retains each provider/scenario independently: both medians, p95 values, within-run median absolute deviations, first-run samples, median delta, and the median absolute deviation between the two run medians. With only two baseline runs this is descriptive variation, not a confidence interval. Final clean-call medians span 26.887-30.097 ms for Copilot, 27.724-28.634 ms for Gemini, and 25.716-25.955 ms for Codex. Existing large-command medians span 73.512-77.014, 118.635-122.221, and 116.468-120.161 ms respectively. These numbers do not establish candidate acceptance.

Before implementation, unchanged-hook candidate verification reported 92 passed and 52 failed. Those failures are the preserved future acceptance requirements, including the discovered execution-sink gaps; baseline verification reports 144 passed. The maintained benchmark CLI suite reports two passed on macOS, and the aggregate registry contract reports 14 passed. On other hosts only the benchmark execution fixture is explicitly marked macOS-only; public argument checks remain available.
