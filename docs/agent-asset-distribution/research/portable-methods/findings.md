# Portable distribution methods and additional clients

Research date: 2026-09-29

## Recommendation

**Recommendation (synthesis and inference):** Keep the repository as the canonical, team-managed source. For explicit repository-scoped installation, default to committed project copies while preserving the existing user-global workflow. Add a selective installer that resolves an explicit manifest, dependency closure, target clients, and scope, then materializes each client's native layout. Record immutable source revisions and content hashes so a clean checkout can reproduce the selection. Offer local untracked installation and development symlinks as additional modes. This covers skills, agents, hooks, and instructions in one workflow, while the documented Vercel CLI focuses on skills and shared plugin formats do not normalize every client-specific component. [Agent Skills specification](https://agentskills.io/specification), [Agent Plugins specification](https://agent-plugins.org/specification), [Vercel Skills CLI](https://github.com/vercel-labs/skills/blob/main/README.md), [Cursor plugins](https://cursor.com/docs/plugins), [OpenAI plugin packaging](https://developers.openai.com/plugins/build/plugins), [OpenCode plugins](https://opencode.ai/docs/plugins)

Use the [Agent Skills](https://agentskills.io/specification) directory format for portable skill payloads. Where clients implement it, use a root [`plugin.json`](https://agent-plugins.org/specification) package to distribute skills and MCP configuration together. Treat Agent Plugins as a shared package shape, not a universal registry, installer, update protocol, or guarantee that clients understand each other's agents, hooks, rules, and extensions. OpenAI and Cursor document support for the root format; their other components still use client-specific conventions. [OpenAI plugin packaging](https://developers.openai.com/plugins/build/plugins), [Cursor plugins](https://cursor.com/docs/plugins), [Agent Plugins specification](https://agent-plugins.org/specification)

For the default team workflow, copy selected files into the project and commit them. A manifest should distinguish maintained sources from generated client layouts and pin dependency closure, source revision, destination, and scope. Copying avoids reliance on symlink behavior in Windows checkouts. For personal workspaces, permit global output and symlinks for convenient iteration. This recommendation follows from the clients' distinct search paths, the Vercel CLI's copy/symlink choices, and Git's documented symlink limitations on Windows. [Vercel Skills CLI](https://github.com/vercel-labs/skills/blob/main/README.md), [Git core.symlinks](https://git-scm.com/docs/git-config), [Git for Windows symbolic links](https://gitforwindows.org/symbolic-links.html)

## Standards and portability boundaries

**Agent Skills standardizes skill content.** A skill is a directory with a required `SKILL.md` and optional supporting `scripts/`, `references/`, and `assets/`. The format standardizes skill identity and instructions; it does not specify a distribution registry, install location, dependency solver, version lock, or client installation workflow. `allowed-tools` is experimental and support varies. Optional `compatibility` metadata can describe environment requirements, but does not provision them. The standard therefore carries skill content, not its external tools, called skills, hooks, or agent configuration. [Agent Skills specification](https://agentskills.io/specification)

**Agent Plugins standardizes a package shape.** Its v1.0.0 specification requires a root `plugin.json`, defines shared `skills/` and `mcp.json` locations, and allows namespaced `extensions` for client-specific metadata and files. Clients ignore extension namespaces they do not implement. Paths must stay within the package root; plugin subprocesses can receive `PLUGIN_ROOT` and persistent `PLUGIN_DATA`. The spec does not define a shared marketplace, version resolver, install command, lockfile, or update/removal lifecycle. [Agent Plugins specification](https://agent-plugins.org/specification)

**OpenAI and Cursor document adoption of the shared root manifest, with different extensions.** OpenAI documents shared skills and MCP configuration, `extensions.com.openai`, and `.codex-plugin/plugin.json` as a compatibility fallback. Cursor documents the Agent Plugins root format alongside `.cursor-plugin/plugin.json`, which provides Cursor rules, agents, commands, hooks, and other extensions. Cursor's MCP configuration uses `${CURSOR_PLUGIN_ROOT}` rather than the shared spec's `${PLUGIN_ROOT}`. This is a portable core plus adapters, not identical behavior across clients. [OpenAI plugin packaging](https://developers.openai.com/plugins/build/plugins), [Cursor plugins](https://cursor.com/docs/plugins), [Agent Plugins specification](https://agent-plugins.org/specification)

## Selective installer and Vercel Skills CLI

The Vercel `skills` CLI documents project and global installs, selection by agent and skill, listing, removal and update, copy mode, and sources including Git repositories, local paths, archives, and URLs. Project mode keeps a canonical copy under `.agents/skills/` and links agent-specific skill directories to it; `--copy` writes copies to selected agent paths, with copy fallback where symlinks fail. Git source syntax accepts a ref such as a tag or commit SHA. These are useful features for skill directories, not a general installer for repository agents, hooks, or instructions. [CLI README](https://github.com/vercel-labs/skills/blob/main/README.md), [installer source](https://github.com/vercel-labs/skills/blob/main/src/installer.ts), [source parser](https://github.com/vercel-labs/skills/blob/main/src/source-parser.ts)

Project installs have a `skills-lock.json` recording source information, ref, skill path, and computed SHA-256. Current source marks `experimental_install` and `experimental_sync` as experimental. `experimental_install` restores from `.agents/skills` and re-adds via recorded source and ref; the inspected implementation does not restore agent-specific destinations or validate the stored hash as a frozen snapshot. The lock entry also does not preserve copy-versus-symlink mode for re-installation. These are **implementation-based inferences** from current CLI source and may change independently of the README. For strict reproducibility, pin a commit SHA and add repository-owned verification. [Vercel local lock](https://github.com/vercel-labs/skills/blob/main/src/local-lock.ts), [add implementation](https://github.com/vercel-labs/skills/blob/main/src/add.ts), [install implementation](https://github.com/vercel-labs/skills/blob/main/src/install.ts), [update implementation](https://github.com/vercel-labs/skills/blob/main/src/update.ts)

The CLI is a good selective skill downloader and implementation reference. Its documented asset model does not cover arbitrary instructions, custom agents, hook configuration or executables, or those assets' dependencies, so it cannot alone deliver the full bundle described by this ticket. **Inference:** use it to fetch third-party skills if useful, while a repository-owned manifest and adapters manage the complete selection. [Vercel CLI README](https://github.com/vercel-labs/skills/blob/main/README.md), [Vercel CLI source](https://github.com/vercel-labs/skills/blob/main/src/cli.ts)

## Distribution options

| Approach | Reproducibility and team commits | Updates, dependencies, executables, and portability | Assessment |
| --- | --- | --- | --- |
| **Repository manifest + selective installer** | Best fit for committed outputs and reviewable diffs. A custom lock can pin SHAs, hashes, dependency closure, scope, and target output. | Installer must implement update/removal and dependency validation. Copy output is cross-platform; executable assets need runtime and trust metadata. | **Recommended** for the whole bundle. Inference from documented format and CLI gaps. |
| **Native plugin adapters** | Familiar per-client install and marketplace flows; adapters can be generated from canonical sources. | Component coverage, paths, runtime, trust, and upgrade rules vary. Shared plugin format covers only common subset. | Secondary distribution channels, tested per client. [Agent Plugins](https://agent-plugins.org/specification), [Cursor plugins](https://cursor.com/docs/plugins), [OpenAI plugins](https://developers.openai.com/plugins/build/plugins) |
| **Vercel Skills CLI** | Project lock and commit SHA refs help; current experimental restore is not strict whole-output replay. | Skill selection, update/removal, project/global scope, copy/symlink. No arbitrary agents/hooks/instructions. | Good for skill acquisition, incomplete for whole bundle. [README](https://github.com/vercel-labs/skills/blob/main/README.md), [lock](https://github.com/vercel-labs/skills/blob/main/src/local-lock.ts), [install](https://github.com/vercel-labs/skills/blob/main/src/install.ts) |
| **npm package** | Versions and committed lockfiles support reproducible dependency installs. | Requires Node/npm and an adapter to map assets to client layouts; npm lifecycle scripts can execute package-defined commands. | Useful to distribute a versioned installer or adapter, not automatically discovered by clients as skills/agents/hooks. [Package specs](https://docs.npmjs.com/cli/v11/using-npm/package-spec/), [npm ci](https://docs.npmjs.com/cli/v11/commands/npm-ci), [npm scripts](https://docs.npmjs.com/cli/v11/using-npm/scripts) |
| **GitHub release archive** | Tagged snapshots provide a versioned archive; release immutability settings can prevent changing/deleting tags and assets. | Archive alone does not select assets, resolve dependencies, map native layouts, or remove old files. | Good transport paired with manifest/installer. [GitHub releases](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases) |
| **Vendored copies** | Ordinary tracked project content is directly reviewable and self-contained. | Updates/removals are repository edits; copies can drift from upstream; dependency closure needs explicit management. | Strong simple baseline for a curated team set. Assessment is inference. |
| **Git submodule** | Superproject records a specific submodule commit. | Consumers need initialization/update steps; selection is generally at repo/submodule granularity. | Preserves upstream history, adds onboarding friction. [Git submodule](https://git-scm.com/docs/git-submodule), [Git submodules](https://git-scm.com/docs/gitsubmodules) |
| **Git subtree** | Imports content into the main repository history, allowing one checkout. | Upstream synchronization and decomposition use subtree workflow; selected output still needs custom tooling. | Useful when a single self-contained clone matters. Assessment is inference. [Git subtree manual](https://github.com/git/git/blob/master/contrib/subtree/git-subtree.txt) |
| **Template repository** | Bootstraps a new repository with files that the team can commit. | Does not inherently track upstream updates, resolve dependencies, or remove assets. | Useful for initialization, not ongoing distribution. Assessment is inference. [GitHub template repositories](https://docs.github.com/en/repositories/creating-and-managing-repositories/creating-a-template-repository) |
| **Symlinks** | Link client paths to one canonical checkout without duplicate editable files. | Git can check out symlinks as plain files when `core.symlinks=false`; Windows creation also varies with privileges/environment. | Offer for local iteration, avoid as committed default when Windows users need working files. [Git core.symlinks](https://git-scm.com/docs/git-config), [Git for Windows symlinks](https://gitforwindows.org/symbolic-links.html) |
| **MCP** | Shared `mcp.json` describes connections for clients implementing Agent Plugins. | MCP exposes tools, resources, and prompts via a server; it does not distribute static instructions, agent definitions, or lifecycle hooks. Server runtime and credentials remain separate. | Use for live services, not as a replacement for the file bundle. [MCP server spec](https://modelcontextprotocol.io/specification/draft/server/index), [Agent Plugins](https://agent-plugins.org/specification) |

## Design implications

1. **Separate canonical sources from outputs.** Maintain skills, agent definitions, hooks, and instructions in owned source directories. Generate client layouts from them and commit project copies by default. Specific directories and manifest schema are implementation choices, not requirements of the standards.
2. **Model selection and dependency closure.** Resolve named assets and target clients, plus skills/workflows that call other skills, referenced files, and hook executables. Agent Skills permits supporting files but does not define this dependency graph. Store resolved closure in the lock. [Agent Skills specification](https://agentskills.io/specification)
3. **Pin source and generated output.** Record upstream repository, full commit SHA or immutable release, selected path, content hash, generated destinations, and installer/schema version. Do not treat a mutable branch or Vercel's experimental restore metadata as a frozen resolution. The latter is an implementation-based inference. [Vercel source parser](https://github.com/vercel-labs/skills/blob/main/src/source-parser.ts), [Vercel lock](https://github.com/vercel-labs/skills/blob/main/src/local-lock.ts), [Vercel install](https://github.com/vercel-labs/skills/blob/main/src/install.ts)
4. **Make repository scope explicit.** Preserve the current global installer behavior and default repository mode to committed team setup. Cursor, OpenCode, Cline, and Cascade document project/workspace and user/global locations for at least some assets, but the paths are client-specific. A per-client adapter should own mapping and safe removal, while the lock records ownership. [Cursor skills](https://cursor.com/docs/skills), [OpenCode agents](https://opencode.ai/docs/agents), [Cline skills](https://docs.cline.bot/customization/skills), [Cascade skills](https://docs.devin.ai/desktop/cascade/skills)
5. **Treat executables explicitly.** Skills may contain scripts, and native plugins/hooks can execute code. Metadata should state client, OS, shell, runtime, and external commands needed. A copied script is present but not necessarily trusted or executable. OpenAI notes hook files must be available in the execution environment and user trust is required. [Agent Skills specification](https://agentskills.io/specification), [OpenAI plugin packaging](https://developers.openai.com/plugins/build/plugins), [Cursor hooks](https://cursor.com/docs/hooks), [OpenCode plugins](https://opencode.ai/docs/plugins)
6. **Prefer copies for checked-in Windows output.** Copy materialization avoids runtime dependence on symlink creation; local users can opt into symlinks where supported. [Git core.symlinks](https://git-scm.com/docs/git-config), [Git for Windows symlinks](https://gitforwindows.org/symbolic-links.html)
